## Interfaces and behavior

- `JwtStrategy.validate`: uncached persisted profile + `AccessSnapshotService.forUser(id)` each request. No role impersonation. `req.user.access` is current; raw managed role remains unchanged; managed companies derive solely from snapshot grants (or persisted owner authority). Empty managed grants do not default to legacy companies. No ten-second authorization cache remains for unmanaged roles/status either.
- Login, DB refresh, legacy-JWT refresh and `/auth/me`: hydrate `user.access` and grant-derived companies. Refresh HTTP now includes `user` as well as `accessToken`; login/me suppress the old personal reverse flag for managed users. Task 7 should consume this immediately rather than treating the initial login user as legacy.
- `AccessPolicyService.authorize(context)` runs after Passport in JwtAuthGuard, before RolesGuard/BranchGuard. Global `AccessPolicyInterceptor` provides the post-authentication backstop. Symbols `ACCESS_AUTHORIZED`, `ACCESS_SELF_SERVICE`, `ACCESS_COLLECTION_EXECUTE` are server-owned and are not body/query flags. Existing global throttling, CSRF and audit remain.
- Managed RolesGuard/BranchGuard no longer veto an explicit successful current policy because of a legacy role/branch; they require the exact route authorization marker. Entity guard/interceptor use managed grants instead of role company defaults. Self-service snapshots remain available with no grants even when UI still sends a previous company.
- Explicit unmigrated path: `req.accessMode='LEGACY_UNMIGRATED'` for snapshot.managed=false, otherwise `MANAGED`. Unmigrated users, including owners, preserve existing role/company/branch handling. Missing snapshots, customer staff-route attempts, unknown audiences, unknown routes and unresolved managed resource boundaries fail closed.
- `assertAccess(user, permission, AccessResource)` checks current supplied snapshot/principal identity plus shared tuple evaluator. `permissionScopes(user, permission, company)` returns original capability-specific `{scope,branchIds,userId}` tuples. ASSIGNED ownership remains intact, empty BRANCHES is not a global scope, FINANCE tuple company remains FINANCE while branch IDs may be SHOP origins. Safe activity summaries match shared `activity.read` semantics.
- `AccessPolicyService.onDenied?: (event) => Promise<void>|void` hook emits only `{userId,route,permission,reason}`. Failure of capture never authorizes. Task 5 must install the durable safe sink and instrument domain/transaction denials; current hook is tested but not yet a production audit integration.

Every staff entry has a concrete shared catalog capability; no unknown-action placeholders remain. **1,092 rows require domain integrations**. Fingerprints cover controller/transport/authentication/policy decorators. New/stale/duplicate/re-routed or unclassified entries fail; this proves inventory/classification, not query correctness or whole-program enforcement.

The manifest declares permission, classification, company source and record/collection/none resolution. Runtime never guesses sensitive actions from HTTP verbs. Only shared catalog owner-only capabilities remain structurally reserved. Initial self-review considered extra route-level owner-only exceptions for write-off/closing reversal/outbox and removed them: old OWNER-only decorators are not an immutable business policy. Those operations map to accounting.update / journal.reverse / journal.read / journal.post, respectively, and Task 4 must enforce scoped positions plus independent maker-checker/transaction invariants. No route-only owner flag creates a checkbox promise mismatch.

**Registrar wiring:** Task 4 should add an injectable `OnModuleInit` registrar provider to global EmployeeAccessModule (or domain modules), inject Prisma/domain services and register `ACCESS_BOUNDARIES.set('Controller.method', resolver)`. Current map is empty outside tests. Service/registry is shared by both guard and interceptor. No ready boolean exists.

`AccessBoundary(request, snapshot, permission): Promise<AccessDecision>` returns exactly one of:

- `{kind:'resource',resource:AccessResource}` for record policies. Resolve persisted source company/branch/assigned users; never accept caller-supplied branch/ownership as proof. Check all source/destination resources on cross-record operations. Writes additionally use current snapshots/assertions inside their transaction and lock when necessary.
- `{kind:'collection',company,execute:(scope:CollectionScope)=>Promise<unknown>}` for collection policies. `CollectionScope={userId,company,permission,tuples}` preserves ASSIGNED and capability-specific tuples. Interceptor executes this callback **instead of** the unscoped handler. The callback must validate raw filters/DTOs, apply OR predicates **before** rows/pagination/count/aggregate/search/export and redact nested results. It must preserve HTTP/file status/headers. Since the callback runs from the interceptor, original controller argument pipes/downstream interceptors do not validate its inputs automatically. A representative branch resource is rejected for a collection policy. The typed boundary prevents a “registration done” flag from enabling an old unscoped list.

Precise remaining integrations: every `resource:'domain'` row; capability-appropriate persisted relations; collection/filter/count/export/search predicates; cost/profit/salary and audit redaction; source/destination transfers; file/signed-URL/stream responses; domain service role vetoes; current authorization inside financial transactions; legacy accounting/payment/reverse personal-grant readers/writers; managed/no-grants bootstrap for new staff; background jobs started by staff. Task 4 must review compound actions, not assume the route's primary capability replaces every business/sensitive check. Detailed examples and limitations are in `docs/guides/employee-access-coverage.md`.
