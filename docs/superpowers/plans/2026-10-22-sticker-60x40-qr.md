# Sticker 60×40 + QR Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Print the device sticker as the owner-approved แบบ ค layout at 60×40 mm with a QR code, with roll size and QR toggle configurable from settings.

**Architecture:** API exposes two new ui-flags (`stickerSize`, `stickerShowQr`) read from SystemConfig and adds `code` (legacy product code) to sticker product data. Web rewrites `StickerCard` (layout + per-size CSS incl. `@page`), derives `qrValue/idLabel/idText` in `buildStickerView`, reads the flags via `useUiFlags`, and replaces the obsolete sticker settings card with size select + QR toggle.

**Tech Stack:** NestJS (jest), React + Vite (vitest + testing-library), `qrcode.react` 4.2 (already a web dependency).

**Spec:** `docs/superpowers/specs/2026-10-22-sticker-60x40-qr-design.md`

## Global Constraints

- Sizes: `60x40` (default) · `50x40` · `50x30`; anything else → `60x40`. QR default on.
- QR value: `imei ?? code ?? productId`; footer text: IMEI full / รหัส full / `ID ` + first 8 chars of productId.
- Thai text line-height ≥ 1.35 everywhere on the sticker; no `position: absolute` inside `.sticker`.
- Print `@page` size must equal the selected roll size; stickers keep `page-break-after: always`.
- Shop name `BESTCHOICE` bottom-right in mono bold (owner-approved mockup).
- Never run `npm run lint` in apps/api (has `--fix`); use `npx eslint -c eslint.config.mjs <files>` from apps/api. Web vitest: `npx vitest run --root /abs/apps/web <file>`.
- Bump `apps/web/package.json` version to `26.10.48` (PRs #1723–#1725 hold 45–47).

## Review Focus

1. Old API without `stickerSize` in ui-flags → page must still render 60×40 with QR (test in Task 5 covers `{}` response).
2. QR off → no `svg` inside `.st-qr`, price row spans full width (Task 4 test).
3. Accessory without IMEI and without legacy code → QR holds full productId, footer shows `ID` + 8 chars (Task 3 test).
4. Spec line longer than 34 chars gets the `st-spec--long` class so it is not truncated at 60×40 (Task 4 test).
5. Settings PATCH payload carries exactly `sticker_size` + `sticker_show_qr` for the sticker card (Task 6 test).
