# ถังขยะรวม (ก้อน 8 · A10) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** เจ้าของเปิดหน้าเดียวเห็นของที่ถูกลบทุกประเภทที่กู้ได้ (allow-list) รู้ว่าใครลบเมื่อไร และกดกู้คืนทีละรายการหรือหลายรายการ โดยกู้แล้ว "กลับมาใช้งานเหมือนก่อนลบ" ไม่ชน unique และมี audit ในสาย Merkle

**Architecture:** โมดูลใหม่ `apps/api/src/modules/trash/` — `trash-registry.ts` (allow-list เดียว: ป้าย/กลุ่ม/ฟิลด์แสดง/การตรวจ/ข้อมูลที่ต้องคืน ต่อประเภท) · `TrashService` (list รวมหลายโมเดล + deletedBy จาก AuditLog + restore ใน `$transaction` + `audit.log` หลัง commit) · `TrashController` (`/trash`, OWNER) · เว็บ: หน้า `pages/settings/TrashPage/` ลงทะเบียนใน `settings-registry` หมวด system (`/settings/system/trash`) + hook `useTrash.ts` · สินค้าไม่กู้ตรง ชี้ไป dialog คำขอ FOUND ของหน้าตัดสินค้าผ่าน query param

**Tech Stack:** NestJS + Prisma (jest หน่วย · vitest บน Postgres ชั่วคราว `tools/test-db-vitest.sh`) · React + react-query + shadcn/Tailwind (vitest+RTL) · design canvas `https://claude.ai/artifact/NqV1ghjSSU7d79byFzdymW`

**Spec:** `docs/superpowers/specs/2026-10-26-trash-bin-design.md`

## Global Constraints

- ห้าม hard delete · ทุก query กรอง `deletedAt` เอง (ไม่มี middleware) · ไม่เพิ่ม flag/`includeDeleted` ให้ query เดิม
- audit ของการกู้ = `await this.audit.log(...)` **หลัง** `$transaction` commit เท่านั้น (database.md) · ห้าม `tx.auditLog.create` · ห้ามเรียก `audit.log` ใน tx
- ล็อกเบอร์ลูกค้า: `lockCustomerPhone(tx, null, phone)` เป็นคำสั่ง**แรก**ของ tx หนึ่งเบอร์ต่อ tx (database.md กติกาลำดับล็อก)
- OWNER เท่านั้นทุก endpoint (`@UseGuards(JwtAuthGuard, RolesGuard)` + `@Roles('OWNER')`) · DTO class-validator ข้อความไทย
- เว็บ: โทเคนจาก `index.css` เท่านั้น (`bg-card`, `text-muted-foreground`, `bg-warning/10`, `text-warning-strong` …) · สถานะมีไอคอน+คำ ไม่ใช้สีอย่างเดียว · ปุ่ม/ช่องติ๊ก ≥44px บนมือถือ · ตารางใน `overflow-x-auto` · ไม่มี raw `<select>`
- ข้อความ error ต้องชี้ทางที่มีจริง (coding-standards) — ปุ่ม/เมนูที่อ้างถึงต้อง grep แล้วว่ามี
- web version → `26.10.57` · ห้ามรัน `apps/api run lint` · jest ในเครื่องใส่ `--testPathIgnorePatterns db.spec integration.spec`

## Review Focus

1. กู้แล้วชน unique ที่ตรวจล่วงหน้าไม่ทัน (race) → ต้องได้ 409 ภาษาไทย ไม่ใช่ 500 — เทส TR6 (Task 3)
2. เรียก `POST /trash/product/:id/restore` หรือ `contract` ตรง ๆ โดยข้ามหน้า → 400 พร้อมเหตุผล/ลิงก์ ไม่เปลี่ยนข้อมูล — เทส TR2 (Task 3)
3. ลูกค้าที่ถูกรวม (`mergedIntoId` ไม่ว่าง) ต้องไม่ปรากฏในถังและกู้ไม่ได้แม้รู้ id — เทส R3 (Task 1) + TR9 (Task 4)
4. แถว audit `RESTORED` อยู่ในสาย Merkle (`rowHash` ไม่ว่าง) และเขียนหลัง commit — เทส TR5 (Task 3) + I4 (Task 6)
5. ของที่ลบโดยสคริปต์/ระบบ (ไม่มีแถว audit) ยังแสดงและกู้ได้ โดย "ลบโดย" = null — เทส TS3 (Task 2)
