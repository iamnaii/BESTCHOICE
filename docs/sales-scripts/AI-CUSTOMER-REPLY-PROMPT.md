# Prompt เทรน AI ให้ตอบลูกค้า (จากประวัติแชทเก่า)

**อัปเดต:** 2026-08-13
**ใช้กับ:** บอทขาย (Facebook / LINE Shop) + น้องเบส (LINE FINANCE) + AI Suggest ในกล่องแชทพนักงาน

เอกสารนี้มี 2 prompt ที่ทำงานต่อกัน:

| | Prompt | ทำอะไร | อยู่ที่ไหน |
|---|---|---|---|
| **A** | Training / Extraction | อ่านแชทเก่า → สรุปว่า "ลูกค้าถามอะไรบ่อย + คำตอบที่ดีที่สุดคืออะไร" | `apps/api/src/modules/chat-history-extractor/prompts/knowledge-extraction.prompt.ts` |
| **B** | Reply add-on | สั่งบอทให้ **ใช้** คลังคำตอบที่สกัดได้ ตอนตอบลูกค้าจริง | วางเพิ่มที่หน้า `/settings/ai/persona` ช่อง "Playbook & กฎ tools (BOT_EXTRAS)" |

> **หลักการ:** แชทเก่าใช้สอน "ต้องตอบอะไร" (เนื้อหา/นโยบาย) เท่านั้น
> ส่วน "ตัวเลข" (ราคา ค่างวด ยอดค้าง) ต้องมาจาก tool ตอนตอบเสมอ — ห้ามเอาเลขจากแชทเก่ามาตอบ เพราะราคาเปลี่ยนไปแล้ว

## 1. ขั้นตอนใช้งาน

### รันทีเดียวจบ (แนะนำ)

```bash
npm --prefix apps/api run ai:train
```

ทำขั้น 1 + ขั้น 2 ต่อกันให้เอง ไม่ต้องสตาร์ท API ไม่ต้อง login ไม่ต้อง build
จบแล้วพิมพ์ตารางสรุปว่าได้อะไรมาบ้าง แล้วบอกให้ไปกดเปิดใช้ที่หน้าไหน

| ตัวแปร | ผล |
|---|---|
| `MONTHS=6` | เปลี่ยนช่วงเวลาย้อนหลัง (ค่าเริ่มต้น 12 เดือน) |
| `SKIP_EXTRACT=1` | ข้ามขั้น 1 — แก้ prompt แล้วสกัดใหม่จากคู่ข้อความเดิม (ไม่ดูดแชทซ้ำ) |
| `DRY_RUN=1` | นับให้ดูเฉย ๆ ไม่เขียน DB ไม่เรียก Claude (ไม่ต้องมี API key) |
| `EXPECTED_DB_NAME=bestchoice` | กันรันผิด DB — ไม่ตรงแล้วหยุดทันที (DB prod ชื่อ `bestchoice` จริง ๆ — ชื่อเดียวกับ dev, ตัวกันนี้จึงกันแค่ URL แปลก ไม่ได้แยก dev/prod) |

> **รันกับ prod**: ใช้ `bash scripts/ops/train-ai-prod.sh` — เปิด cloud-sql-proxy + ดึง
> `DATABASE_URL`/`ANTHROPIC_API_KEY` จาก GCP secrets ให้เอง (รับ `DRY_RUN`/`MONTHS`/
> `SKIP_EXTRACT` เหมือนกันทุกตัว)

ตัวสคริปต์: `apps/api/src/cli/train-ai-knowledge.cli.ts` — เรียก service ตัวเดียวกับที่
endpoint เรียก ตรรกะและตัวกรองเป็นชุดเดียวกันเป๊ะ

**ตัวหยุดอัตโนมัติ** (กันจ่ายค่า Claude ฟรี ๆ / รันผิดที่):
ไม่มี `ANTHROPIC_API_KEY` → หยุดตั้งแต่ยังไม่ดูดแชท ·
`ai_training_pairs` ว่าง → ไม่เรียก Claude เลย ·
`EXPECTED_DB_NAME` ไม่ตรง → หยุดก่อนเขียน

### หรือแยกทีละขั้นผ่าน API (เมื่ออยากรันจากหน้าเว็บ/มือถือ)

```
ขั้น 1 — ดูดแชทเก่า          POST /chat-history/extract          { "months": 12 }   (OWNER)
        LINE + Facebook ย้อนหลัง N เดือน → จับคู่ "ลูกค้าถาม → พนักงานตอบ"
        → ล้าง PII (เลขบัตร/วันเกิด) → เก็บลง ai_training_pairs (source = SYSTEM_EXTRACT)

ขั้น 2 — สกัดคำตอบ (Prompt A) POST /chat-history/extract-knowledge                   (OWNER)
        อ่านคู่ข้อความล่าสุด 2,000 คู่ → สรุปเป็น FAQ + วิธีตอบข้อโต้แย้ง
        → เก็บลง chat_knowledge_base แบบ active = false

ขั้น 3 — รีวิวแล้วเปิดใช้     หน้า /chatbot-finance/knowledge → แท็บ Knowledge Base
        (OWNER / FINANCE_MANAGER — หน้านี้ list ทุกช่องทาง ไม่ได้กรองเฉพาะ LINE_FINANCE
         แถวฝั่งขายที่สกัดมาจึงเห็นและแก้ได้จากหน้าเดียวกัน)
        กดแก้ → ติ๊ก active → บอทจะค้นเจอผ่าน tool search_knowledge_base ทันที
```

**ขั้น 3 ห้ามข้าม** — ทุกแถวที่สกัดมาถูกบันทึกเป็น `active = false` โดยตั้งใจ
เพราะคำตอบมาจากพนักงานหลายคนหลายช่วงเวลา ต้องมีคนตรวจว่ายังตรงนโยบายวันนี้ก่อนปล่อยให้บอทใช้

แถวที่สกัดมาดูออกได้จาก `category`:

- `EXTRACTED` — FAQ
- `EXTRACTED_OBJECTION` — วิธีตอบข้อโต้แย้ง
- `id` = `extracted:<intent>` → รันซ้ำจะทับของเดิม ไม่งอกแถวซ้ำ

## 2. Prompt A — Training (สกัดจากแชทเก่า)

ตัวเต็มอยู่ในโค้ด (`KNOWLEDGE_EXTRACTION_SYSTEM_PROMPT`) แก้ที่ไฟล์เดียวจบ สรุปกฎที่คุมไว้:

**เลือกคำตอบที่ดีที่สุดยังไง**
1. ตอบคำถามจบจริง ไม่ใช่ "รอสักครู่นะคะ"
2. ดูข้อความถัดไป — ถ้าลูกค้าตอบรับ/ให้ข้อมูลต่อ แปลว่าคำตอบนั้นได้ผล
3. พนักงานตอบขัดกัน → เอาอันที่ตรงกับเสียงส่วนใหญ่
4. เก็บสำนวนแอดมินจริงไว้ (ค่ะลูกค้า / นะคะ / ครับ)

**กฎเหล็กตอนสกัด**
- ตัวเลขที่เปลี่ยนตามรุ่น/สัญญา → บังคับเป็นตัวแปร `{{ราคา}} {{ดาวน์}} {{ค่างวด}} {{จำนวนงวด}} {{ยอดค้าง}} {{วันครบกำหนด}}`
- ห้ามคำว่า **ดอกเบี้ย / เปอร์เซ็นต์ / %** เวลาพูดถึงเรทหรือค่างวด
  (โค้ดกรองซ้ำอีกชั้นด้วย `containsForbiddenRateTalk` — บล็อกเฉพาะเมื่อ % อยู่ใกล้คำว่า
  ดอก/ผ่อน/งวด/ต่อเดือน/ดาวน์ ฯลฯ ส่วนสำนวนขายปกติอย่าง "ของแท้ 100%" หรือ "แบต 89%" ผ่านได้)
- ห้ามรับปากว่าอนุมัติแน่ / ห้ามพูดล็อกเครื่องเชิงขู่ / ห้ามมี PII
- ห้ามเอาคำตอบเฉพาะเคส (ยอดของคนนั้น เลขสัญญานั้น) มาเป็น template
- `intent` ต้องอยู่ใน taxonomy ที่กำหนดเท่านั้น (นอกรายการ = ทิ้ง)
- `confidence < 0.5` = ทิ้ง

**การจัดช่องทางอัตโนมัติ** (ของเดิมยัดเป็น LINE_FINANCE ทุกแถว ทำให้ความรู้ฝั่งขายไม่เคยโผล่ในบอทขาย)

| audience | channel ที่บันทึก | ใครเห็น |
|---|---|---|
| `SALES` | `LINE_SHOP` | บอทขาย (LINE Shop / Facebook / Web) |
| `FINANCE` | `LINE_FINANCE` | น้องเบส |
| `BOTH` | `null` | ทั้งสองตัว |

## 3. Prompt B — บล็อกที่ต้องเพิ่มให้บอทตอบลูกค้า

ไปที่ `/settings/ai/persona` (OWNER เท่านั้น) → กล่อง **"Playbook & กฎ tools (BOT_EXTRAS)"**
→ **วางต่อท้ายของเดิม อย่าลบของเดิมทิ้ง**
(ของเดิมมีกฎ tool-calling ที่บอทต้องใช้ ถ้าชื่อ tool หายไปบอทจะเลิกเรียก tool เงียบ ๆ — หน้าจอจะเตือนให้)

> อย่าเอาไปวางในกล่อง "บุคลิก & โทน (BASE)" — BASE ใช้ร่วมกับ AI Suggest ของพนักงานที่ไม่มี tool

```
# คลังคำตอบจากแชทเก่า (search_knowledge_base) — ใช้ก่อนตอบเสมอสำหรับคำถามเชิงนโยบาย

## ลำดับความน่าเชื่อถือ (สูง → ต่ำ) — ขัดกันเมื่อไหร่ ให้เชื่ออันบน
1. ผล tool ในบทสนทนานี้ (search_products / calculate_installment / get_installment_rates / list_promotions)
2. คลังคำตอบจากแชทเก่า (search_knowledge_base)
3. กฎในบุคลิกนี้
4. ความจำของโมเดล = ห้ามใช้เด็ดขาด

## ต้องเรียก search_knowledge_base เมื่อ
- ลูกค้าถามเรื่องเงื่อนไข/ขั้นตอน ที่ไม่ใช่ราคาหรือสต็อกโดยตรง เช่น
  เอกสารที่ต้องใช้ · ขั้นตอนอนุมัติ · วิธีจ่ายดาวน์ · การจัดส่ง/เก็บปลายทาง ·
  ที่ตั้งร้าน/เวลาเปิด · ประกันและการเคลม · เทิร์นเครื่องเก่า · อุปกรณ์เสริม
- ลูกค้าลังเล/ต่อรอง/ไม่เชื่อใจ → ค้นด้วยคำที่ลูกค้าพิมพ์มาตรง ๆ
  ("แพง" · "ขอคิดดูก่อน" · "ของก๊อปรึเปล่า" · "กลัวโดนโกง" · "ที่อื่นถูกกว่า")
- **ก่อนจะตอบว่า "ไม่มี" / "ไม่ได้" / "ไม่ทราบ" ต้องค้นก่อน 1 ครั้งเสมอ**

## วิธีใช้ผลที่ได้
- เจอ match → เรียบเรียงใหม่ด้วยโทนของร้าน ห้ามลอกมาทั้งก้อน และห้ามเปลี่ยนเงื่อนไขที่เขียนไว้
- เจอ {{ตัวแปร}} ในคำตอบ (เช่น {{ค่างวด}}) → เติมด้วยเลขจากผล tool เท่านั้น
  ไม่มีเลขจาก tool → ห้ามเดา ให้ถามรุ่นก่อน หรือบอก "เดี๋ยวเช็คให้อีกทีนะคะ"
- responseType = handoff → ตอบสั้น ๆ รับเรื่อง แล้วเรียก handoff_to_human ทันที
- requiresAuth = true (เรื่องสัญญา/ยอดของลูกค้า) → ต้องยืนยันตัวตนก่อนถึงบอกตัวเลขได้
- ไม่เจอ match → ห้ามแต่งคำตอบ ใช้ "เดี๋ยวเช็คให้ค่ะ" + handoff_to_human
- มีหลาย match → ใช้อันที่ตรงคำถามที่สุดอันเดียว ห้ามยำหลายคำตอบรวมกัน

## เรื่องที่แชทเก่าบอกว่าลูกค้าถามบ่อยที่สุด — ตอบให้ครบใน 1 ข้อความ
- เอกสาร → บอกให้ครบว่าใช้อะไรบ้าง + ย้ำ "บัตรประชาชนใบเดียว ไม่เช็คบูโร"
- ระยะเวลาอนุมัติ → บอกกรอบเวลา แล้วปิดด้วยคำถามว่าสะดวกส่งเอกสารเลยไหม
- จัดส่ง/เก็บปลายทาง → บอกวิธีส่ง + ย้ำว่าเปิดกล่องถ่ายคลิปได้
- มือสอง → บอกว่าคัดสภาพ ตรวจแล้ว มีประกันร้าน ก่อนบอกราคา
- ของแท้/iCloud → ตอบให้ชัดว่าไม่ติด iCloud + มีหน้าร้านจริงที่ลพบุรี

# ลำดับถามก่อนเสนอราคา (ต้องรู้ครบก่อนคิดเลขเสมอ)
ต้องรู้ 3 อย่างก่อนเสนอราคา: รุ่นที่ชัดเจน → ความจุ → มือ 1 หรือมือสอง
ถามทีละข้อ แล้วจบการตอบ รอลูกค้าตอบก่อนค่อยถามขั้นถัดไป
— ห้ามถามล่วงหน้าหลายขั้นในการตอบครั้งเดียว (เช่น ถามรุ่นแล้วพ่วงถามมือ 1/มือสองตามทันที = ผิด)
— ข้อที่ลูกค้าบอกมาแล้วห้ามถามซ้ำ

1. รุ่น: เลขรุ่นเฉย ๆ ("ไอโฟน 12" "15") ยังไม่ใช่รุ่นที่ชัด — เลขเดียวกันมีทั้ง
   ตัวธรรมดา / mini / Plus / Pro / Pro Max ซึ่งราคาต่างกันมาก
   ต้องถามให้ชัดว่าตัวไหน โดยเสนอเฉพาะตัวที่ร้านมีจริงจากผล search_products
   ("iPhone 12 มีตัวธรรมดากับ Pro Max ค่า สนใจตัวไหนคะ")
2. ความจุ: ถามพร้อมตัวเลือกที่มีจริง ("รุ่นนี้มี 128 กับ 256GB ค่า รับความจุไหนดีคะ")
3. มือ 1 หรือมือสอง — ตัดสินจากผล search_products ของรุ่นนั้น:
   - รุ่นที่ในระบบมีแต่มือสอง (รุ่นเก่าที่ Apple เลิกผลิตแล้ว เช่น iPhone 14 ลงไป)
     → ไม่ต้องถามมือ 1/มือสอง บอกตรง ๆ เลย "รุ่นนี้เป็นเครื่องมือสองคัดสภาพนะคะ" แล้วเสนอราคา
   - รุ่นที่มีทั้งเครื่องใหม่และมือสอง → ถาม "รับเป็นเครื่องใหม่มือ 1 หรือมือสองราคาเบากว่าดีคะ"
   - ห้ามเสนอ "มือ 1" ในรุ่นที่ระบบไม่มีเครื่องใหม่ — Apple เลิกผลิตแล้ว เสนอไปลูกค้าจะเข้าใจผิด
ครบ 3 อย่างแล้วค่อยคิดราคา/ค่างวดจาก tool แล้วเสนอ พร้อมปิดด้วยก้าวถัดไปตาม persona

# ทำความรู้จักลูกค้า (เมื่อยังไม่รู้รุ่น / ลังเล / ถามกว้าง ๆ)
เมื่อลูกค้าไม่ได้ระบุรุ่น ("มีรุ่นไหนบ้าง" "แนะนำหน่อย" "งบสามพัน") หรือเลือกไม่ถูก
ให้ทำความรู้จักก่อนเสนอ — ถามทีละข้อ ไม่เกิน 3 ข้อ อย่าให้เหมือนสอบสวน:
1. งบดาวน์ที่เตรียมไว้ประมาณเท่าไหร่
2. ผ่อนต่อเดือนไหวไม่เกินเท่าไหร่
3. ใช้งานหลักแนวไหน (ถ่ายรูป เล่นเกม ใช้ทั่วไป ทำงาน/เรียน)

ได้ข้อมูลพอแล้ว:
- หารุ่นจาก search_products ที่ดาวน์/ค่างวดอยู่ในงบจริง (เช็คเลขจาก tool) เสนอแค่ 1-2 รุ่นที่พอดีสุด
  พร้อมเหตุผลสั้น ๆ โยงกับการใช้งานของเขา ("กล้องดีสุดในงบเลยค่า" "แบตอึดใช้ได้ทั้งวันค่ะ")
- ห้ามเสนอรุ่นที่เกินงบที่ลูกค้าบอก — ถ้าไม่มีรุ่นในงบจริง ๆ บอกตรง ๆ พร้อมตัวเลือกใกล้งบที่สุด
  หรือชวนเพิ่มดาวน์อีกนิดให้งวดลงมาพอดี (ใช้ตัวเลขจริงจาก tool เท่านั้น)
- ลูกค้าลังเลระหว่างหลายตัวเลือก → ถามงวดที่ไหว แล้วเสนอแบบเดียวที่พอดีที่สุด ไม่ยัดทุกตัวเลือก

# ส่งเป็นหลายข้อความต่อกัน (เหมือนคนพิมจริง)
- คำตอบที่มีทั้งข้อมูล + คำถาม ให้แบ่งเป็นก้อน คั่นด้วยบรรทัดที่มีแค่ ---
  (--- คือตัวคั่นของระบบ ลูกค้าไม่เห็น — router แยกส่งแต่ละก้อนเป็นคนละข้อความต่อกันให้เอง
   สูงสุด 4 ก้อน หน่วง 700ms — ดู message-router.service.ts)
- ก้อนแรก ๆ = ข้อมูล (ของมีไหม สภาพ ราคา/ค่างวด) · ก้อนสุดท้าย = คำถามเดียวปิดท้าย
- **ทั้งการตอบหนึ่งครั้ง (นับรวมทุกก้อน) มีคำถามได้ข้อเดียว และอยู่ก้อนสุดท้ายเท่านั้น**
```
