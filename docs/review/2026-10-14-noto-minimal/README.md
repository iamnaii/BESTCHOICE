# Noto Sans Thai Looped และ UI ที่อ่านน้อยลง

งานรอบนี้ทำตาม [แผนก่อนแก้ไข](../../superpowers/plans/2026-10-14-noto-minimal-ui.md) บน branch `feat/noto-minimal-ui-20261014` จาก main `c26cf0091` ใช้ UI UX Pro Max ประกอบการเลือกแนวทาง Minimalism & Swiss Style และระยะบรรทัดภาษาไทย โดยคงสี Zinc/Emerald ของระบบ

ผลรอบต่อมาสำหรับความแน่นบนมือถืออยู่ใน [รายงาน Mobile density](../2026-10-14-mobile-density/README.md) โดยผลและ source fingerprint ในรายงาน Noto นี้เก็บไว้เป็นหลักฐานของรอบก่อนหน้า

## สิ่งที่เปลี่ยน

- ใช้ Noto Sans Thai Looped ที่โฮสต์ในแอปสำหรับภาษาไทย อังกฤษ ตัวเลข เมนู ช่องกรอก การแจ้งเตือน หน้าเข้าสู่ระบบ หน้าเว็บสาธารณะ หน้า LINE และหน้าร้าน
- คงฟอนต์ในสัญญา ใบเสร็จ ใบสำคัญ สติกเกอร์ ตัวแก้ไขเอกสาร PDF และรูปแบบตอนพิมพ์ แยกขอบเขตเอกสารออกจากปุ่ม/ตัวกรองรอบเอกสาร
- โหลดฟอนต์แบบ variable 100–900 จากไฟล์ WOFF2 ของ Google Fonts พร้อม OFL และข้อมูลต้นทางใน `public/fonts/noto-sans-thai-looped/SOURCE.json` ของทั้งสองแอป
- หัวข้อหลักแอดมินยังเป็น 22px บนมือถือ / 24px บนเดสก์ท็อป ตัวเนื้อหา/ตาราง 14–16px ข้อมูลรองอย่างน้อย 12px และช่องกรอกมือถืออย่างน้อย 16px
- การ์ดยอดเงินใช้ระยะบรรทัด 1.65 เพื่อรองรับฟอนต์ใหม่และยังอ่านตัวเลขครบ จอเล็กกว่า 390px เรียงการ์ดจำนวนเงินเป็นคอลัมน์เดียว; กลุ่ม 3/5 ใบให้ใบสุดท้ายเต็มแถวเมื่อจอแคบ กลุ่มตัวนับค่าใช้จ่ายยังใช้สองคอลัมน์
- ย่อชื่อเมนูมือถือสองจุดเป็น “สัญญา” และ “จดหมาย” โดยคงปลายทางและสิทธิ์เดิม ชื่อเต็มในเมนูหลักยังอยู่
- หน้านโยบาย HTML แยกมีฟอนต์ตรงกับแอป ตารางเลื่อนภายในได้ด้วยคีย์บอร์ดและ URL ยาวตัดบรรทัดได้ โดยรูปแบบพิมพ์เดิมไม่เปลี่ยน

## ลดข้อความที่ต้องอ่านก่อนเริ่มงาน

| รอถ่ายรูป QC | แยกคำอธิบายแหล่งที่มาของเครื่องออกจากงานหลัก | ต้องถ่าย 6 มุมก่อนขึ้นขาย |

| สำรองข้อมูล | ย่อคำอธิบายรอบทำงาน รายละเอียดทางเทคนิคเปิดเพิ่มได้ | ต้องตั้งค่าที่เก็บและสิทธิ์ก่อนเปิด คำเตือน SQL |

## การตรวจ

ผลตรวจ UI ผ่านแล้ว: inventory **807 สถานะ / 1,614 ภาพ**, admin typography **24 route/width states**, finance cards **78 route/tab/width states**, public/disclosure/navigation **23 states**, LINE **84 cases** และ storefront **102 route/width states** รวมการทดสอบปฏิสัมพันธ์เพิ่มเติม รายการละเอียดอยู่ใน `verification.json` และ [สรุปทุกเส้นทาง](route-summary.json)

การตรวจ `local:check` รอบปิดงาน **ผ่านครบ 39 ขั้นตอน** รวม types, lint, build, unit tests ของ web 3,326 / shared 149 / storefront 46 รายการ และ browser flow บนมือถือ/เดสก์ท็อป ดู [ผลตรวจรอบสุดท้าย](local-check.json) ตรวจจบวันที่ 14 ตุลาคม 2026 เวลา 16:31 น. (กรุงเทพฯ) และยืนยันว่า preview ใช้ source fingerprint ตรงกับผลตรวจ

ชุดตรวจครอบคลุม:

- `npm run local:check`: types, lint, build, unit tests และ browser flow บน preview ของ checkout นี้
- inventory 269 รายการ × 3 ขนาดจอ × 2 ธีม: การเรนเดอร์ ฟอนต์ที่โหลดจริง ข้อความ UI ที่ใช้ฟอนต์ผิด การล้นหน้าจอ และ JavaScript errors
- admin typography: 6 เส้นทาง × 4 ขนาดจอ รวม input, badge, portal และ toast
- finance cards: 10 เส้นทางและ 3 tab states × 6 ขนาดจอ พร้อมยอดหลักล้านและยอดติดลบ
- หน้าเว็บสาธารณะ/ตัวช่วย: 23 สถานะ รวมขยาย root text 200% และเมนูของทุก role/zone
- LINE: 84 กรณีบน Chromium/WebKit และโหมดสว่าง/มืด โดยจำลอง SDK/API
- หน้าร้าน: 17 เส้นทาง × 6 ขนาดจอ พร้อมเมนู ค้นหา ตัวกรอง ฟอร์ม toast และตัวอักษรขยาย; catalog/warranty เดิมอีก 4 กรณี
- เอกสารจริง 3 renderer × screen/print เทียบ font metrics และ geometry ทุก descendant ก่อน–หลัง; หน้า policy HTML อีก 2 หน้าเทียบตอนพิมพ์
- ผู้ตรวจโค้ดอิสระตรวจฟอนต์ที่เรนเดอร์จริง การเข้าถึงด้วยคีย์บอร์ด ขอบเขตเอกสาร ข้อความสำคัญ และการแก้สเกลรอบท้ายแล้ว ไม่มีข้อค้างจาก review

ระหว่างตรวจพบและแก้: ขอบเขตฟอนต์ที่ครอบปุ่มรอบเอกสารกว้างเกินไป, ฟอนต์ใน standalone HTML, ตาราง/URL ล้นบน 320px, ชื่อเมนูมือถือแน่น และพื้นที่ของตัวเลขในการ์ดการเงิน รวมทั้งปรับตัวทดสอบ badge ให้ระบุแถวแชทที่ตั้งใจตรวจ และตั้ง fixture หน้าชำระเงินเป็นกรณียกเลิก LINE login เพื่อไม่ให้หลุดไปอ่าน JSON ของ API ที่ไม่ได้ตั้งค่า LINE

ตัวทดสอบคิวแชทรองรับข้อมูลจำลองที่สะสมจนมีหลายหน้าแล้ว ทั้งการค้นหารายการและการตรวจว่าไม่มีข้อมูลข้ามบริษัท รวมถึงไม่ยอมให้การโหลดล้มเหลวถูกนับเป็นคิวว่าง ทดสอบกรณีจงใจใส่รายการผิดบริษัทไว้คนละหน้ากับรายการเป้าหมายแล้ว ตัวตรวจจับความผิดพลาดได้ตามที่ต้องการ การปรับนี้อยู่ในเครื่องมือทดสอบ ไม่เปลี่ยนการทำงานของคิวในแอป
