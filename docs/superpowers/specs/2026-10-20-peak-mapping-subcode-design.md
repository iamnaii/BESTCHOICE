# PEAK mapping — รหัสย่อย PEAK + แหล่งรหัสย่อย (FINANCE mapping v5 · 2026-10-20)

ที่มา: ฝ่ายบัญชีส่งไฟล์ **FINANCE mapping v5** (19/10/2569 — Google Sheet / `BESTCHOICE-PEAK_mapping_FINANCE_19-10-69.xlsx`)
พร้อมโน้ต "สิ่งที่ต้องแจ้งโปรแกรม MAPPING":

1. บัญชีที่ไม่มีให้เพิ่มรหัสตามไฟล์
2. ผูกบัญชีกับรหัสบัญชี PEAK
3. เพิ่ม รหัสย่อย / subCodeSource / แหล่ง sub code

## คำตัดสินเจ้าของ 2026-10-20 (ปิดประเด็น — อย่าเสนอซ้ำ)

**คงผังบัญชีของระบบไว้ ไม่ยุบ/ไม่เปลี่ยนเลขให้เป็นตาม PEAK** — ผังเราเป็นสมุดใช้งาน (accrual ตามงวด · บัญชีแยกที่ขับฟีเจอร์ค้างชำระ/VAT/ปิดยอด ·
รหัสฝังในโค้ดหลายร้อยจุด + เทสทองของ CPA) ส่วน PEAK ได้ข้อมูลผ่าน "ชั้นแปล" = รหัส PEAK + รหัสย่อย/แหล่งรหัสย่อย (งานนี้) + กติกา export
รายบรรทัด 1A/2A/2B ของฝ่ายบัญชี (งานถัดไป). ถามเจ้าของแล้วเมื่อ 2026-10-20 ("แล้วเราปรับให้เป็นตาม PEAK เลยไม่ดีกว่าหรอ" → "ทำตามที่แนะนำได้เลย ไม่ต้องยุบ").

## เป้าหมาย

- ผังบัญชี FINANCE ในระบบตรงกับไฟล์ของฝ่ายบัญชี: บัญชีครบ · รหัส PEAK ครบ · รู้ว่าบรรทัดของบัญชีไหนต้องส่ง "บัญชีย่อย" ของ PEAK แบบไหน
- ไม่แตะกติกาลงบัญชี (JE) — งานนี้คือ **ข้อมูลผูกรหัส** ไม่ใช่กติกา export รายบรรทัด (กติกา export 1A/2A/2B ของฝ่ายบัญชีเป็นงานถัดไป)
- ข้อมูลผูกรหัสต้องถึง prod พร้อม deploy (migration) ไม่ต้องรัน seed มือ และไม่ทับค่าที่เจ้าของแก้ในหน้าจอ

## ไม่ทำในงานนี้

- UI คอลัมน์ "รหัสย่อย PEAK / แหล่งรหัสย่อย" บนหน้า `/settings/accounting/chart?tab=peak` — รอเจ้าของเคาะ mockup ก่อนแตะโค้ด (กติกา 2026-09-06)
- การ resolve รหัสย่อยรายบรรทัดสำหรับ `contact` / `bank` / `cashbox` ตอน export (ต้องรู้ผู้ติดต่อ/บัญชีธนาคารของบรรทัด — JournalLine ยังไม่เก็บ)
- การปิดบัญชีที่โค้ดลงรายการยังอ้างอยู่ และการเปลี่ยนชื่อ 42-1106 (ดู "รอเจ้าของตัดสิน")

## สิ่งที่ทำ

### 1. โมเดล

`ChartOfAccount` เพิ่ม `peakSubCode String?` (`peak_sub_code`) และ `peakSubCodeSource String @default("none")` (`peak_sub_code_source`)
ค่า = `none | fixed | contact | bank | cashbox` (`PEAK_SUB_CODE_SOURCES` ใน `peak-mapping.dto.ts` — string ไม่ใช่ Prisma enum เหมือน `status`).
กติกา: `fixed` ต้องมี `peakSubCode` · แหล่งอื่นเก็บ `null` เสมอ (รหัสย่อยมาจากบรรทัดตอน export).

### 2. API `/chart-of-accounts/peak-mapping`

- GET คืน `peakSubCode` + `peakSubCodeSource` เพิ่ม
- PUT รับสองฟิลด์เป็น optional — **ไม่ส่ง = ไม่แตะค่าเดิม** (UI เดิมที่ส่งแค่ `peakCode` ไม่ทำรหัสย่อยหาย) · ส่ง source ≠ fixed = ล้างรหัสย่อย ·
  fixed โดยไม่มีรหัสย่อย = 400 ทั้งชุด (all-or-nothing เหมือนเดิม) · audit `PEAK_MAPPING_UPDATED` เพิ่ม `peakSubCodeBefore/After` + `sourceBefore/After`
- CSV ดาวน์โหลด = `code,name,peakCode,peakSubCode,peakSubCodeSource` (3 คอลัมน์แรกเท่าเดิม — ไฟล์นำเข้าแบบเก่ายังใช้ได้)

### 3. Export สมุดรายวัน (`/expenses/journal/export-peak`)

เพิ่มคอลัมน์ `peakSubCode` ต่อจาก `peakCode` — ใส่ค่าเฉพาะบัญชีที่ source = `fixed`; แหล่งอื่นเว้นว่างจนกว่ากติกา export รายบรรทัดจะมา · **รอบ 2 (2026-10-20): `contact` แก้รายบรรทัดแล้ว — ดูหัวข้อ "รอบ 2" ท้ายเอกสาร**

## รอบ 2 — รหัสย่อยรายบรรทัด (contact) + ปิด/เปลี่ยนชื่อตามไฟล์ (เจ้าของ 2026-10-20: "1 ทำรหัสย่อยได้เลย · 2 ตามไฟล์ได้เลย · 3 ok")

### 1. Export แก้รหัสย่อย `contact` รายบรรทัด (`peak-export.service.ts`)

| บัญชี (source = contact) | คู่สัญญา | ที่มาของรหัส |
|---|---|---|
| `11-2101` `11-2103` `11-2104` `11-2105` `21-1103` (`CUSTOMER_CONTACT_ACCOUNTS`) | ลูกค้าของสัญญา | `JournalEntry.metadata.contractId` → `Contract.customer.contact.peakContactCode` |

- ค้น 2 ครั้งแบบ batch (`contract.findMany` / `expenseDocument.findMany` ด้วย `id in [...]`) ไม่ค้นต่อบรรทัด · รายการที่ไม่มีรหัส / บัญชีไม่อยู่ในสองรายการ / source = `bank`·`cashbox` (ไม่มีตัวแก้ — เงินสด/ธนาคารผูก `fixed` อยู่แล้ว) → ช่องว่าง + นับใน `unresolvedSubCodeCount`
- header ใหม่ `X-Unresolved-Sub-Codes` (expose คู่ `X-Skipped-Lines` / `X-Row-Count`) · หน้า `/finance/peak-export` ขึ้นเตือนบรรทัดที่สอง "รหัสย่อยยังหาไม่ได้ N บรรทัด (ผู้ติดต่อยังไม่มีรหัส PEAK)" + ลิงก์ไป `/contacts`

### 2. ใส่รหัสผู้ติดต่อ PEAK (`Contact.peakContactCode` มีอยู่แล้ว แต่ไม่มีที่กรอก)

- `PATCH /contacts/:id/peak-code` `{ peakContactCode }` — OWNER / ACCOUNTANT · trim → null = ล้าง · ต้องตรง `^[A-Za-z0-9\-_.]{1,20}$` ไม่งั้น 400 ไทย · ไม่เปลี่ยน = ไม่เขียน · audit `CONTACT_PEAK_CODE_SET` (ค่าเก่า/ใหม่ + contactCode)
- หน้า `/contacts/:id` ช่อง "รหัสผู้ติดต่อ PEAK" ใน identity hero (`PeakContactCodeField`) — OWNER / ACCOUNTANT แก้ได้ (ปุ่มบันทึกเปิดเมื่อค่าเปลี่ยน · ตรวจรูปแบบก่อนยิง API) · role อื่นอ่านอย่างเดียว
