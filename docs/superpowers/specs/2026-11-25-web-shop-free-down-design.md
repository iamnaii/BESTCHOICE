## 3. นิยาม

**ค่าตั้งต้นของเรท 2** = งวดตั้งต้นของเครื่อง (งวดเรท 2 ของราคากลาง ไม่มีแล้วเพดานของรุ่น) + ดาวน์ขั้นต่ำของเรท 2
(`resolveGfinDownPct`) — คือสิ่งที่ server เลือกเองเมื่อผู้เรียก**ไม่ส่ง**งวดและ % ดาวน์
ราคาที่ใช้คิด = ราคาขายเรท 2 ของเครื่อง (`financePrice`) ถ้ามี ไม่งั้นราคาผ่อน — กติกาเดียวกับหน้ารายละเอียด

**แผนเรท 2 ของการ์ด** = ผลคิดเรท 2 ด้วยค่าตั้งต้น: `{ down, monthly, months }` · คิดไม่ได้ = ไม่มี
เงินดาวน์ที่ลูกค้าพิมพ์และตัวเลือกจำนวนงวดในตัวกรอง **ไม่มีผล** กับแผนนี้

**ฟรีดาวน์** = แผนเรท 2 ที่ `down` = 0

**ดาวน์ขั้นต่ำเรท 1 ของเครื่อง** = ราคาผ่อน × % ขั้นต่ำของหมวด แล้วปัดขึ้นหลักร้อย (`downFromPct` — กติกา 2026-11-19)
ตัวเลขนี้คือทั้งที่การ์ดโชว์ตอนไม่ใส่อะไร และเกณฑ์ตัดสินว่าเงิน X พอสำหรับเรท 1 หรือไม่ (ตัวเดียวกัน ห้ามใช้เกณฑ์ "ถึง 15% พอ" ที่ไม่ปัด)

**เพดานเงินดาวน์เรท 1** = 90% ของราคาผ่อน ปัดลงเป็นบาทเต็ม (ค่าเดียวกับหน้ารายละเอียด `MAX_DOWN_PCT`) — พิมพ์เกินใช้เพดาน

**การ์ดกลุ่ม (เครื่องมือ 1)**: เรท 1 คิดจากราคาผ่อนต่ำสุดของกลุ่ม (ตามเดิม) · แผนเรท 2 คิดจากเครื่องที่การ์ดลิงก์ไป
(เครื่องเดียวกับที่ลูกค้าจะเห็นเมื่อกดเข้าไป)

## 4. การ์ด — กล่องราคาในโหมดผ่อน

```
┌ ดาวน์                    ┐   text-xs สีเทา
│ ฿5,000                   │   ตัวใหญ่ text-primary
│ ผ่อน ฿1,960 × 12 งวด     │   text-xs บรรทัดเดียว (whitespace-nowrap)
└──────────────────────────┘   กล่องเรท 1 — พื้น bg-muted (มินต์)
┌ ฟรีดาวน์                 ┐   แผนเรท 2 ดาวน์ 0 — ตัวใหญ่ พื้นเหลืองอ่อน + ขอบเหลือง
│ ผ่อน ฿4,061 × 15 งวด     │
└──────────────────────────┘
┌ ดาวน์                    ┐   แผนเรท 2 ดาวน์ > 0 — หน้าตาเดียวกับกล่องเรท 1 (ไม่เหลือง)
│ ฿1,000                   │
│ ผ่อน ฿3,450 × 15 งวด     │
└──────────────────────────┘
```

**กล่องล่างขึ้นเมื่อ** เครื่องมีแผนเรท 2 และ (ดาวน์ของแผนเรท 2 < ดาวน์ในกล่องเรท 1 **หรือ** ไม่มีกล่องเรท 1)
ดาวน์เรท 2 ≥ ดาวน์เรท 1 → ไม่ขึ้น (ไม่ช่วยให้ใช้เงินน้อยลง — ลูกค้าเทียบค่างวดได้ในหน้ารายละเอียด)

- ใช้โทเคนเดิมของหน้าร้านทั้งหมด (`font-head` / `num` / `text-primary` / `bg-muted` / `bg-ink` / มุมมนและเงาเดิม)
  สีใหม่มีอย่างเดียวคือเหลืองอ่อนของกล่องฟรีดาวน์ (เหลืองสงวนให้โปรจริง) · ตัวอักษรบนพื้นเหลืองต้องผ่าน 4.5:1
- มีคำว่า "ฟรีดาวน์" กำกับเสมอ ไม่บอกด้วยสีอย่างเดียว
- ปุ่ม "ดูเครื่องนี้" ชิดล่างการ์ด (มีอยู่แล้ว) การ์ดกล่องเดียวกับสองกล่องจึงเสมอกันในแถว
- มือถือ (การ์ดกว้างราว 170px): ระยะขอบกล่องซ้ายขวา 8px · บรรทัดค่างวดต้องไม่ตกบรรทัดแม้ค่างวดหลักหมื่น
- ไม่มีทั้งสองกล่อง = "สอบถามค่างวด" · ไม่มีราคา = "สอบถามราคา" (ตามเดิม)
- โหมด `cash` และ `combined` (หน้าแรก / เครื่องใกล้เคียง) ไม่เปลี่ยน

## 5. กล่องเงินดาวน์ในตัวกรอง — 3 สถานะ (รอบ 2 · รอบ 1 มีสถานะ ① กับ ③)

| สถานะ | เครื่องที่ขึ้น | กล่องเรท 1 | กล่องล่าง (แผนเรท 2) |
|---|---|---|---|
| ① ไม่ใส่อะไร | ทุกเครื่อง | ดาวน์ขั้นต่ำเรท 1 ของเครื่อง + ค่างวด | ตามกติกาหัวข้อ 4 |
| ② พิมพ์ X บาท | X ≥ ดาวน์ขั้นต่ำเรท 1 **หรือ** ดาวน์ของแผนเรท 2 ≤ X | ดาวน์ = X (ไม่เกินเพดาน) + ค่างวดคำนวณใหม่ · เงินไม่พอ = ไม่มีกล่องนี้ | ขึ้นเมื่อดาวน์เรท 2 ≤ X และน้อยกว่าดาวน์ในกล่องเรท 1 (หรือไม่มีกล่องเรท 1) |
| ③ ติ๊กฟรีดาวน์ | เฉพาะเครื่องที่แผนเรท 2 ดาวน์ 0 | ไม่ขึ้น | กล่องฟรีดาวน์กล่องเดียว |

- เครื่องที่เงินไม่พอทั้งสองเรท → ไม่ขึ้น · ท้ายรายการมีบรรทัด
  "อีก N เครื่องต้องดาวน์มากกว่า ฿X (เริ่มที่ ฿Y) — ดูทั้งหมด" · Y = เงินดาวน์น้อยที่สุดที่ทำให้เครื่องถัดไปขึ้น
  (ค่าน้อยสุดของ `min(ดาวน์ขั้นต่ำเรท 1, ดาวน์แผนเรท 2)` ในกลุ่มที่ถูกตัด) · "ดูทั้งหมด" = ล้างช่องเงินดาวน์
- พิมพ์ 0 = ติ๊กฟรีดาวน์
- ติ๊กฟรีดาวน์ → ช่องเงินดาวน์ (รอบ 1: แถบเลื่อน %) ใช้ไม่ได้ · เอาติ๊กออก → กลับสถานะ ①
- ไม่มีเครื่องเข้าเงื่อนไข → "เงินดาวน์ ฿X ยังไม่พอ — ดาวน์ต่ำสุดเริ่มที่ ฿Y" + ปุ่ม "ดูเครื่องฟรีดาวน์" (ถ้ามี) + ปุ่มล้างเงินดาวน์
- ค่าที่พิมพ์ commit ตอนออกจากช่อง / กด Enter แล้วหน่วง 250ms ก่อนยิง API (รูปแบบเดียวกับช่อง % เดิม)
- โหมดซื้อสด: ไม่มีกล่องเงินดาวน์ (ตามเดิม) · สลับไปซื้อสดล้าง `down` / `freeDown` ออกจาก URL

## 6. ตัวกรองโฉมใหม่ (`FilterSidebar` + แถบบนของ `CatalogPage`) — รอบ 2

โครงและกรอบเดิม (กรอบมุมมน 40px หัว "ตัวกรองสินค้า" + ไอคอน) เรียงจากบนลงล่าง:

1. **กล่องเงินดาวน์** (พื้นมินต์เดิม)
   - "เงินดาวน์ [____] บาท" — ช่องตัวเลข (`inputMode="numeric"`) มี label · ไม่มีปุ่มลัดจำนวนเงิน
   - ช่องติ๊ก "ฟรีดาวน์ · N เครื่อง" — `<input type="checkbox">` จริง มี label แถวสูง ≥ 44px · ติ๊กแล้วแถวพื้นเหลือง
     · N = 0 และไม่ได้ติ๊กอยู่ → ไม่แสดงแถวนี้
   - "จำนวนงวด" ดรอปดาวน์เดิม (มีผลกับกล่องเรท 1)
2. **ประเภทเครื่อง** — ปุ่มคู่ มือ 1 / มือ 2 (เดิม)
3. **เครื่องไทย / เครื่องนอก** — ปุ่มกด 3 ตัว: ทั้งหมด · เครื่องไทย · เครื่องนอก (แทนดรอปดาวน์)
4. **รุ่น** — ดรอปดาวน์เดิม
5. **ช่วงราคา** — ปุ่มกด 6 ช่วงเดิม ขึ้นบรรทัดใหม่ได้ (แทนดรอปดาวน์)
6. "ล้างตัวกรองทั้งหมด" — ล้างเงินดาวน์และติ๊กฟรีดาวน์ด้วย

- เอา "สภาพเครื่อง" ออกจากตัวกรอง (ป้ายเกรดบนการ์ดและหน้ารายละเอียดยังอยู่) · API ยังรับ `conditionGrade` ตามเดิม
- ปุ่มกดทุกตัวเป็น `<button aria-pressed>` · ตัวที่เลือกอยู่พื้นเขียวตัวขาว (รูปแบบ `Pill` เดิม)
- **มือถือ**: ใต้สวิตช์ ผ่อน/ซื้อสด เพิ่มแถว "เงินดาวน์ [____] บาท" + ช่องติ๊ก "ฟรีดาวน์" ใช้ได้โดยไม่ต้องเปิดแผง ·
  แถวถัดไป: ทั้งหมด / มือ 1 / มือ 2 / ปุ่ม "ตัวกรอง" (เดิม) · แผงตัวกรองมีเนื้อหาเดียวกับแถบข้าง
- บรรทัดสรุปเหนือรายการ: สถานะ ② "พบ N เครื่องที่ดาวน์ได้ด้วยเงิน ฿X" · สถานะ ③ "พบ N เครื่องฟรีดาวน์" · นอกนั้นข้อความเดิม
- สถานะเก็บใน URL: `?down=5000` · `?freeDown=1`

## 7. หน้ารายละเอียดเครื่อง (`InstallmentCalculatorCard`)

- หัวการ์ด "เรท 1" / "เรท 2" (ทำแล้วในสาขานี้)
- **คำขอเรท 2 ไม่ส่ง % ดาวน์จนกว่าลูกค้าจะแก้ช่องเงินดาวน์ในหน้านี้** (แบบเดียวกับที่ไม่ส่งงวดอยู่แล้ว) → server ใช้ค่าตั้งต้นของเรท 2
  ⇒ เรท 2 ตอนเปิดหน้า = แผนเรท 2 บนการ์ดเสมอ · ลูกค้าแก้ช่องเงินดาวน์แล้ว ทั้งสองเรทคิดจากค่าที่แก้ (พฤติกรรมเดิม)
- ป้ายเล็กข้างหัว คิดจากผลของสองเรท ณ ตอนนั้น ขึ้นเฉพาะเมื่อคิดได้ทั้งคู่และต่างกันจริง:
  `ดาวน์น้อยกว่า` · `ค่างวดต่ำกว่า` · `ผ่อนจบเร็วกว่า`
- เรท 2 ดาวน์ = 0: การ์ดเรท 2 พื้นเหลืองอ่อน ป้าย "ฟรีดาวน์" (แทน "ดาวน์น้อยกว่า") บรรทัดดาวน์เขียน "ไม่ต้องวางดาวน์ · 15 งวด"
- รอบ 2: เปิดด้วย `?down=5000` → เรท 1 เริ่มที่เงินดาวน์ ฿5,000 (โหมดจำนวนเงินที่มีอยู่แล้ว) · เรท 2 ยังเป็นค่าตั้งต้น (ข1) ·
  ลิงก์จากการ์ดพา `?down=` ไปด้วยเฉพาะสถานะ ②
- ไม่มียอดรวมจ่าย · ไม่มีชื่อผู้ให้ผ่อน

## 8. ฝั่งระบบ (API `shop-catalog`)

**ตัวคิดเรท 2 ตัวเดียว** — แยกส่วนคิดเรท 2 ออกจาก `InstallmentPreviewService.previewGfin` เป็น util ใช้ร่วม
(`shop-gfin-quote.util.ts`):

- `loadShopGfinContext(prisma)` — อ่านตั้งค่า / ราคากลาง / เงื่อนไขรุ่น / ตารางเรท ครั้งเดียวต่อคำขอ
- `quoteShopGfin(ctx, product, salePrice, terms, { months?, downPct? })` — ฟังก์ชันบริสุทธิ์ ผลเท่ากับ `previewGfin` วันนี้
- `previewGfin` (หน้ารายละเอียด) และ `listGroupedByModel` (หน้ารวม) เรียกตัวเดียวกัน · งวดตั้งต้นของทุกเครื่องในหน้า
  อ่านด้วย `loadTemplateTerms` รอบเดียว
- หน้ารวมต้องอ่าน `financePrice` ของเครื่องเพิ่ม (วันนี้ `select` ไม่มี) และของเครื่องตัวอย่างของการ์ดกลุ่ม

**เรท 1 จากเงินดาวน์เป็นบาท (รอบ 2)** — `installmentFor` รับ `downAmount`: น้อยกว่าดาวน์ขั้นต่ำเรท 1 ของเครื่อง → ไม่มีกล่องเรท 1 ·
ไม่งั้นส่ง `customDownAmount = min(downAmount, เพดาน 90%)` เข้า `calcBcInstallment`

**สัญญาข้อมูล `GET /shop/products`**

| ที่ | เพิ่ม | รอบ |
|---|---|---|
| รายการทุกแบบ | `rate2: { down: number; monthly: number; months: number } \| null` | 1 |
| query | `freeDown=true` | 1 |
| คำตอบ | `freeDownCount` | 1 |
| query | `downAmount` (จำนวนเต็มบาท ≥ 0) | 2 |
| รายการทุกแบบ | `monthlyPaymentFrom` / `downAmount` / `installmentMonths` เป็น null เมื่อเงินไม่พอสำหรับเรท 1 (ช่องเดิม) | 2 |
| คำตอบ | `overBudgetCount` · `nextDownFrom` (null ถ้าไม่มี) | 2 |

- ลำดับ: ตัวกรองอื่น → คิดเรท 1 และแผนเรท 2 ทุกรายการ → นับ `freeDownCount` → ตัดรายการที่เงินไม่พอ (นับ `overBudgetCount`) →
  ตัวกรองฟรีดาวน์ → เรียง → แบ่งหน้า · ตัวนับทุกตัวไม่ขึ้นกับการแบ่งหน้า
- `freeDown=true` ชนะ `downAmount` · `downAmount=0` = `freeDown=true`
- `downPct` (ของเดิม) ยังรับต่อ: รอบ 1 เว็บยังใช้ · รอบ 2 เว็บเลิกส่ง แต่ API คงไว้เพื่อเว็บรุ่นเก่าที่ค้างในเครื่องลูกค้า
- `rate2.down` / `rate2.monthly` ปัดขึ้นเป็นบาทเต็มแบบเดียวกับเรท 1 บนการ์ด
- ห้ามส่งราคาส่ง / ส่วนลดดาวน์ของเรท 2 ออกหน้าร้าน (กติกาเดิม)
- ช่องใหม่เป็น optional ทั้งสองฝั่ง: เว็บใหม่ + API เก่า = ไม่มีกล่องล่าง/ไม่มีช่องติ๊ก และ (รอบ 2) ช่องเงินดาวน์ไม่มีผล
  ⇒ **deploy API ก่อนหรือพร้อมเว็บ** · เว็บเก่า + API ใหม่ = ทำงานแบบเดิม

## 9. แบ่งงาน 2 รอบ

**รอบ 1 — ฟรีดาวน์ขึ้นบนการ์ดและกรองได้** (ตอบโจทย์แรก ความเสี่ยงต่ำ ไม่แตะวิธีตั้งดาวน์)

- API: util คิดเรท 2 ตัวเดียว · `rate2` ต่อรายการ · `freeDown=true` · `freeDownCount`
- การ์ด: กล่องราคาสองกล่อง (หัวข้อ 4) · บรรทัด "ผ่อน ฿X × N งวด"
- ตัวกรอง: ช่องติ๊ก "ฟรีดาวน์ · N เครื่อง" ในกล่องเงินดาวน์เดิม (แถบเลื่อน % ยังอยู่ ใช้ไม่ได้ตอนติ๊ก) + ช่องติ๊กบนแถบบนมือถือ · `?freeDown=1`
- หน้ารายละเอียด: เรท 2 ไม่ส่ง % ดาวน์ตอนเปิด · ป้ายเทียบสองเรท · หน้าตาฟรีดาวน์
- รวมสองจุดที่ทำไปแล้ว (หัวข้อ 13)

**รอบ 2 — เงินดาวน์เป็นบาท + ตัวกรองโฉมใหม่**

- API: `downAmount` · `overBudgetCount` · `nextDownFrom`
- ตัวกรอง: ช่องเงินดาวน์เป็นบาทแทนแถบเลื่อน · สถานะ ② · ปุ่มกดแทนดรอปดาวน์ · เอาสภาพเครื่องออก · แถวเงินดาวน์บนมือถือ · `?down=`
- หน้ารายละเอียด: เปิดด้วย `?down=` (ข1)

## 10. การทดสอบ

- **API รอบ 1**: เรท 2 ดาวน์ 0 → `rate2.down = 0` · ดาวน์ > 0 → ค่าจริง · คิดไม่ได้ → null · ใช้ `financePrice` เมื่อมี ·
  `freeDown=true` กรองก่อนแบ่งหน้า · `freeDownCount` ไม่เปลี่ยนตามหน้า · `downPct` / `months` ของคำขอไม่เปลี่ยน `rate2` ·
  **parity**: `rate2` ของหน้ารวม = `/shop/installment-preview` provider GFIN ที่ไม่ส่ง `months` / `downPct` ของเครื่องเดียวกัน
  (ต่อจาก `shop-catalog.installment-parity.spec.ts`) · `previewGfin` ให้ผลเท่าเดิมหลังย้ายไปใช้ util
- **API รอบ 2**: `downAmount` ≥ ดาวน์ขั้นต่ำเรท 1 (ปัดหลักร้อย) → ดาวน์เท่าที่ส่ง ค่างวดลด · ต่ำกว่า 1 บาท → ไม่มีเรท 1 ·
  เกินเพดาน → ตรึง 90% · เงินไม่พอเรท 1 แต่ `rate2.down` ≤ เงิน → ยังอยู่ · ไม่พอทั้งคู่ → ตัดออก + นับ ·
  `nextDownFrom` ถูก · parity เรท 1 กับ preview `customDownAmount`
- **เว็บ**: กล่องล่างขึ้น/ไม่ขึ้นตามกติกาหัวข้อ 4 (ฟรีดาวน์ · ดาวน์น้อยกว่า · ดาวน์มากกว่า · ไม่มีเรท 1) · รูปบรรทัดค่างวด ·
  ติ๊กฟรีดาวน์ปิดช่องดาวน์ · `?freeDown=1` · หน้ารายละเอียด: เรท 2 ไม่ส่ง `downPct` จนกว่าจะแก้ช่อง · ป้ายเทียบสองเรท ·
  รอบ 2: ช่องเงินดาวน์ commit ตอน blur/Enter · พิมพ์ 0 = ติ๊ก · `?down=` · ไม่มีตัวกรองสภาพเครื่อง · ปุ่มกดแทนดรอปดาวน์
- **ตาดู**: จอ 360px และ 1280px — บรรทัดค่างวดไม่ตกบรรทัด ป้ายไม่ล้น หน้าตาตรงกับหน้าร้านเดิม
