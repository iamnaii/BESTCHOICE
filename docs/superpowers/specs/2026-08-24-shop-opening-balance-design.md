**ไม่ทำในรอบนี้:** ยอดยกมาฝั่ง FINANCE · รายการระหว่างกิจการ (ดู §6) · การย้ายรายการเก่า
`S21-3001` → `S21-1104` · การรวมงบสองฝั่ง

## 5. JE ยอดยกมา

```
วันที่ 29 ส.ค. 2569 · companyId = SHOP · ทุกบรรทัดขึ้นต้นด้วย S
คำอธิบาย: "ปรับยอดยกมาฝั่งหน้าร้าน (SHOP) ให้ตรงของจริง ณ 29 ส.ค. 2569"

เดบิต
  S11-1101 / S11-1102 / S11-1103   เงินสด — ลิ้นชักสาขา
  S11-1201                          ธนาคาร SHOP (รับ)
  S11-1202                          ธนาคาร SHOP (จ่าย)
  S11-2001                          สินค้าคงเหลือ — มือถือใหม่
  S11-2002                          สินค้าคงเหลือ — มือถือมือสอง
  S11-2003                          สินค้าคงเหลือ — อุปกรณ์เสริม

เครดิต
  S21-1101                          เจ้าหนี้ — ซัพพลายเออร์มือถือ
  S21-1102                          เจ้าหนี้ — อุปกรณ์เสริม
  S21-2001                          เงินรับล่วงหน้า (เงินดาวน์ที่ยังไม่เปิดสัญญา)
  S21-4101  <-- ใหม่                เงินกู้ยืมกรรมการ
  S32-1101                          กำไร (ขาดทุน) สะสม — SHOP     <-- ตัวปิด
```

**ตัวปิดอาจอยู่ฝั่งเดบิต** ถ้าหนี้สินมากกว่าสินทรัพย์ (ขาดทุนสะสม) — ไม่ผิด แต่ต้องเตรียมใจ

**ทำไมตัวปิดเป็น `S32-1101` ไม่ใช่ `S31-1101`:** ทุนควรเป็นจำนวนที่เจ้าของลงจริงและมีเอกสาร
รองรับ ส่วนต่างที่เหลือคือผลสะสมของการดำเนินงานที่ผ่านมา — และ CPA ย้าย `S32` → `S31`
ทีหลังด้วย JE ใบเดียวได้ โดยไม่กระทบสินทรัพย์/หนี้สิน/กำไรขาดทุน

### 5.1 ยอดที่ลง = **ส่วนต่าง** ไม่ใช่ยอดเต็ม

สมุด SHOP ไม่ได้ว่างเปล่า (F2 — ขายสดลง JE มาตั้งแต่ 23 มิ.ย. 2569) สูตรต่อบัญชีคือ:

```
ยอดที่ลงใน JE = ยอดที่ควรเป็น ณ 29 ส.ค. (นับจริง/สเตทเมนต์)
              − ยอดที่มีอยู่แล้วในสมุด ณ 29 ส.ค. (SQL หมวด 2.1)
```

ตัวอย่าง: นับมือถือใหม่ได้ 4,200,000 แต่ `S11-2001` ติดลบ 800,000 → **ลง Dr 5,000,000**
เพื่อให้ยอดสุทธิหลังลง = 4,200,000 ตามที่นับได้

ถ้า SQL หมวด 2.2 ตอบว่า *"สมุด SHOP ว่างเปล่า"* → ลงยอดเต็มได้ ไม่ต้องหักส่วนต่าง

## 6. สิ่งที่ **ตัดออก** จากยอดยกมา — และเหตุผล

ร่างแรกมีบรรทัดระหว่างกิจการ 2 กลุ่ม ตัดออกทั้งคู่หลัง scrutinize:

### 6.1 `S11-3001` / `S11-3002` ลูกหนี้ FINANCE — **ตัดออก**

สองเหตุผล ทั้งคู่ตรวจจากโค้ดแล้ว:

1. **ไม่มีกลไกล้าง** — รอบจ่าย INTER-CO เครดิตบัญชีนี้เฉพาะสัญญาที่ `legacyNoShop = false`
   ซึ่งคำนวณ**ต่อสัญญา**จาก JE ที่ stamp `metadata.contractId` · JE ยอดยกมาใบเดียวที่ครอบ
   หลายสัญญา stamp แบบนั้นไม่ได้ ⇒ สัญญาเก่ายังคง `legacyNoShop = true` ⇒ `buildShopLines`
   ข้ามไม่สร้างบรรทัด SHOP ⇒ **ลูกหนี้ที่ตั้งไว้ไม่มีวันถูกล้าง**
2. **ทำตัวเลขกระทบยอดเพี้ยนถาวร** — `getReconcileTotals()` คำนวณ `glShopTotal` จาก
   `S11-3001`+`S11-3002` **ทั้งบัญชี ไม่กรอง metadata** แล้วแสดงคู่กับ `pendingTotal`
   ที่นับเฉพาะสัญญาที่มี `contractId` ⇒ สองตัวเลขห่างกันเท่ายอดยกมาตลอดไป
   (`interco-pending.service.ts:482-491`)

### 6.2 เจ้าหนี้ FINANCE (`S21-1104`) — **ตัดออก**

1. **ยังไม่ถึง prod** — branch `feat/cpa-answers-2026-08-24` **commit แล้ว** (`c29864278`,
   2026-08-24) แต่ **ยัง merge/deploy ไม่ได้** ⇒ ถ้ายังไม่ deploy การลง JE วันที่ 29 ส.ค.
   จะติด `รหัสบัญชีไม่ถูกต้องหรือไม่อยู่ในผังบัญชี` (`journal.service.ts:67`) ·
   ถ้าเลี่ยงไปใช้ `S21-3001` ก็เป็นยอดค้างในบัญชีที่กำลังจะเลิกใช้
   > ⚠️ **นี่เป็นเหตุผลเชิงจังหวะเวลา ไม่ใช่เชิงหลักการ — หมดไปเมื่อ deploy**
   > แต่เหตุผลข้อ 2 ด้านล่างยังยืนอยู่เสมอ ⇒ **ถึง deploy แล้วก็ยังตัดออกเหมือนเดิม**
2. **เลนส์อ่านต่อสัญญา** — `swapCreditShopBalance` / `recallShopBalance` query บัญชีนี้ด้วย
   `metadata.newContractId` / `metadata.contractId` และ `getTypedAccountDrift()` เทียบ
   ยอดทั้งบัญชีกับยอดที่เลนส์อธิบายได้ ⇒ ยอดยกมาที่ไม่มีเลขสัญญาจะกลายเป็น finding
   **`ACCOUNT_DRIFT`** พร้อม Todo `HIGH` ทุกเดือนตลอดไป โดยไม่มีเลขสัญญาให้ตามด้วย

### 6.3 ผลของการตัด — ต้องเขียนหมายเหตุประกอบงบ

ตัวปิด `S32-1101` จะดูดซับส่วนที่ตัดออกไป ⇒ **งบ SHOP จะแสดงส่วนของเจ้าของต่ำกว่าความจริง**
เท่ายอดลูกหนี้ FINANCE สุทธิ · ต้องกำกับในหมายเหตุว่า *"ยังไม่รับรู้ลูกหนี้/เจ้าหนี้ระหว่าง
กิจการ ณ วันยกมา — รอคำวินิจฉัยผู้สอบรอบ 2"*

นี่คือ **opening-balance gap เดียวกับ interco spec §11** ที่ผู้สอบตอบข้อ A2 ว่า *"ต้องตั้ง"*
แต่ยังไม่ได้ระบุวิธี (ลงเฉพาะงบดุลหรือรื้อ P&L · คู่บัญชี S32 หรือ S33 · ลงวันไหน)
⇒ **ยังลงมือไม่ได้ ห้ามเดา JE ปิดช่องนี้เอง**

## 7. ขั้นตอนลง JE + ด่านกันลงผิดสมุด

ใช้กลไกที่มีอยู่แล้ว (F7) ไม่ต้องเขียนโค้ดเพิ่ม:

```
1. สร้าง JE เป็นร่าง (POST /journal)        -> ยังไม่กระทบงบใดๆ
2. ตรวจสายตา: ทุกบรรทัดขึ้นต้นด้วย S        -> ระบบไม่ตรวจให้ (F5)
3. รัน SQL หมวด 3 ซ้ำ                        -> ต้องได้ 0 แถวทั้ง 3 ข้อ
4. กดลงบัญชี (POST /journal/:id/post)
5. รัน SQL หมวด 2.1 + 2.2 อีกครั้ง           -> ยอดแต่ละบัญชีตรงที่นับได้ + งบทดลองสมดุล
```

สิทธิ์: `OWNER` / `FINANCE_MANAGER` / `ACCOUNTANT` (`journal.controller.ts:36`)
