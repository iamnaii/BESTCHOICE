# เครื่องไทย / เครื่องนอกบนเว็บร้าน

พนักงานระบุประเภทเครื่องได้จากหน้ารายละเอียดสินค้าในหลังบ้าน ส่วนจัดการแสดงบนเว็บ เลือก “เครื่องไทย”, “เครื่องนอก” หรือ “ยังไม่ระบุ” แล้วกด “บันทึกประเภทเครื่อง” โดยใช้สิทธิ์แก้ไขข้อมูลขึ้นเว็บเดิม

ข้อมูล `deviceOrigin` หมายถึงตลาดที่จำหน่ายเครื่อง ไม่ใช่ประเทศที่ผลิต:

- `THAI`: เครื่องไทย
- `IMPORTED`: เครื่องนอก
- `null`: ยังไม่ได้ตรวจสอบ ข้อมูลเดิมทุกเครื่องเริ่มจากสถานะนี้ ไม่มีการเดาจากชื่อหรือ IMEI

หน้า `/products` มีตัวกรองทั้งคอมและมือถือ และแชร์ลิงก์ เช่น `/products?deviceOrigin=IMPORTED` ได้ สินค้าที่ยังไม่ระบุจะแสดงใน “ทั้งหมด” เท่านั้น การ์ดสินค้า หน้ารายละเอียด และตัวเลือกเครื่องแสดงประเภทเครื่องด้วย

เครื่องใหม่แยกกลุ่มตามรุ่น ความจุ หมวด และประเภทไทย/นอก ทั้งราคาเริ่มต้น จำนวนสต็อก และเครื่องที่ใช้เปิดหน้ารายละเอียดมาจากกลุ่มเดียวกัน หน้ารายละเอียดเลือกเครื่องทดแทนได้เฉพาะประเภทเดียวกับเครื่องที่เปิดดู รวมถึงกรณีเครื่องเดิมขายไปแล้ว

## การนำขึ้นระบบ

1. ใช้ขั้นตอน migration ปกติของโครงการเพื่อรัน `20261001000000_add_product_device_origin`, `20261001100000_add_product_warranty_terms`, `20261001200000_product_disclosure_snapshots` และ `20261001300000_pricing_device_origin` ก่อนนำ API ใหม่ขึ้นระบบ คำสั่งสำหรับฐานข้อมูลที่กำหนดไว้แล้วคือ `npx prisma migrate deploy --schema apps/api/prisma/schema.prisma` ซึ่งจะรัน migration ที่ค้างทั้งหมดด้วย
2. สร้าง Prisma client และนำ API หลังบ้าน และเว็บร้านเวอร์ชันใหม่ขึ้นระบบ
3. ตรวจสอบประเภทเครื่องจริง แล้วบันทึกผ่านหลังบ้าน เครื่องที่ยังไม่ระบุยังขายได้ในมุมมองทั้งหมด

การแก้โค้ดนี้ไม่ได้รัน migration บนฐานข้อมูลจริงหรือจัดประเภทสินค้าเดิมให้

## ประกันรายเครื่อง

ส่วนจัดการแสดงบนเว็บมีฟอร์ม “ประกันเครื่องนี้”:

- ระยะเวลาประกันร้าน ใช้ `shopWarrantyDays` เดิม: เว้นว่าง = ใช้ค่ามาตรฐานร้านสำหรับเครื่องมือสอง (`warranty.shopWarrantyDays`, ค่าเริ่มต้น 60 วัน), 0 = ไม่มีประกันร้าน, จำนวนเต็มบวก = จำนวนวัน ค่ารายเครื่องมีผลก่อนค่ามาตรฐานเสมอ เครื่องใหม่ที่ไม่ได้กำหนดประกันร้านไม่มีประกันร้านโดยอัตโนมัติ
- ผู้รับประกันและเงื่อนไขความคุ้มครอง ใช้ `warrantyTerms` ความยาวสูงสุด 2,000 ตัวอักษร รองรับข้อความหลายบรรทัด สำหรับแจ้งผู้รับประกัน ข้อยกเว้น และวิธีเคลม เว้นว่างเพื่อล้างข้อมูลได้

หน้าสินค้าแสดงประกันของเครื่องที่เลือก เมื่อเปลี่ยนเครื่อง ข้อมูลประกันเปลี่ยนตาม หากเครื่องหมดสต็อกจะแสดงข้อมูลของเครื่องในลิงก์ จำนวนวันใช้สูตรเดียวกับหลังบ้านและตอนขาย ส่วนเงื่อนไขที่ยังไม่ระบุให้สอบถามร้าน หน้าเครื่องใหม่ไม่แสดงคำรับรอง “ประกันศูนย์” แบบเหมารวม

ตามขอบเขตที่เจ้าของยืนยัน ไม่เพิ่มข้อมูลประเทศ/รหัสโมเดล ซิม/eSIM หรือสถานะล็อกเครือข่าย

## หลังบ้าน bestchoicephone.app

- กรอกไทย/นอกและประกันได้ตั้งแต่เพิ่มสินค้า รับเข้าจาก PO รับเข้าโดยตรง ยืนยันรับซื้อ/เทิร์น และรับซื้อด่วน
- สต็อก POS และตัวเลือกสินค้าเปิดสัญญามีตัวกรองไทย/นอก/ยังไม่ระบุ พร้อมแสดงประกันจริงของเครื่อง
- ตารางราคาขายแยกตามไทย/นอก/ยังไม่ระบุ ทั้งสร้าง ค้นหา และนำเข้า Excel (คอลัมน์ “เครื่องไทย/นอก”) ข้อมูลราคาเดิมอยู่กลุ่มยังไม่ระบุ ไม่เดาว่าเป็นเครื่องไทย และไม่ยืมราคาข้ามประเภทเมื่อหาเทมเพลตไม่เจอ
- ขายเงินสด ไฟแนนซ์ และเปิดสัญญาใหม่เก็บ `productDisclosure` ณ วันทำรายการ ประวัติขาย/Excel สัญญา และใบเสร็จที่อ้างอิงสัญญาอ่านจากข้อมูลนี้ แก้สินค้าในภายหลังไม่เปลี่ยนเงื่อนไขเดิม สัญญาเก่าไม่ถูกเติมข้อมูลย้อนหลังจากสินค้าปัจจุบัน
- ข้อความสรุปส่งลูกค้าจากหน้าสินค้าแสดงประเภทเครื่อง จำนวนวันประกันที่ใช้จริง และเงื่อนไข
- ป้ายราคาใช้ราคาขายที่บันทึกไว้กับเครื่องนั้น บอทค้นสินค้าแยกกลุ่มไทย/นอกและส่งประกันที่ใช้จริง พร้อมแยกข้อมูลราคาและสต็อกในการแนะนำเครื่อง

## ราคากลางรับซื้อ AppleHouse

ใช้แหล่ง `https://applehouseth.com/` และเครื่องมือประเมินสาธารณะ `https://sure.applehouseth.com/` แทน Yellobe สำหรับฐานราคารับซื้อเกรด A ไม่เปลี่ยนราคาขายเงินสดหรือผ่อนของร้านเป็นราคารับซื้อ

ไฟล์ `apps/api/prisma/data/applehouse-valuations.json` เก็บ 51 คู่รุ่น/ความจุ ณ 21 กันยายน 2026 พร้อมเวลาที่ดึง ราคาแยกก่อนโปรโมชัน และโปรโมชัน เงื่อนไขอ้างอิงคือเครื่องไทย แบต 80–100% มีกล่อง ประกันเหลืออย่างน้อย 4 เดือน ไม่มีรอยและตำหนิ ราคาที่นำเข้าใช้ `finalPrice` รวมโปรโมชันตามที่แหล่งแสดง ณ เวลานั้น

เครื่องนอกและสภาพต่างจากฐานใช้ค่าหักที่ร้านกำหนดในแบบประเมินเดิม ไม่ได้อ้างว่าราคาสุทธิหลังหักตรงกับ AppleHouse ทุกกรณี รุ่น/ความจุที่แหล่งไม่มีราคาไม่สร้างตัวเลขขึ้นเอง

คำสั่งจากรากโครงการ:

```sh
# ดึง snapshot ใหม่ (ติดตั้ง Playwright Chromium ไว้ก่อน)
node scripts/collect-applehouse-valuations.cjs
# ตรวจไฟล์โดยไม่เชื่อมต่อฐานข้อมูล
npx tsx apps/api/prisma/seed-sell-valuations-applehouse.ts --validate-only
# ดูแผนเปลี่ยนราคาบน DATABASE_URL ที่ตั้งไว้ (ไม่เขียน)
npx tsx apps/api/prisma/seed-sell-valuations-applehouse.ts
# นำราคาที่ตรวจแล้วเข้าฐานข้อมูลเป้าหมาย
npx tsx apps/api/prisma/seed-sell-valuations-applehouse.ts --apply
```

ตัวนำเข้าปรับราคาแถวเกรด A ที่ตรงรุ่น/ความจุและหมายเหตุแหล่งที่มาใน transaction เดียว ข้ามแถวที่ถูกลบ ไม่คืนชีพ และถอนราคาเก่าจากแหล่งที่ดูแลโดยสคริปต์เมื่อไม่มีรุ่นนั้นใน snapshot ใหม่ แถวที่ร้านสร้างเองซึ่งไม่ตรงกับแหล่งยังคงเดิม สคริปต์ชื่อ Yellobe เดิมส่งต่อมาที่ตัวใหม่และเป็น preview โดยค่าเริ่มต้น

ก่อนเปลี่ยนแหล่ง สคริปต์ตรวจว่าร้านมีแบบตรวจสภาพที่ใช้งานได้ แล้วปิดโปรไฟล์อ้างอิง Yellobe ใน transaction เดียวกับการเปลี่ยนราคา โดยเก็บข้อมูลเดิมไว้ตรวจสอบย้อนหลัง ผลประเมินที่บันทึกไปแล้วไม่ถูกคำนวณใหม่

การแก้ครั้งนี้เตรียมโค้ดและข้อมูลแล้ว ยังไม่ได้รัน migration หรือนำราคาเข้าฐานข้อมูล production
