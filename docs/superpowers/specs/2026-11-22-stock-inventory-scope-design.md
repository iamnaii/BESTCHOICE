# ภาพรวมคลังแยกเครื่องและอุปกรณ์เสริม

สถานะ: เจ้าของอนุมัติแนวทางในแชท 22 พ.ย. 2569 (“ok วางแผนทำได้เลย”) เอกสารนี้บันทึกแนวทางนั้นและรายละเอียดที่ผู้พัฒนากำหนดสำหรับจัดทำแผน ยังไม่ได้แก้แอปหรือ deploy

## เป้าหมาย

ให้เจ้าของร้านเห็นจำนวนเครื่อง เงินทุน และอายุเครื่องที่พร้อมขายได้ทันที โดยแยกอุปกรณ์เสริม/ของแถมออกจากมุมมองเริ่มต้น และยังเปิดดูอุปกรณ์หรือยอดรวมได้ ทุกยอดและรายการปลายทางต้องใช้ขอบเขตเดียวกัน

## แนวทางที่พิจารณา

1. ตัดอุปกรณ์ออกเฉพาะการ์ดพร้อมขาย: แก้น้อย แต่จำนวนในกราฟ สาขา และรายการค้างยังไม่ตรงกัน
2. **ตัวเลือกทั้งหน้า `เครื่อง | อุปกรณ์เสริม | ทั้งหมด` ค่าเริ่มต้นเครื่อง**: แนวทางที่เสนอและเจ้าของตอบรับ เห็นธุรกิจหลักชัด และยังบริหารของแถมได้
3. แยกเป็นสองหน้า: เพิ่มการนำทางและบำรุงรักษาหน้าซ้ำ ยังไม่จำเป็นสำหรับงานนี้

## ข้อมูลอ้างอิง ณ หลังย้าย 22 พ.ย. 2569

เป็น baseline สำหรับตรวจรับ ไม่ใช่ค่าที่ hardcode และอายุจะเพิ่มตามเวลา

| ขอบเขต | ทั้งหมด | พร้อมขาย | รอตรวจรับ | ทุนพร้อมขาย | อายุเฉลี่ยพร้อมขาย | เกิน 90 วัน |
|---|---:|---:|---:|---:|---:|---:|
| เครื่อง | 43 | 40 | 3 | 707,187 บาท | 12 วัน | 2 |
| อุปกรณ์เสริม | 609 | 608 | 1 | 29,755 บาท | 68 วัน | 84 |
| ทั้งหมด | 652 | 648 | 4 | 736,942 บาท | 65 วัน | 86 |

เครื่อง = `PHONE_NEW`, `PHONE_USED`, `TABLET`; อุปกรณ์เสริม = `ACCESSORY` รวม Apple Pencil และของแถมราคา 0 บาท ใช้ category จริง ไม่เดาจากราคา ชื่อ หรือการมี IMEI

## หน้าจอและการใช้งาน

คงหน้า `/stock` สีเขียว ฟอนต์ การ์ด และ design tokens เดิม เพิ่มตัวเลือกใต้หัวข้อก่อน KPI เป็นกลุ่มปุ่มเลือกได้หนึ่งค่า พร้อมข้อความอธิบายเมื่อเลือกเครื่องว่า “มือถือและแท็บเล็ต ไม่รวมอุปกรณ์เสริม”

```text
ภาพรวมคลัง                         รายการสินค้า · พิมพ์สติกเกอร์ · เพิ่มสินค้า
แสดงสินค้า  [เครื่อง ✓] [อุปกรณ์เสริม] [ทั้งหมด]
มือถือและแท็บเล็ต ไม่รวมอุปกรณ์เสริม

เครื่องพร้อมขาย    ขายเดือนนี้                  อายุเครื่องเฉลี่ย    Margin เดิม*
40 เครื่อง        164 เครื่อง                  12 วัน              ...
ต้นทุน 707,187 ฿   รวมประวัติ Tooltify · ดูที่มาของยอด

งานที่ต้องทำ: ค้างเกิน 90 วัน 2 เครื่อง · รอตรวจรับ 3 เครื่อง
สาขา: ลพบุรี พร้อมขาย 40 / ทั้งหมด 43 เครื่อง
กราฟอายุ · มูลค่าตามสถานะ · ประเภท/ยี่ห้อ/สี/ความจุ · การเคลื่อนไหว
```

`*` รักษาชื่อ/สูตร margin เดิมในงานนี้ ไม่เปลี่ยนสูตรบัญชีหรือถือว่ากำไรคาดการณ์รวมต้นทุนของแถมแล้ว

- หน่วยเป็น “เครื่อง” ในมุมมองเครื่อง และ “ชิ้น” ในอีกสองมุมมอง; ใช้ “ต้นทุนพร้อมขาย” ให้ชัดว่าไม่ใช่มูลค่าตามราคาขาย
- ตัวเลือกเป็น Radix ToggleGroup แบบ single ที่มีข้อความและ pressed state ไม่ใช้สีอย่างเดียว; ห้ามปล่อยให้ไม่มีค่าที่เลือก
- ความสูงเป้าหมายกดอย่างน้อย 44 CSS px, focus ring ชัดเจน, keyboard roving focus ตาม primitive เดิม, ข้อความทั่วไปอย่างน้อย 14 px, contrast ปกติอย่างน้อย 4.5:1
- บนจอ 375 px ตัวเลือกต้องไม่ล้นแนวนอน; ปุ่มหัวหน้า wrap ได้; ใช้ชุดสี/spacing เดิม ไม่เพิ่ม dependency หรือ animation library
- ระหว่างโหลดขอบเขตใหม่ให้ skeleton/สถานะโหลดเฉพาะส่วน อย่านำยอดขอบเขตเก่ามาแสดงใต้ชื่อขอบเขตใหม่; error มี retry ไม่แทนด้วยศูนย์
- รายการว่างแสดง “ไม่มีสินค้าพร้อมขายในกลุ่มนี้”; อายุและ margin ที่ไม่มีฐานข้อมูลแสดง “—” ไม่กล่าวว่าหมุนเวียนดีหรือกำไร 0%

## ขอบเขตข้อมูลและ URL

- Query ชื่อ `inventoryScope=devices|accessories|all` แยกจาก `view=ready|all` ซึ่งเป็นตัวกรองสถานะเดิม
- `/stock` เมื่อไม่มี scope เปิด `devices`; ไม่เก็บค่าซ้ำใน localStorage หรือ React state
- API และ `/stock/products` ที่ไม่มี scope ยังคง `all` เพื่อรักษาพฤติกรรม POS/ผู้เรียกเดิมและทางเข้ารายการสินค้าโดยตรง
- ลิงก์จากภาพรวมใส่ scope ชัดเจน เก็บ branch และ zone; Back/Forward/Refresh ต้องคืน scope เดิม
- สลับ scope ในรายการสินค้าให้ reset หน้าและการเลือก bulk; ล้าง category/accessoryGroupId ที่ขัดกับ scope อย่างมองเห็นได้ และจำกัดตัวเลือก category ให้ตรง scope
- API ปฏิเสธ scope ไม่รู้จักและรูปแบบ array/object ด้วย 400; URL หน้าเว็บที่ scope ไม่ถูกต้องใช้ค่าเริ่มต้นของหน้านั้นและ normalize URL
- การกรองทำที่ server ก่อน aggregate, grouping, pagination และ sort ไม่กรองเฉพาะรายการหน้าแรกใน browser
- จำนวน dashboard เป็น **หน่วยจริง**; ตารางอุปกรณ์รวมเป็นแถวรุ่นได้ แต่ต้องระบุทั้งจำนวนชิ้นและจำนวนแถว/รุ่นให้ต่างกัน

## ส่วนที่ต้องตาม scope

1. KPI พร้อมขาย/ต้นทุน อายุเฉลี่ย ยอดขายเดือนนี้และเดือนก่อน และ margin เดิม
2. สรุปทุกสาขา, aging buckets, status values, category/brand/color/storage, slow movers, top sellers, movement
3. งาน inspection, QC_PENDING, PHOTO_PENDING, repossession, pending transfers และ warranty expiring โดย warranty ต้องตาม branch ด้วย
4. รายการสินค้าปลายทางและยอดหน่วยในตาราง; รายการโอน PENDING ที่เปิดจากการ์ดต้องตาม scope และสาขาปลายทางเดียวกัน

QC_PENDING ต้องมีการ์ด “รอตรวจรับ” แยกจาก INSPECTION; ของแถมราคา 0 ยังเป็น IN_STOCK และไม่ถูกเปลี่ยนสถานะ

คลิกค้างเกิน 90 วันใช้ `view=ready&aging=over90`; เวลาอ้างอิง `stockInDate ?? createdAt` และ floor จำนวนวัน >90 เหมือนสูตร dashboard ปัจจุบัน คลิกสถานะอื่นใช้ `view=all&status=...` เพื่อไม่ให้ ready view กลบตัวกรอง

หน้ารายการโอนรับบริบท scope/branch เฉพาะการเปิด PENDING จากภาพรวม แสดงบริบทและปุ่มล้างชัดเจน หากเปลี่ยนไปมุมมองอื่นให้ล้างบริบทนี้อย่างชัดเจน งานนี้ไม่เปลี่ยน workflow ยืนยัน/รับ/ส่งสินค้า

## ความหมายยอดขาย

เจ้าของแก้ข้อกำหนดหลังดู mockup วันที่ 22 พ.ย. 2569: **รวมประวัติที่นำเข้าในยอดขายด้วย** ใช้ “ขายเดือนนี้” พร้อม “รวม Tooltify · ดูที่มาของยอด” โดยรวมเหตุการณ์ขายจริงของ BESTCHOICE กับ ImportedSale ตามวันขายเดิม (`soldAt`) ในเขตเวลา Asia/Bangkok ไม่ใช้วันที่นำเข้า และไม่สร้างรายการขาย เงินรับ หรือตัดสต๊อกใหม่

- อุปกรณ์ใช้ชื่อ “จ่ายอุปกรณ์เดือนนี้”; ทั้งหมดใช้ “ขาย / จ่ายเดือนนี้” แสดงจำนวนของแถมแยกจากเครื่องและไม่เรียกยอดของแถม 0 บาทว่ารายได้
- ตัวอย่างที่อ่านจริง ณ 22 พ.ย.: พฤศจิกายน เครื่อง 164 / ยอดขาย 3,275,269 บาท, อุปกรณ์ 369 ชิ้นเป็นของแถมทั้งหมด / ยอดขาย 0 บาท, รวม 533 หน่วย ยอดขาย 3,275,269 บาท; native sold-product count ปัจจุบัน 0 ใช้ประกอบ mockup เท่านั้น
- ตุลาคมสำหรับฐานเดือนก่อน: เครื่อง 299, อุปกรณ์ 631, รวม 930 หน่วย; อย่าเทียบเดือนพฤศจิกายนที่ยังไม่จบกับเดือนเต็มโดยไม่ระบุช่วงเวลา
- นับแต่ละเหตุการณ์ขายและจำนวนหน่วย ไม่ deduplicate ด้วย IMEI เพราะเครื่องเดิมขายได้หลายรอบ; กันซ้ำข้ามแหล่งด้วย provenance / source event identity ที่ตรวจยืนยันได้ ไม่ใช่การเทียบ IMEI เพียงอย่างเดียว
- หมวดนำเข้าเป็นข้อความต่างจาก Product enum: map หมวด iPhone มือ 1/มือ 2/มือ 2 (เครื่องนอก)/iPad มือ 1 ไป devices และ Accessories ไป accessories; หมวดไม่ทราบรวมใน all พร้อมแสดง “ไม่ระบุหมวด” ห้ามเดาเป็นเครื่อง (มีหมวด `-` ย้อนหลัง 13 รายการ แต่ไม่อยู่ใน ต.ค.–พ.ย.)
- ImportedSale ไม่มี branchId/companyId: ต้องใช้ provenance ของ batch และ branch ที่ยืนยันในการย้าย พร้อม permission boundary เดิม; รายการที่ระบุสาขาไม่ได้ต้องแยกให้เห็น ไม่กระจายซ้ำทุกสาขาหรืออนุมานจากสินค้าคงเหลือปัจจุบัน
- เดือนก่อน ขายดี และฝั่งขายของกราฟต้องใช้ชุดเหตุการณ์เดียวกัน; ประวัติขายไม่ใช่ประวัติรับเข้า ห้ามสร้างตัวเลขรับเข้าย้อนหลังจาก ImportedSale
- เปิดรายละเอียดที่มาของยอด แยก BESTCHOICE / Tooltify / ของแถม และช่วงวันที่; การกรอง scope กับสาขาต้องเหมือนการ์ดหลัก ไม่เผยประวัติที่ผู้ใช้ไม่มีสิทธิ์

## ข้อจำกัด

- ใช้ React 19 / React Router / TanStack Query / Radix / Tailwind ตาม package ปัจจุบัน; NestJS / Prisma / PostgreSQL เดิม
- ไม่เปลี่ยนข้อมูลนำเข้า หมวดสินค้า ราคา IMEI จำนวนของแถม บัญชี หรือสิทธิ์บริษัท/สาขา; ไม่ต้องมี migration
- ต้องส่งตัวกรองผ่าน `access-shop-boundaries.ts` ด้วย ไม่เพียง controller เพราะเป็นทางเรียกจริงของระบบสิทธิ์ใหม่
- รักษา `domainAccessClient`, `currentProductScopeSql` และการซ่อนต้นทุนจากผู้ไม่มีสิทธิ์ทั้ง response และ UI
- ใช้ชุดข้อมูลสังเคราะห์ใน PostgreSQL test harness เท่านั้น; ข้อมูลจริงใช้ตรวจอ่านอย่างเดียวหลัง deploy ที่ได้รับอนุญาต
- ส่งมอบโค้ดพร้อม local preview ที่ผ่าน `npm run local:check` และการทดสอบหน้า stock เพิ่มเติม; ไม่ deploy/merge อัตโนมัติ

## UI/UX guidance ที่ตรวจแล้ว

ใช้ ui-ux-pro-max ค้น `filter selection keyboard focus` (ux → Focus States) และ `derived state single source` (react → Avoid unnecessary effects/state) ซึ่งตรงกับตัวเลือกขอบเขตนี้ เก็บ URL เป็นแหล่งเดียวของ filter และ reuse primitive เดิม อ่าน quick-reference เรื่อง focus/loading/responsive ประกอบ ไม่สร้าง design system ใหม่สำหรับการเปลี่ยนเฉพาะหน้านี้

## เกณฑ์ยอมรับ

เมื่อทดสอบด้วย fixture ที่ตรึงเวลาและแทนข้อมูล baseline: เครื่องพร้อมขาย 40, อายุ 12, ค้าง >90 เท่ากับ 2; สลับทั้งหมดกลับเป็น 648/65/86; แยก QC 3 เครื่องและ 1 อุปกรณ์; ทุกลิงก์และยอดหน่วยตรง scope; รวมอุปกรณ์เป็นแถวไม่ทำให้หน่วย 608 หาย; ไม่มีต้นทุนรั่วหรือการเขียนฐานข้อมูลจากการดู/เปลี่ยน filter
