# แบบทดลองใช้ BESTCHOICE สำหรับพนักงานใหม่

ใช้กับพนักงานใหม่หรือผู้ที่ยังไม่เคยใช้ระบบ 3–5 คน ในข้อมูลทดสอบเท่านั้น ยังไม่มีผลจากคนจริงในเอกสารนี้

## วิธีดำเนินการ

ผู้สังเกตเตรียมบัญชี SALES สาขาทดสอบ ลูกค้าที่ยังไม่มีเครดิต สินค้าพร้อมขาย และห้องแชทที่มอบหมายให้พนักงาน ควรใช้สถานการณ์สองชุดที่มีความยากใกล้กันเพื่อเทียบรุ่นเดิมกับรุ่นใหม่ โดยสลับลำดับผู้ทดลอง ไม่บอกชื่อเมนูหรือตำแหน่งปุ่มระหว่างทำงาน

| งานที่ให้ลอง | ผลที่ควรเห็น |
| --- | --- |
| เริ่มขายสินค้า 1 เครื่องจากหน้าแรก | หา “ขายสินค้า” ได้เอง |
| หางานของตนที่ต้องทำวันนี้ | เข้า “งานที่ต้องทำต่อ” และคงตัวกรองของตน |
| เตรียมตัวเลือกมือถือจากงบที่ลูกค้าแจ้งในแชท | เห็นรุ่น งบที่ใช้ สต็อก ราคา ค่างวด และข้อความอ้างอิง |
| นำข้อเสนอไปตอบลูกค้า | เข้าใจว่า “แทรกร่างในช่องพิมพ์” ยังไม่ได้ส่งข้อความ และตรวจร่างก่อนส่ง |
| ไปตรวจเครดิตจากร่างสัญญา แล้วกลับมาทำต่อ | ลูกค้า สินค้า เงินดาวน์ และจำนวนงวดเดิมอยู่ครบ |
| ลองทำสัญญาให้ลูกค้าที่ยังไม่ผ่านเครดิต | รู้ว่าต้องให้ผู้มีสิทธิ์ตรวจ/อนุมัติก่อน และ AI ไม่ใช่ผลอนุมัติ |

หยุดก่อนส่งข้อความจริง บันทึกขาย รับชำระ หรืออนุมัติรายการจริง ผู้จัดการใช้ข้อมูลสังเคราะห์ประกอบการทดลองอนุมัติในระบบทดสอบได้

## แบบบันทึกผล

ใช้รหัสผู้ทดลองแทนชื่อและไม่บันทึกข้อมูลส่วนตัวลูกค้า

| ผู้ทดลอง | รุ่น/ลำดับ | งาน | เวลาเริ่มถูก (วินาที) | เวลาจบ (วินาที) | จำนวนครั้งที่ถาม | จำนวนครั้งที่ย้อนกลับ | สำเร็จ/ไม่สำเร็จ | จุดที่สับสน |
| --- | --- | --- | ---: | ---: | ---: | ---: | --- | --- |
| | | | | | | | | |

หลังแต่ละงานถามสั้น ๆ ว่า “ตอนนี้เกิดอะไรขึ้นแล้ว และต้องทำอะไรต่อ” โดยเฉพาะหลังแทรกร่าง AI และหลังอ่านผลเครดิต

## เกณฑ์รับผล

- หาเส้นทางเริ่มงานและทำต่อได้โดยไม่ต้องบอกชื่อเมนู
- แยกร่าง AI ออกจากข้อความที่ส่งและรายการที่บันทึกแล้วได้
- เข้าใจเหตุผลที่ยังทำสัญญาไม่ได้และรู้ว่าต้องติดต่อใคร
- ข้อมูลไม่หายเมื่อไปตรวจเครดิตแล้วกลับมา
- ผู้ใช้เดิมยังใช้เมนูและกระบวนการเดิมได้

หากมีคนส่งร่างโดยเข้าใจผิดว่าเป็นผลอนุมัติ ให้แก้คำอธิบายและทดลองซ้ำก่อนขยายใช้ กลุ่มเล็กนี้ใช้ค้นหาปัญหา ไม่ใช่หลักฐานเชิงสถิติว่าทุกคนจะใช้งานง่ายหรือเร็วขึ้น
