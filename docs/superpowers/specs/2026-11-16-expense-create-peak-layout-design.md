# หน้าสร้างเอกสารค่าใช้จ่าย — โครงหน้าแบบ PEAK (2026-11-16)

สถานะ: รอบที่ 1 อยู่ใน PR #1781 · รอบที่ 2 เขียนโค้ดแล้วบน feat/expense-create-peak-layout-round2

## 1. เป้าหมาย

เปลี่ยนหน้าตาของหน้าสร้างเอกสารใน "ค่าใช้จ่ายดำเนินงาน" ทั้ง 6 ประเภท ให้มีโครงหน้าแบบหน้า
"บันทึกค่าใช้จ่าย" ของ PEAK (`secure.peakaccount.com/expense/invoiceCreate`) โดยใช้สีและ token ของ BESTCHOICE

**เปลี่ยนแค่หน้าตา:** logic, การคำนวณ, API และ payload ที่ส่งไป server ต้องเหมือนเดิมทุกฟิลด์
ไม่มีการแก้ `apps/api`

## 3. โครงหน้า PEAK ที่ใช้อ้างอิง (ดูจากหน้าจริง 2026-11-16)

- หน้าเต็ม ไม่ใช่ modal · การ์ดใหญ่ใบเดียว
- หัวการ์ด: ชื่อเอกสารพร้อมลูกศรสลับประเภท · มุมขวาบน: เลขที่ใบกำกับภาษี + เลขที่เอกสาร
- แต่ละส่วนเป็นแถว: ป้ายชื่ออยู่คอลัมน์ซ้าย (มีเครื่องหมายถูกเมื่อกรอกครบ) ช่องกรอกอยู่ขวา คั่นด้วยเส้นบาง
- รายการเป็นตารางเดียว: บัญชี (มีแถวคำอธิบายใต้บัญชี) / จำนวน / ราคาต่อหน่วย / ส่วนลด / ภาษี / มูลค่า / หัก ณ ที่จ่าย · ปุ่ม "+ เพิ่มรายการใหม่" ใต้ตาราง
- สรุปข้อมูล: ตัวเลขย่อยทางซ้าย + กล่องสีเข้ม "จำนวนเงินทั้งสิ้น" ทางขวา
- ชำระเงิน: สวิตช์ พื้นฐาน/ขั้นสูง + ลิงก์ "ยังไม่ชำระเงิน (ตั้งหนี้ไว้ก่อน)" ที่ย่อส่วนนี้เหลือบรรทัดเดียว พร้อมลิงก์ "เพิ่มข้อมูลชำระเงิน"
- แถบติดล่างจอ: ชื่อเอกสารทางซ้าย · ยกเลิก / บันทึกร่าง / อนุมัติ ทางขวา

ของ PEAK ที่**ไม่ทำ** เพราะเราไม่มีฟีเจอร์นั้น: แนบไฟล์, วันครบกำหนด, วันที่ชำระแยก, ลากสลับแถว,
สร้างเอกสารจากไฟล์ด้วย AI, หลายช่องทางชำระ, ตัดชำระกับเอกสาร

## 5. หน้าตาแต่ละประเภท

กติการ่วม:

- แถวที่เป็นช่องกรอกใช้ `FormRow layout="side"` · แถวที่เป็นตารางใช้ `layout="stacked"`
- ช่องในตารางทุกช่องมี `aria-label` ของตัวเอง (`จำนวน`, `ราคา/หน่วย`, `ส่วนลด`, `VAT%`, `WHT%`, `บัญชีค่าใช้จ่าย`, `คำอธิบาย`) และปุ่มลบมี `aria-label="ลบรายการ"` — หัวคอลัมน์ไม่ใช่ป้ายของช่อง
- กล่องสรุปแสดงเฉพาะตัวเลขที่ส่วนนั้นคำนวณอยู่แล้ว ไม่มีสูตรใหม่
- แถวท้ายทุกประเภท: "ตัวอย่างรายการบัญชี" (เฉพาะ EX · ย่อไว้ · หัวแถวบอกสมดุลหรือไม่) และ "ผู้บันทึก & ผู้อนุมัติ"
- ปุ่ม "ใช้แม่แบบ" อยู่เหนือการ์ด เปิด `QuickStartPanel` เดิม (แสดงเมื่อเปิดหน้าครั้งแรกเหมือนวันนี้)

### 5.1 บันทึกค่าใช้จ่าย (EXPENSE_SAMEDAY + EXPENSE_ACCRUAL)

| ราคาและภาษี | ประเภทราคา · ช่องติ๊กค่าใช้จ่ายต้องห้าม (ม.65 ตรี) + คำอธิบายเดิม |
| รายการ | ตารางสัดส่วนเท่าหน้า PEAK (เจ้าของสั่ง 2026-11-16): แถวบน # / บัญชีค่าใช้จ่าย / จำนวน / ราคาต่อหน่วย / ส่วนลด / VAT% / จำนวนเงิน / WHT% / ลบ · แถวล่าง คำอธิบาย (ใต้บัญชี กว้างเท่ากัน) + ช่องติ๊กต้องห้ามรายบรรทัด (ในพื้นที่ว่างใต้ตัวเลข) · ความกว้าง: # 24 · จำนวน 76 · ราคา 96 · ส่วนลด 96 · VAT% 64 · จำนวนเงิน 96 · WHT% 76 · ลบ 44 · บัญชี = ที่เหลือ (360px บนการ์ด 924px เท่าความกว้างของ PEAK — PEAK 368px) · เมนูรายการบัญชีกว้างเท่าช่อง · ปุ่ม "เพิ่มบัญชี" |

| ชำระเงิน | ข้อ 6 |

(เท่ากับกดชิป "จ่ายทันที" วันนี้)

### 5.2 จ่ายชำระเจ้าหนี้ (VENDOR_SETTLEMENT)

ข้อมูลผู้รับเงิน (ผู้รับเงิน + หัก ณ ที่จ่าย: ประเภท + ยอด — คงที่เดิมใน `SettlementLinesSection`) →
ตารางเอกสารตั้งหนี้ที่จะล้าง → `SummaryBox` (รวมยอดที่จ่าย · หัก ณ ที่จ่าย · ยอดเด่น "ตัดเงินสดสุทธิ") → ชำระเงิน

### 5.3 ใบลดหนี้ (CREDIT_NOTE)

ข้อมูลผู้ขาย + ราคาและภาษี (`VendorSection` ชุดเดียวกับ EX — แสดงทั้งสองโหมดเหมือนวันนี้) →
อ้างอิงเอกสาร (โหมด · เอกสารต้นฉบับ · ยอดเดิม/ใช้ไป/คงเหลือ · ชื่อผู้ขาย/เลขผู้เสียภาษีของโหมดไม่อ้างอิง · เหตุผล\*) →
ตารางรายการ (`ItemLinesSection` ตัวเดียวกับ EX) → ข้อความเตือนเกินเพดาน →
**แถว "รับเงินคืนเข้า"** (โหมดอ้างอิง และเอกสารต้นฉบับที่เลือกเป็น `POSTED` คือจ่ายแล้ว): `CashAccountSelect` ผูกกับ `state.depositAccountCode`
— เอกสารต้นฉบับที่ยังตั้งหนี้ (`ACCRUAL`) server ลดเจ้าหนี้ (`Dr 21-1104`) ไม่ใช้บัญชีเงิน จึงไม่แสดงแถวนี้
ข้อจำกัดที่รู้ (เจ้าของคงคำตัดสินนี้ 2026-11-16): ถ้าต้นฉบับยังตั้งหนี้ตอนบันทึกร่าง แต่ถูกจ่ายก่อนลงบัญชีใบลดหนี้ server จะรับเงินคืนเข้าบัญชีเงินค่าเริ่มต้นที่ฟอร์มส่งไป (พฤติกรรมเดิมก่อนรอบ 2)

แถว "รับเงินคืนเข้า" (เมื่อต้นฉบับจ่ายแล้ว) เปิดให้เห็นค่าที่ฟอร์มส่งอยู่แล้ววันนี้ (`depositAccountCode` ของ payload ใบลดหนี้โหมดอ้างอิง)
ซึ่งปัจจุบันไม่มีช่องให้เห็นหรือเลือก ไม่ได้เพิ่มฟิลด์ใน payload

### 5.4 เงินสดย่อย (PETTY_CASH_REIMBURSEMENT)

ผู้ดูแลเงินสดย่อย — ไม่บังคับ (แถวของตัวเอง) → ตารางรายการสัดส่วนเดียวกับรายจ่าย: แถวบน # / ผู้ขาย / หมวดบัญชี / จำนวน / VAT % / รวม / ลบ ·
แถวล่าง เลขใบกำกับฯ + รายละเอียด · ความกว้าง # 24 · ผู้ขาย 208 · จำนวน 112 · VAT % 80 · รวม 96 · ลบ 44 · หมวดบัญชี = ที่เหลือ (มีแถวรวมท้ายตาราง) →
`SummaryBox` (มูลค่าก่อนภาษี · ภาษีมูลค่าเพิ่ม · ยอดเด่น "จำนวนเงินทั้งสิ้น" — คำเดียวกับรายจ่าย) → ชำระเงิน (เลือกบัญชีอย่างเดียว)

### 5.5 เงินเดือน (PAYROLL)

`PayrollLinesSection` ทั้งตัวใน `FormRow layout="stacked"` → ชำระเงิน (เลือกบัญชี + หมายเหตุ SHOP/FINANCE เดิม)
ไม่มี `SummaryBox` (ตารางมีแถวรวมอยู่แล้ว)

โหมดแก้ไข (`?edit=`): ช่องเลขที่เอกสารแสดงเลขจริงของใบ · เมนูสลับประเภทถูกล็อก ·
แบนเนอร์ "ใบนี้รออนุมัติ/อนุมัติแล้ว…" อยู่บนสุดของการ์ด · สถานะกำลังโหลด/โหลดไม่สำเร็จแสดงในหน้า

### 5.6 หัวการ์ด

- ป้ายสถานะ: "ร่าง" หรือสถานะของใบที่โหลดมา (เหมือนเดิม)
- เลขที่เอกสาร: เอกสารใหม่แสดง "ออกเลขเมื่อบันทึก" (server ออกเลข) · โหมดแก้ไขแสดงเลขของใบ
- เลขที่ใบกำกับ: แสดงเฉพาะประเภทที่มีช่องนี้วันนี้ (EX และใบลดหนี้)
- ชื่อสาขา: อ่านอย่างเดียว

| จ่ายเจ้าหนี้ | ไม่มี | เลือกบัญชี | + ยอดจ่ายจริง + รายการปรับปรุง |
| เงินเดือน, เงินสดย่อย | ไม่มี | เลือกบัญชี | ไม่มีสวิตช์ |
| ใบลดหนี้ | — | ไม่มีส่วนนี้ (ดูแถว "รับเงินคืนเข้า" ข้อ 5.3) | — |

กติกาของ EX:

1. กด "ยังไม่ชำระเงิน (ตั้งหนี้ไว้ก่อน)" = `patch({ docType: 'EXPENSE_ACCRUAL' })` · ส่วนนี้ย่อเหลือบรรทัดเดียว
   "ยังไม่ชำระเงิน — ตั้งหนี้ไว้ก่อน" พร้อมลิงก์ "เพิ่มข้อมูลชำระเงิน" = `patch({ docType: 'EXPENSE_SAMEDAY' })`
2. effect สลับเป็นตั้งหนี้อัตโนมัติเมื่อวันที่ใบกำกับย้อนหลังยังทำงานเหมือนเดิม · เมื่อสลับให้แสดงบรรทัด
   "วันที่ใบกำกับไม่ใช่วันนี้ — เอกสารนี้ตั้งหนี้ไว้ก่อน" ใต้บรรทัดสถานะ (แสดงเมื่อ flag `smartDoctypeSwitchEnabled` เปิด
   และเอกสารเป็นตั้งหนี้โดยวันที่ย้อนหลังเกินเกณฑ์ — คิดจากสถานะปัจจุบัน ไม่ได้ติดตามว่าระบบเป็นผู้สลับ)
3. โหมด "ขั้นสูง" เปิดเองเมื่อ `state.adjustments.length > 0` หรือ `state.amountPaid` ไม่ว่าง ·
   ขณะมีข้อมูลสองอย่างนี้ สลับกลับ "พื้นฐาน" ไม่ได้ ต้องกด "ล้างรายการปรับปรุง" (ล้างทั้ง `adjustments` และ `amountPaid`) ก่อน · ล้างแล้วยังอยู่ที่ "ขั้นสูง" จนกว่าผู้ใช้จะกด "พื้นฐาน" เอง
4. อยู่ที่ "ยังไม่ชำระเงิน" แต่ยังมีรายการปรับปรุงหรือยอดจ่ายจริงค้าง: แสดงบรรทัดเตือน
   "มีรายการปรับปรุงที่กรอกไว้ ซึ่งจะถูกบันทึกไปด้วย" พร้อมปุ่ม "ล้างรายการปรับปรุง"
5. ไม่มีแถบ "ที่ต้องจ่าย · จ่ายจริง · ผลต่าง" (ของเดิมแสดงผลต่าง 0.00 ตายตัว) — ผลต่างจริงอยู่ใน `AdjustmentSection`

สถานะ พื้นฐาน/ขั้นสูง เป็น state ของ `PaymentSection` เอง ไม่เข้า `ExpenseFormState` และไม่มีผลกับ payload

## 7. พฤติกรรมที่เปลี่ยน (นอกจากหน้าตา)

รายการนี้คือทั้งหมด ถ้าพบข้ออื่นระหว่างทำต้องหยุดถามเจ้าของ

### 7.1 สาขาของเอกสาร

- ลำดับ: `?branch=` (ถ้าอยู่ในรายการ `GET /branches` ที่ผู้ใช้เห็น) → `user.branchId` → สาขาแรกของรายการ
- ทุกปุ่มในเมนู "สร้างเอกสารใหม่" ของหน้ารายการส่ง `?branch=<ตัวกรองสาขา>` เมื่อมีตัวกรอง
- ผล: EX ได้สาขาเดียวกับ modal เดิม (ตัวกรองสาขา → สาขาแรก) เมื่อมีตัวกรอง ·
  ใบลดหนี้/เงินเดือน/จ่ายเจ้าหนี้ ที่เดิมไม่สนตัวกรอง จะใช้สาขาตามตัวกรองด้วย
- กรณีที่ต่างจากเดิม: EX ที่เปิดโดยไม่มีตัวกรองสาขา ผู้ใช้ที่มีสาขาประจำจะได้สาขาประจำ (เดิมได้สาขาแรกของรายการ)

### 7.2 กลับหน้ารายการ

ปุ่มสร้างส่ง query ของหน้ารายการผ่าน router state · บันทึกหรือยกเลิกแล้วกลับไป `/expenses` พร้อม query เดิม ·
เปิด `/expenses/new` ตรง ๆ (ไม่มี state) กลับไป `/expenses`

### 7.3 ข้อมูลที่กรอกหายได้

- เดิมฟอร์มบังเมนูข้างทั้งจอ · ใหม่กดเมนูข้างได้ และข้อมูลที่กรอกจะหายโดยไม่ถาม (ยอมรับ — ข้อ 2)
- เพิ่ม `beforeunload` เมื่อข้อมูลของฟอร์มเปลี่ยนหลังผู้ใช้แตะฟอร์มแล้ว (พิมพ์ คลิกเลือก สลับประเภท ใช้แม่แบบ) และยังไม่ได้บันทึก (กันรีเฟรช/ปิดแท็บ)

### 7.4 อื่น ๆ

- หน้า `/expenses/new` ไม่มีเมนูล่างของแอปบนมือถือ
- ใบลดหนี้โหมดอ้างอิงที่เอกสารต้นฉบับจ่ายแล้วมีช่องเลือกบัญชีรับเงินคืน (ข้อ 5.3)
- ตัวเลือกบัญชีค่าใช้จ่ายพิมพ์ค้นหาได้ · บัญชีเงินเลือกจาก dropdown แทนการ์ด (ข้อ 9.1)
- ตัวเลือกบัญชีแบบค้นหาแสดงเลขบัญชี + หัวข้อกลุ่ม — **กระทบหน้ารายได้อื่นและเงินสดย่อยด้วย** (ข้อ 9.1)
- เลือกประเภทจากเมนูที่หัวการ์ดแทนชิป · "จ่ายทันที/ตั้งหนี้" เลือกในส่วนชำระเงิน
- ป้ายแนะนำ "แนะนำ" บนชิปหายไป (แทนด้วยบรรทัดในข้อ 6 กติกา 2)

## 8. มือถือ (จอเล็กกว่า lg)

- `FormRow` ทุกแถวเป็นป้ายบน เนื้อหาล่าง
- ตารางรายการของ EX ใบลดหนี้ และเงินสดย่อยเป็นการ์ดต่อบรรทัด (เจ้าของเลือก 2026-11-16 สำหรับเงินสดย่อย) · ตารางจ่ายเจ้าหนี้เป็นการ์ดเมื่อจอแคบ (ScreenTable เดิม) · ตารางเงินเดือนเลื่อนแนวนอนในกล่องตาราง
- แถบปุ่มติดขอบล่างจอ เว้น safe-area · ปุ่มสูงอย่างน้อย 44px
- ข้อความแจ้งเตือนของเงินเดือน (`role="alert"` ที่ย้ายโฟกัส) และข้อความ "ไม่มีสิทธิ์ลงบัญชี" อยู่เหนือแถบปุ่ม ไม่ถูกบัง
- เนื้อหาหน้ามีระยะล่างเท่าความสูงแถบปุ่ม

## 9. กติกา UI ที่ต้องผ่าน

- token เท่านั้น (ห้าม hex, `gray-*`, `amber-*`) · ตัวอักษรบน `bg-primary` ใช้ `text-primary-foreground` ·
  สีเตือนใช้ `text-warning-strong` บนพื้นอ่อน
- กล่องยอดเด่นของ `SummaryBox`: `bg-primary text-primary-foreground`
- ช่องกรอกใช้ `formControlClass` / `formLabelClass` / `NativeSelect` / `NumberInput` เดิม (กติกา field-scale)
- ข้อความไทยใช้ `leading-snug` · สถานะมีไอคอนหรือข้อความกำกับ ไม่ใช้สีอย่างเดียว
- เครื่องหมายถูกของ `FormRow` มี `aria-hidden` (ข้อมูลนี้ซ้ำกับบรรทัด "พร้อมบันทึก/ยังไม่ครบ" ในแถบล่าง)

- ใบเงินเดือนมีปุ่มบันทึกร่างสองปุ่มที่ทำงานต่างกัน ("บันทึกร่าง + คิดยอด" อยู่หน้าเดิม · "บันทึกร่าง" กลับหน้ารายการ)
- `ItemLinesSection` คิดจำนวนเงินต่อบรรทัดโดยไม่ดูประเภทราคา (แก้ด้วยการเปลี่ยนชื่อคอลัมน์เท่านั้น)
- ยังไม่ได้ตรวจว่า server ปฏิเสธ `branchId` ข้ามสาขาของผู้จัดการสาขาหรือไม่ (หน้าใหม่รับ `?branch=` เฉพาะสาขาที่ผู้ใช้เห็น)
- ใบลดหนี้แสดงช่องที่ไม่ได้ส่งไป server (เลขใบกำกับ, ประเภทราคา, ประเภทผู้ขาย, ค่าใช้จ่ายต้องห้าม) และโหมดไม่อ้างอิงมีช่องชื่อผู้ขายสองที่
  ที่ผูกกับค่าเดียวกัน — คงไว้ตามเดิม
- การกันออกจากหน้าด้วยเมนูข้าง (ต้องย้ายจาก `<BrowserRouter>` เป็น data router)
