# ตรวจบนอุปกรณ์จริงเมื่อพร้อม

สถานะปัจจุบัน: ยังไม่ทดสอบจริง เพราะผู้ใช้ยืนยันว่าไม่มี staging และไม่มีเครื่องทดสอบ ผล browser emulation ไม่ใช้แทนการลงนามส่วนนี้

ใช้บัญชีและข้อมูลทดสอบเท่านั้น บันทึกรุ่นเครื่อง, OS, browser/LINE version, URL/build, role/company, รูปหรือวิดีโอ, expected/actual ของแต่ละกรณี

1. เปิดจอแนวตั้ง/นอน 320–430 CSS px: header, sidebar, bottom nav, safe-area, ไม่มี body scroll แนวนอน; ตารางเลื่อนเฉพาะภายใน
2. ลองขยายข้อความและซูม: label/value/ปุ่มหลักไม่ทับกัน; เปิด keyboard กรอกไทย/ตัวเลข/วันที่แล้ว submit ยังเข้าถึงได้
3. Light/dark ตามระบบและสลับเอง: primary/status/error อ่านได้; เอกสาร/ใบเสร็จ/สติกเกอร์ยังพื้นขาวและขนาดกระดาษเดิม
4. LINE: login → callback → เปลี่ยนบัญชี → ยกเลิก login → back/resume; ไม่แสดงข้อมูลบัญชีก่อนหน้า; ข้อผิดพลาดเครือข่ายไม่แสดงว่าปิดยอดแล้ว
5. ถ่ายภาพ/เลือกรูป: อนุญาตและปฏิเสธสิทธิ์กล้อง, ลอง HEIC/JPEG และ upload failure/retry; อย่าใช้เอกสารส่วนบุคคลจริง
6. QR เก่า: UUID/hash, RT ใบเสร็จ/ใบสำคัญ, prefix ใบสำคัญ custom; guest login แล้วกลับรายการเดิม; ไม่เห็นเอกสารนอกบริษัท/สาขา
7. Editor320: เพิ่ม “แนบรูปภาพ”, collapse/edit/undo, preview, scroll และ Export PDF; popup อยู่ในจอและปุ่มถึงได้
8. ตรวจ PDF/print กับเครื่องจริง: ไทย, A4/แนวนอน/ใบเสร็จ/สติกเกอร์, ตารางหลายหน้า, ยอดรวมและช่องเซ็นไม่ถูกตัด

เกณฑ์ยอมรับ: flow สำเร็จหรือมีข้อความ error/retry ถูกต้อง, ไม่มีข้อมูลผิดคน/สิทธิ์, ไม่มีปุ่มใช้งานไม่ได้หรือข้อมูลสำคัญถูกตัด บันทึกผลจริงก่อนระบุ PASS
