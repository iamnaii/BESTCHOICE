## 1. เจตนาและเหตุผล

ระบบลงเวลา (ก้อน 10) เก็บชั่วโมง OT ต่อคนต่อวันได้แล้ว แต่ใบเงินเดือนยังให้คนพิมพ์ยอด OT เองเป็น "รายได้พิเศษ" และค่าคอมพนักงานขายจ่ายแยกนอกใบเงินเดือนโดย**ไม่ลงบัญชีและไม่หักภาษี**เลย ก้อนนี้ต่อสองอย่างเข้าใบเงินเดือนเดิม:

- OT / ทำงานวันหยุด คิดจากระบบลงเวลาอัตโนมัติ ตามสูตรเจ้าของ `ชั่วโมง × อัตรา × (เงินเดือน ÷ 30 ÷ 8)`
- ค่าคอมที่อนุมัติแล้วเข้าใบเงินเดือนเป็นรายการ จ่ายพร้อมเงินเดือน ลงบัญชีและเข้าฐาน ภ.ง.ด.1 ตามใบเงินเดือนที่มีอยู่
- สลิปกระดาษ A4 ที่มีอยู่แล้วแต่ไม่มีทางเข้า เปิดใช้ได้จริง และแสดงที่มาของ OT/ค่าคอม

**ความสำเร็จ:** สิ้นเดือนผู้ทำเงินเดือนกด "ดึง OT และค่าคอมงวดนี้" ครั้งเดียว ได้ยอดที่ถูกต้องและตรวจสอบย้อนได้ ไม่มีค่าคอมจ่ายซ้ำ และข้อมูลลงเวลาของเดือนที่จ่ายแล้วแก้ไม่ได้

## 3. เป้าหมาย / ไม่ทำ / ห้ามเกิด

**เป้าหมาย**
1. ปุ่ม "ดึง OT และค่าคอมงวดนี้" ในฟอร์มใบเงินเดือน เติมแถวรายได้พิเศษที่ระบบสร้าง (ล็อก แก้มือไม่ได้) + รายการค่าคอม + สรุปลงเวลา + รายการที่ต้องตรวจ
2. server คิดยอดเองทุกครั้งที่บันทึก/ลงบัญชี — ไม่เชื่อตัวเลขจากหน้าเว็บ
3. ค่าคอมหนึ่งรายการอยู่ได้ในใบเงินเดือนที่ยังมีผลเพียงใบเดียว · POST = ค่าคอมเป็น PAID · VOID = กลับเป็น APPROVED
4. วันลงเวลาของ (คน, เดือน) ที่อยู่ในใบเงินเดือน POSTED แก้ไม่ได้
5. สลิป A4 พิมพ์ได้จากหน้ารายละเอียดใบเงินเดือน แสดง "ชั่วโมง × อัตรา" และรายการค่าคอม

**ไม่ทำในก้อนนี้**
- หักเงินสาย/ขาด/ลาไม่รับค่าจ้าง (D1)
- ปฏิทินวันหยุดตามประเพณี/วันหยุดนักขัตฤกษ์ (ร้านเปิดทุกวัน หยุดสัปดาห์ละ 1 วันสลับ — วันหยุดในระบบ = `dayKind DAY_OFF`)
- OT อัตโนมัติของพนักงานรายวัน/สัญญาจ้าง (D4) · ใบเงินเดือนที่ฐานเงินเดือนเป็น 0
- ตั้งค่าใช้จ่ายค่าคอมค้างจ่าย ณ วันขาย (รอฝ่ายบัญชี คำถาม A3)
- สิทธิ์ BM ทำใบเงินเดือน (เดิมเลือกพนักงานไม่ได้ — แยกเป็นงานต่างหาก)
- เปลี่ยนวิธีแนะนำ WHT (×12) และฐานประกันสังคม (คงฐานเงินเดือนอย่างเดียว) จนกว่าฝ่ายบัญชีตอบ

**ห้ามเกิด (anti-goals)**
- ค่าคอมจ่ายซ้ำ (ใบเงินเดือน + ปุ่มจ่ายเก่า + ใบจ่ายคอมรายเดือน)
- OT ของคนเดียวกันเดือนเดียวกันถูกดึงเข้าสองใบ (สองสาขา/สองฝั่ง)
- ยอด OT บนใบไม่ตรงข้อมูลลงเวลาตอนลงบัญชี โดยไม่มีใครรู้
- ส่งสลิปทาง LINE/อีเมล

## 5. การคิดเงิน (ฟังก์ชันบริสุทธิ์ตัวเดียว ใช้ทั้ง prefill / บันทึก / POST)

อัตราต่อชั่วโมง `h = EmployeeProfile.baseSalary ÷ 240` (= ÷30 ÷8) **ไม่ปัด** — ใช้เงินเดือนเต็มเดือนในทะเบียน ไม่ใช่ฐานในบรรทัด (คนเข้า/ออกกลางเดือนถูกพิมพ์ฐานตามวัน ถ้าใช้ฐานในบรรทัด อัตรา OT จะต่ำกว่า ม.61) · ทะเบียนเปลี่ยนหลังดึง = ยอดคิดใหม่ไม่เท่า → 409 ตาม §8 (คำตัดสินผม §15)

| แถว (source) | ชั่วโมงมาจาก | ยอด | บัญชี (ค่าเริ่มต้น) |
|---|---|---|---|
| `ATTENDANCE_OT` OT วันทำงาน | Σ `otHours` ของแถว `dayKind = WORK` และ `LEAVE_*` ที่มีการตอก (ลาแล้วมาทำงาน = วันทำงาน) | `h × 1.5 × ชม.` | role `shop_payroll_overtime` (S52-1202) / `payroll_overtime` (53-1103) |
| `ATTENDANCE_HOLIDAY` ทำงานวันหยุด (เวลางานปกติ) | แถว `DAY_OFF` / `SHOP_CLOSED` ที่มีการตอก: นาทีที่อยู่ในช่วงเวลางาน [workStart, workEnd] − พัก 60 นาทีเมื่ออยู่ในช่วงงาน ≥ 5 ชม. → ปัดตามตาราง 15/45 → เพดาน 8 ชม. | `h × 1 × ชม.` | บัญชีเดียวกับ OT (รอฝ่ายบัญชี A5) |
| `ATTENDANCE_HOLIDAY_OT` OT วันหยุด | `otHours` ของแถว `DAY_OFF` / `SHOP_CLOSED` | `h × 3 × ชม.` | บัญชีเดียวกับ OT |
| `COMMISSION` ค่าคอม | Σ `commissionAmount` ของรายการที่ดึง (ดู §6) | ตามยอด | S51-1101 "ค่าคอมพนักงานขายสาขา" (SHOP เท่านั้น — รอฝ่ายบัญชี A3) |

- ปัดเงิน **ครั้งเดียวต่อแถวต่อคนต่อเดือน** HALF_UP 2 ตำแหน่ง (`ชม.` รวมทั้งเดือนก่อน แล้วคูณ) · ตัวอย่างเงินเดือน 15,000: `h = 62.5` · OT 1.5 ชม. = 140.63 · OT วันหยุด 2 ชม. = 375.00 · ทำงานวันหยุด 8 ชม. = 500.00
- ชั่วโมงเก็บใน `quantity` · อัตราต่อชั่วโมงหลังคูณเท่า (`h × multiplier`, ไม่ปัด) เก็บใน `rate` · สลิปพิมพ์ "2 ชม. × 93.75" (แสดงอัตราปัด 2 ตำแหน่ง ยอดใช้ค่าที่คำนวณจาก `rate` เต็ม)
- `isTaxable = true` ทุกแถวระบบ (เงินได้ ม.40(1) — รอฝ่ายบัญชี A2) · ฐานประกันสังคมคงเป็นฐานเงินเดือนอย่างเดียว (รอ A1)
- **ไม่คิดอัตโนมัติ** เมื่อ `EmployeeProfile.employmentType ≠ MONTHLY` หรือ `EmployeeProfile.baseSalary` ว่าง (D4) → ไม่สร้างแถว แต่ส่งชั่วโมงและคำเตือน "พนักงานรายวัน/ไม่มีฐานเงินเดือนในทะเบียน — กรอก OT เอง"
- ข้อมูลลงเวลาอ่านตรงจาก `attendanceDay` **ทุกสาขา** ของ userId ในเดือน (`dbDate(bangkokMidnight(...))`) — ไม่ผ่าน controller/boundary ของลงเวลา · รวมตาม userId (ไม่ใช่ตามสาขา)
- แถวที่มีธง `MISSING_OUT` ได้ OT 0 อยู่แล้ว (กติกาลงเวลา) — เข้า "รายการที่ต้องตรวจ" ให้ผู้จัดการแก้เวลาออกก่อนดึง

## 6. ค่าคอม

- ดึงเฉพาะ `SalesCommission` ของ `salespersonId = userId` · `status = APPROVED` · `period ≤ งวดของใบ` (ค่าคอมที่อนุมัติค้างจากเดือนก่อนเข้าได้) · `deletedAt null` · ไม่ผูกกับใบเงินเดือนที่ยังมีผล
- ไม่ดึง `PENDING` (ยังไม่อนุมัติ) · `CLAWED_BACK` / `PARTIALLY_CLAWED_BACK` (รอเจ้าของตัดสินภายหลัง) · ใบเงินเดือนฝั่ง `FINANCE` ไม่ดึงค่าคอม (บล็อกพร้อมข้อความ — รอฝ่ายบัญชี A7)
- ตารางใหม่ `PayrollCommissionItem { id · payrollLineId (Cascade) · salesCommissionId · amount Decimal(12,2) · releasedAt? · createdAt }` + **partial unique** `(sales_commission_id) WHERE released_at IS NULL` (SQL ใน migration) ⇒ ค่าคอมหนึ่งรายการอยู่ได้ใบเดียว · แก้ร่าง (ลบ/สร้างบรรทัดใหม่) = cascade · VOID = ตั้ง `releasedAt`
- POST ใบเงินเดือน (ใน tx ของ post): รายการที่ผูก → `PAID` · `paidAt = documentDate` · `paidAmount = amount` · VOID: กลับเป็น `APPROVED` · ล้าง `paidAt/paidAmount` · `releasedAt = now`
- หน้า `/commissions`: ปุ่ม "อนุมัติ" ใช้ได้ (**แก้บั๊ก**: เว็บเรียก `PATCH /commissions/:id/approve` แต่ API เป็น `@Post` → 404 · `CommissionsPage.tsx:114,126`) · ถอดปุ่ม "จ่าย" รายแถว · ป้ายสถานะ "อยู่ในใบเงินเดือน PR-…" · API `POST /commissions/:id/pay`, `POST /commissions/payouts/generate`, `PATCH /commissions/payouts/:id/paid` → **410** "จ่ายค่าคอมผ่านใบเงินเดือนเท่านั้น — สร้างใบเงินเดือนที่เมนูรายจ่าย › สร้างเอกสาร › เงินเดือน แล้วกด ดึง OT และค่าคอมงวดนี้" (ชื่อเมนูจริงต่างตาม role: "บันทึกรายจ่าย" / "ค่าใช้จ่ายดำเนินงาน" / "รายจ่าย" ⇒ ใช้คำว่า "เมนูรายจ่าย") · ใบจ่ายคอมรายเดือนเดิมเหลือดูอย่างเดียว
- `markPayoutPaid` / `generatePayouts` เดิมรวมแถว PENDING/PAID และไม่อัปเดตแถวข้างใน (บรีฟ §2 ข้อ 10) — ปิดด้วย 410 ข้างบน ไม่ต้องซ่อม
- **ค่าคอมเก่าไม่มีให้จ่ายซ้ำ** (ตรวจ prod 27/10): `sales_commissions` 8 แถว + `commission_payouts` 1 ใบ (DRAFT) เป็นข้อมูลทดสอบที่ถูกลบแล้วทั้งหมด · ใบเงินเดือน 0 ใบ ⇒ ไม่ต้อง migration · กันไว้อีกชั้น: ไม่ดึงแถวที่อยู่ในใบจ่ายรายเดือนที่ไม่ใช่ร่าง (ตัวตรวจเดียวกับด่าน G4b ของยกเลิกใบขาย — ห้ามเขียนชุดที่สอง)
- ร่างที่ถูก soft delete ไม่ cascade ⇒ ต้องตั้ง `releasedAt` ของ `PayrollCommissionItem` เองใน tx เดียวกัน · VOID คืนสถานะแบบมีเงื่อนไข (`updateMany where status = PAID` — แถวที่ถูกเรียกคืนไปแล้วไม่ถูกตั้งกลับเป็น APPROVED)

## 8. ลำดับการทำงานและ API

1. ผู้ทำเงินเดือนเลือกสาขา · ฝั่ง · งวด · พนักงาน (หรือคัดลอกงวดก่อน — **ข้ามแถว source ≠ MANUAL**)
2. กด **"ดึง OT และค่าคอมงวดนี้"** → `POST /expense-documents/payroll/prefill { branchId, entityScope, payrollPeriod, userIds[] }` (roles เดียวกับสร้างใบเงินเดือน · ลง manifest) คืนต่อคน: `systemIncome[]` (source, ชื่อ, ชม., อัตรา, ยอด, บัญชี) · `commissionItems[]` (เลขสัญญา/ใบขาย, วันที่, ยอด) · `attendanceSummary` · `review[]` (วัน + ธง: MISSING_OUT, DEVICE_CONFLICT, DEVICE_UNAVAILABLE, AFTER_PIN_LOCKOUT, LOCATION_CHANGED, NETWORK_CHANGED, CORRECTED, NO_PIN) · `warnings[]` (รายวัน/ไม่มีฐาน · ดึงไปแล้วในใบอื่น · ยังไม่ถึงเวลาปิดงวด)
3. แถวระบบแสดงล็อก (ป้าย "จากระบบลงเวลา" / "ค่าคอม n รายการ") · แผง "รายการที่ต้องตรวจ" กดเปิดวันนั้นที่ เมนู ลงเวลา › วันนี้ (เลือกวันที่) ได้
4. บันทึกร่าง (create/update) → server **คิดแถวระบบใหม่เอง** สำหรับบรรทัดที่มีแถวระบบ (ทิ้งยอดจาก client) · แถว MANUAL คงเดิม · ผูก `PayrollCommissionItem`
5. ลงบัญชี (POST) → ตรวจ (ก) ถึงเวลาปิดงวดแล้ว (D3) ถ้ามีแถวระบบลงเวลา (ข) คิดใหม่แล้ว**ต้องเท่ากับ**ที่เก็บไว้ ไม่งั้น 409 "ข้อมูลลงเวลา/ค่าคอมเปลี่ยนหลังดึง — กด ดึง OT และค่าคอมงวดนี้ อีกครั้ง แล้วตรวจก่อนลงบัญชี" (ค) ไม่มีใบอื่นที่ยังมีผลในงวดเดียวกันที่มีแถวระบบลงเวลาของคนเดียวกัน → JE `PayrollTemplate` เดิม (Dr รายบัญชีรายได้พิเศษมีอยู่แล้ว) + ค่าคอมเป็น PAID ใน tx เดียวกัน
6. **ขั้นอนุมัติ (คำตัดสินผม §15):** PAYROLL ต้องอนุมัติทุกใบ (`approval_required_doc_types` ค่าเริ่มต้น `['PAYROLL']`) และ `auto_post_on_approve = true` ⇒ ด่าน (ก)(ข)(ค) ของข้อ 5 ทำงานใน `approve()` ไม่ใช่แค่ `post()`. ส่งขออนุมัติได้ทุกเวลา · ปุ่ม "อนุมัติและลงบัญชี" ปิดจนถึงเวลาปิดงวดพร้อมบอกเวลา · อนุมัติแล้วชน 409 → **ทางใหม่ `PENDING_APPROVAL → DRAFT` "ส่งกลับเป็นร่าง"** (ผู้อนุมัติกด · AuditLog หลัง commit) แล้วผู้ทำเงินเดือนดึงใหม่และส่งอีกครั้ง · ปิดขั้นอนุมัติไว้ = ใบยังเป็นร่าง กดดึงใหม่ได้ทันที · ข้อความ 409 ต้องชี้ปุ่มตามสถานะใบ (รออนุมัติ → "ส่งกลับเป็นร่าง" · ร่าง → "ดึง OT และค่าคอมงวดนี้")
7. `totalAmount` ของใบ PAYROLL = ยอดก่อนหัก (ฐาน + รายได้พิเศษ) เพื่อให้เกณฑ์อนุมัติถูก (เดิม = Σฐาน) — builder ต้อง grep ผู้อ่าน `totalAmount` ของ PAYROLL ทุกตัวก่อนแก้

## 9. ล็อกข้อมูลลงเวลาหลังจ่าย

- `AttendanceService.correctDay` / `setDayKinds` / `clearConflictFlag` ปฏิเสธวันของ (userId, เดือน) ที่อยู่ในใบเงินเดือน `POSTED` ที่ยังไม่ VOID → 409 "เดือนนี้จ่ายเงินเดือนแล้ว (ใบ PR-…) — แก้ไม่ได้ ถ้าต้องปรับให้ใส่รายการปรับปรุงในงวดถัดไป"
- การตอกบัตรสดไม่ถูกล็อก (เกิดก่อนใบลงบัญชีได้ตามกติกา D3 อยู่แล้ว)
- หน้า ลงเวลา: แถว/วันที่ล็อกแสดงป้าย "จ่ายเงินเดือนแล้ว" และไม่มีปุ่มแก้ไข

## 10. สลิปกระดาษ

## 12. คำถามถึงฝ่ายบัญชี (สร้างด้วยค่าเริ่มต้นไปก่อน · เปลี่ยนได้ที่ role/whitelist ไม่ต้องแก้โครง)

- **A1** OT/ค่าทำงานวันหยุด นับเป็น "ค่าจ้าง" ของเงินสมทบประกันสังคม (ม.5) ไหม · ค่าเริ่มต้น: ไม่นับ (ฐาน = เงินเดือน)
- **A2** OT/ค่าคอม เป็นเงินได้ ม.40(1) เข้า ภ.ง.ด.1/50 ทวิ/กท.20ก ไหม · ค่าเริ่มต้น: เข้า (`isTaxable = true`)
- **A3** บัญชีค่าคอมเมื่อจ่ายผ่านเงินเดือน (S51-1101 / S52-1204 / FINANCE 52-1101) · รับรู้ตอนขายหรือตอนจ่าย · ใบจ่ายคอมเก่าที่ PAID โดยไม่มี JE ต้องบันทึกย้อนไหม · ค่าเริ่มต้น: S51-1101 รับรู้ตอนจ่าย ไม่บันทึกย้อน
- **A4** (ถ้าวันหน้าหักสาย/ขาด) ลดฐานหรือ Cr รายได้อื่น (FINANCE 42-1104 · SHOP ไม่มีบัญชีเทียบ)
- **A5** ค่าทำงานวันหยุด/OT วันหยุด ลงบัญชีเดียวกับ OT ไหม · ค่าเริ่มต้น: เดียวกัน
- **A6** วิธีหัก ณ ที่จ่ายของเงินได้ไม่ประจำ (OT/ค่าคอม) · ค่าเริ่มต้น: คงวิธีแนะนำเดิม (×12) เป็นคำแนะนำเท่านั้น
- **A7** ค่าคอมของพนักงานในใบฝั่ง FINANCE · ค่าเริ่มต้น: บล็อก
- **A8** ฐาน กท.20ก รวม OT/โบนัส/ค่าคอม ไม่รวมแถว ม.42 ถูกไหม · ค่าเริ่มต้น: ตามที่ระบบทำอยู่

## 13. จุดที่เทสต้องครอบ (review focus)

1. คนเดียวสองสาขาในเดือนเดียว: OT รวมตาม userId และดึงได้ใบเดียว
2. ลงเวลาถูกแก้หลังดึงแต่ก่อน POST → 409 · หลัง POST แก้ไม่ได้
3. ค่าคอม: ใบเงินเดือน VOID แล้วดึงเข้าใบใหม่ได้ · ใบที่สองดึงซ้ำไม่ได้ (unique) · ปุ่มจ่ายเก่า/ใบจ่ายรายเดือน = 410
4. ปัดเศษ: รวมชั่วโมงก่อนแล้วปัดครั้งเดียว (15,000 × 0.5 ชม. × 3 วัน = 140.63 ไม่ใช่ 140.64) · ไม่ปัดอัตรา (16,500 × 1.5 ชม. = 154.69)
5. POST ก่อน 18:00 วันที่ 1 เดือนถัดไปของใบที่มีแถวระบบลงเวลา → ปฏิเสธพร้อมเวลาที่ทำได้
6. วันหยุด: มา 13:00–21:00 บน DAY_OFF (เวลางาน 10–19) → ทำงานวันหยุด 5 ชม. (6 ชม. − พัก 1) · OT วันหยุด 2 ชม.

## 14. คำถามที่เจ้าของต้องตอบ (จาก builder check — เปลี่ยนสิ่งที่สร้าง)

1. **วันที่ยังมีธง "เครื่องชนกัน" (สงสัยตอกแทนกัน) — ห้ามอนุมัติจนกว่าเจ้าของล้างธง หรือแค่เตือน?** ธงนี้ล้างได้เฉพาะเจ้าของอยู่แล้ว แต่สเปกตอนนี้จ่าย OT ของวันนั้นแล้วล็อกทันทีหลังลงบัญชี · **ค่าที่ผมแนะนำ:** ธงเครื่องชนกัน = บล็อกปุ่มอนุมัติ (ชี้ไปหน้าลงเวลาให้เจ้าของตรวจ) · ธงอื่น (ไม่มีเวลาออก / ตอกหลังพักรหัส / ผู้จัดการแก้เวลา / ตำแหน่งเปลี่ยน) = เตือนในแผง "วันที่ต้องตรวจ" อย่างเดียว
2. **ค่าคอมที่จ่ายผ่านเงินเดือนไปแล้ว ถ้าต้องเรียกคืนภายหลัง จะหักจากเงินเดือนงวดถัดไปไหม?** หลังลงบัญชีเงินเดือนครั้งแรก ค่าคอมจะเป็น "จ่ายแล้ว" จริงเป็นครั้งแรก ⇒ (ก) ยกเลิกใบขายที่ค่าคอมจ่ายแล้วถูกบล็อกถาวร (ด่าน G4 "ยังไม่มีเมนูเรียกคืนค่าคอมที่จ่ายแล้ว") (ข) คืนเครดิตเทิร์นจะล้ม "ต้องเรียกคืนค่าคอมก่อน" (ค) รอบเรียกคืนค่าคอมรายวัน (`commission-clawback.cron.ts`) จะตั้งยอดที่พนักงานต้องคืนแต่ไม่มีทางหัก · **ค่าที่ผมแนะนำ:** เพิ่มแถวหักอัตโนมัติ "หักคืนค่าคอม" ในใบเงินเดือนงวดถัดไป (ล็อกแบบแถวจากระบบ) และให้ยกเลิกใบขาย/คืนเครดิตเทิร์นเปลี่ยนค่าคอมที่จ่ายแล้วเป็น "เรียกคืน" แทนการบล็อก — ขอบเขตเพิ่มราว 1 งาน

## 15. คำตัดสินที่ผมตัดสินเอง (เจ้าของตรวจได้ตอนอ่าน)

- อัตรา OT ใช้เงินเดือนเต็มในทะเบียน ไม่ใช่ฐานในบรรทัด (§5)
- ขั้นอนุมัติ: ส่งขออนุมัติได้ทุกเวลา · อนุมัติและลงบัญชีได้หลัง 18:00 วันที่ 1 · ชน 409 ตอนอนุมัติ → ทางใหม่ "ส่งกลับเป็นร่าง" (§8 ข้อ 6 · mockup กระดาน 2)
- ไม่ต้อง migration ค่าคอมเก่า (prod ไม่มีแถวที่ยังใช้งาน) + กันแถวในใบจ่ายรายเดือนที่ไม่ใช่ร่างไว้อีกชั้น (§6)
- ลงเวลาล็อกตาม (คน, เดือน) ที่มีบรรทัดในใบเงินเดือนที่ลงบัญชีแล้ว — รวมคนที่ OT ไปอยู่ในใบของสาขาอื่น (mockup กระดาน 5)
- ตารางใบเงินเดือนเพิ่มคอลัมน์ "รายได้พิเศษ" + ป้ายต่อคน · แผง "วันที่ต้องตรวจ" + "คำเตือน" ข้างตาราง (mockup กระดาน 1)
- สลิปแสดงรายการค่าคอมทีละใบ และกล่องสรุปเวลาทำงานเป็น "ข้อมูลประกอบ ไม่มีผลต่อยอดเงิน" (mockup กระดาน 3)
