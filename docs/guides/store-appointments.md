# นัดเข้าร้าน BESTCHOICE

เมนู **งานหน้าร้าน (SHOP) → นัดเข้าร้าน** (`/appointments`) สำหรับ OWNER, BRANCH_MANAGER และ SALES ที่มีสิทธิ์ SHOP พนักงานสาขาเห็นนัดและตารางเฉพาะสาขาตน

1. ผู้จัดการเปิด **ตารางพนักงาน** เลือกสาขาและวัน เพิ่มช่วงรับนัดของแต่ละคน แยกช่วงพักเป็นคนละช่วง คัดลอกทั้งวันได้โดยตรวจปลายทางทุกแถวก่อนบันทึก
2. เลือกลูกค้าที่มีผลเครดิต APPROVED เบื้องต้นแล้ว กำหนดสาขา/วัน/เวลา หรือสร้างลิงก์ให้ลูกค้าเลือกเอง
3. หน้าลูกค้า `/visit#token` เลือกเวลา ตรวจรายละเอียด และยืนยัน จากลิงก์เดียวกันดูนัด เลื่อน หรือยกเลิกก่อนเวลานัดได้
4. ที่ร้านใช้ **ลูกค้ามาถึงแล้ว → เริ่มบริการ → เสร็จสิ้น** หากปิดบัญชีพนักงาน นัดเดิมยังอยู่และขึ้นแจ้งให้จัดคนรับแทน

คิวสุดท้ายเริ่ม **18:30 น.** และสิ้นสุด **19:15 น.** โดยพนักงานต้องมีช่วงรับนัดครอบคลุมครบ 45 นาที ระบบไม่เปิดเวลาหลัง 18:30 น. และปฏิเสธการจองหรือเลื่อนนัดเกินเวลานี้ทั้งพนักงานและลูกค้า

นัดยาว 45 นาที จองอย่างน้อย 30 นาทีล่วงหน้าได้ภายใน 14 วันปฏิทินไทยรวมวันนี้ ลูกค้าหนึ่งรายมีนัดเปิดได้หนึ่งนัด เวลาเดียวกันรับได้ตามจำนวนพนักงานที่มีตารางและไม่มีนัดซ้อน

ผล FULL/APPROVED จากระบบเดิมใช้ได้ ไม่ต้องสร้าง PRE ใหม่ การกลับไปสถานะรอตรวจไม่ล้างผลผ่าน/ไม่ผ่านล่าสุด ผลก่อน migration ที่พิสูจน์ไม่ได้เป็น UNKNOWN และต้องให้พนักงานตรวจเครดิตก่อนจอง การจองไม่ได้เป็นการอนุมัติสินเชื่อขั้นสุดท้าย

ลิงก์สร้างนัดใหม่ได้ 30 วัน ส่วนสิทธิ์ดู/จัดการนัดที่ผูกไว้หมดอายุ 24 ชั่วโมงหลังจบนัด พนักงานกลับมาเปิด **ลิงก์ที่เคยออกให้ลูกค้า** เพื่อเพิกถอนลิงก์เก่าได้ ระบบเก็บเฉพาะ hash และไม่ใส่ token ในข้อความยืนยัน หลังเปิดลิงก์ token จะอยู่ในหน่วยความจำเท่านั้น หากรีโหลดหน้าลูกค้าให้เปิดลิงก์ต้นฉบับอีกครั้ง

นัดปรากฏในหน้าลูกค้า แผงนัดและสถานะขายของ Inbox ป้ายรายชื่อ/หัวห้อง และแถบแจ้งเตือนตามสิทธิ์สาขา โดยค้นผ่านลูกค้าที่ผูกกับห้อง จึงรวมการจองผ่านลิงก์ที่ไม่มีห้องต้นทางด้วย ประวัติดึงจากเหตุการณ์ของนัดโดยตรง ไม่มีแถวซ้ำตามจำนวนห้องแชท

## ตรวจบนเครื่อง

```sh
bash tools/test-store-appointments.sh
LOCAL_PREVIEW_PORT=5198 npm run local:check
APPOINTMENT_PREVIEW_URL=http://localhost:5198 node tools/check-store-appointments-preview.mjs
```

ทั้งชุดใช้ PostgreSQL แยกจากข้อมูลจริง พรีวิวเพิ่มสาขา/พนักงาน/ลูกค้าผ่านเครดิตจำลอง และใช้ controller/service นัดจริง ส่วนล็อกอินและ AI เป็น fixture ของพรีวิว ไม่มีการส่งแชทจริง หลักฐาน browser อยู่ที่ `.tmp/local-preview/appointments/` ชุด browser ตรวจเพิ่มตาราง → นัดโดยพนักงาน → ลิงก์ดูนัด → เลื่อน/ยกเลิก → ลูกค้าจองเอง → เวลาถูกจองแทรก → เช็กอิน/บริการ/เสร็จสิ้น → เพิกถอนลิงก์เก่า

การใช้งานจริงต้อง deploy migration และ API/Web พร้อมกัน งานนี้เตรียมและตรวจเฉพาะ local ยังไม่ได้ deploy

## ข้อความยืนยันเข้าแชท

เมื่อจองสำเร็จ ระบบบันทึกคิวส่งพร้อมนัดใน transaction เดียวกัน แล้วส่งเข้าแชทต้นทางอัตโนมัติในรอบ worker ประมาณ 10 วินาที ทั้งพนักงานจองให้และลูกค้าจองเอง การเลื่อน/ยกเลิกส่งข้อความอัปเดตด้วย ข้อความมีวัน เวลา สาขา เลขนัด แผนที่และเบอร์สาขาเมื่อมีข้อมูล

ลิงก์จาก Inbox ผูกห้องต้นทางไว้ หากไม่ได้ระบุห้อง ระบบส่งเมื่อมีห้อง SHOP ของลูกค้าเพียงห้องเดียว หลายห้องหรือไม่มีห้องจะขึ้นให้พนักงานติดตาม โดยไม่เดาส่งไปห้องอื่นและไม่ส่งเข้า LINE_FINANCE ก่อนส่งตรวจว่าห้องยังผูกลูกค้าและผู้รับคนเดิม

หน้าเว็บแยกผลส่งออกจากสถานะนัด ส่งไม่สำเร็จไม่ยกเลิกนัด พนักงานกดลองใหม่ได้เฉพาะกรณีที่ช่องทางยืนยันว่าไม่ได้ส่ง ส่วน timeout/ผลไม่แน่นอนต้องตรวจแชทก่อนและไม่ส่งซ้ำอัตโนมัติ งานค้าง SENDING เกิน 2 นาทีเปลี่ยนเป็น UNKNOWN การเลื่อนนัดแทนงานเก่าที่ยังรอส่ง

ข้อความอัตโนมัติส่งผ่าน LINE SHOP และ Facebook ที่ระบบเชื่อมไว้เท่านั้น WEB/TikTok แสดงให้พนักงานติดตามโดยไม่รายงานว่าส่งสำเร็จ การส่งเรียงตามนัดเดียวกัน หากข้อความก่อนหน้ายังยืนยันผลไม่ได้ ข้อความถัดไปเป็น BLOCKED ให้พนักงานตรวจแชทและใช้ข้อความที่เตรียมไว้ ข้อความอัตโนมัติไม่รับห้องแทนพนักงาน ไม่หยุด AI ไม่ล้างสถานะรอคำตอบ และไม่ใช้ HUMAN_AGENT fallback หน้าพรีวิวใช้ adapter จำลอง ไม่มีการส่ง LINE/Meta จริง

UX ใช้สีเขียวและตัวอักษรเดิมของ BESTCHOICE แสดง 3 ขั้นตอน หน้าสำเร็จเป็นบัตรนัดที่เน้นเวลา ปุ่มหลักสูงอย่างน้อย 44px ย้ายโฟกัสเมื่อเปลี่ยนขั้นตอน และแสดงผลส่งตามข้อมูลจาก server พร้อมคัดลอกข้อความหรือเลือกข้อความเองได้
