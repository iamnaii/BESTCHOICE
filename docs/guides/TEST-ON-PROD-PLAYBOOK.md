# คู่มือเทสระบบทั้งหมดบน Production (TEST-ON-PROD)

> คู่กับ: `apps/api/src/cli/seed-test-contracts.cli.ts` + `cleanup-test-contracts.cli.ts`
> Spec: `docs/superpowers/specs/2026-08-09-prod-test-data-pack-design.md`

ข้อมูลเทสทุกชิ้นถูก mark ไว้ให้ลบทิ้งได้หมดจดหลังจบ:

- **สัญญาเทส** — เลขขึ้นต้น `TEST-` (สัญญาที่เปิดใหม่ผ่านหน้าจอระหว่างเทสจะได้เลขจริง `BCP-`
  แต่ cleanup ตามเก็บให้เอง เพราะผูกกับลูกค้าเทส/เครื่องเทส)
- **ลูกค้าเทส** — ที่อยู่ = `ข้อมูลทดสอบระบบ — ลบได้` (ทุกคนชื่อขึ้นต้น "ทดสอบ")
- **เครื่องเทส** — IMEI ขึ้นต้น `TEST-` ชื่อขึ้นต้น "ทดสอบระบบ" (ไม่โชว์บนเว็บ shop)
- **JE ทุกใบ** ที่เกิดจากการเทส (รับชำระ / ปิดยอด / ยึดเครื่อง / cron กลางคืน) stamp
  `metadata.contractId` — cleanup hard-delete คืน Trial Balance ให้เหมือนเดิม

---

## 1. สร้างข้อมูลเทส

```bash
npm --prefix apps/api run build

# ต่อ prod ผ่าน cloud-sql-proxy + gcloud (runbook เดิม) — ชื่อ DB จริงคือ "bestchoice"
EXPECTED_DB_NAME=bestchoice npm --prefix apps/api run seed:test-contracts        # ดูก่อน (dry-run)
CONFIRM_SEED=YES_I_AM_SURE EXPECTED_DB_NAME=bestchoice npm --prefix apps/api run seed:test-contracts
```

ได้อะไรบ้าง:

| ชุด | รายละเอียด | ไว้เทส |
|---|---|---|
| สัญญา #1 | ครบกำหนดวันนี้ | รับชำระปกติ |
| สัญญา #2-4 | ค้าง 1 / 2 / 3 งวด (60+ วัน) | รับชำระ+ค่าปรับ, ติดตามหนี้, หนังสือทวง |
| สัญญา #5 | งวดอนาคตทั้งหมด | จ่ายล่วงหน้า / ดูตารางงวด |
| สัญญา #6 | **TERMINATED** ค้าง 4 งวด | **ยึดเครื่อง** (ผ่าน gate บอกเลิกสัญญาแล้ว) |
| สัญญา #7 | จ่ายแล้ว 4/6 งวด | **ปิดยอดก่อนกำหนด** |
| เครื่องว่าง 3 เครื่อง | มือถือใหม่ / มือสอง / หูฟัง (IN_STOCK) | POS ขายสด + เปิดสัญญาใหม่ |
| ลูกค้าเปล่า 2 คน | "ทดสอบระบบ ลูกค้าใหม่ 1/2" | ลูกค้าใหม่, trade-in, จอง |

ทุกสัญญามีเครื่องเทสของตัวเอง — **ไม่แตะเครื่องจริงในสต็อกเด็ดขาด**

## 2. ลำดับการเทสทีละระบบ

### 2.1 รับชำระ + ใบเสร็จ (สัญญา #1-#4)
- `/payments` → ค้นหา "TEST-" → บันทึกรับชำระ (เลือกวิธี **เงินสด/โอน** — ดูข้อห้าม 3.1)
- เช็ค: ค่าปรับงวดค้างขึ้นอัตโนมัติ, tolerance ±1฿, ใบเสร็จออก, void ใบเสร็จแล้ว wizard เปิดใหม่
- จ่ายบางส่วน (partial) กับสัญญา #3 เพื่อเทส PARTIALLY_PAID

### 2.2 ติดตามหนี้ (สัญญา #2-#4) — `/overdue`
- บันทึก call log, สร้างนัดชำระ (promise หลายที่), เลื่อนนัด (supersede), ปรับดิว (reschedule
  — จำกฎ: เงินไม่เข้า ดิวไม่เลื่อน)
- ⚠️ อย่าปล่อยให้ promise แตก (broken) — cron จะพยายามสั่ง MDM lock ซึ่งสัญญาเทสไม่มีเครื่องจริง

### 2.3 หนังสือทวง (สัญญา #4) — `/letters`
- cron 09:15 จะ generate หนังสือ 45D/60D ให้สัญญาค้างเอง หรือกด generate เอง → พิมพ์ → บันทึก dispatch

### 2.4 ยึดเครื่อง — 2 ทางเลือก

**ทางเร็ว (เทสได้ทันที): สัญญา #6 (TERMINATED แล้ว)** — `/repossessions`
- สร้างรายการยึด → ตีเกรด → ราคากลาง → ถ้าราคากลาง > ยอดปิด ติ๊กคืนเงินลูกค้า (21-1107)
- เทสทั้ง 2 ปุ่ม: **จ่ายคืนเงิน** และ **ไม่คืนเงิน** (ล้างเข้า 41-1102)
- ℹ️ ใบลดหนี้ (CN) จะ**ไม่ออก**กับสัญญานี้ (ถูกต้องตามหลัก: สัญญานี้ไม่เคยมีงวดที่รับรู้รายได้
  ผ่าน cron — ไม่มีอะไรให้ลดหนี้) และตัวเลขกำไร/ขาดทุนไม่สมจริง — ดู flow ครบก็พอ

**ทางเต็ม (สมจริง + ได้เทส CN): สัญญา #4 — ต้องรอข้ามคืนอย่างน้อย 1 คืน**
1. คืนแรกหลัง seed: cron 00:01 จะ accrue งวดค้างของสัญญา #4 ให้ครบเอง
2. `/letters` → dispatch หนังสือบอกเลิกสัญญา (60D) → สัญญาเปลี่ยนเป็น TERMINATED
3. `/repossessions` → ยึดเครื่อง → คราวนี้**ใบลดหนี้ออกอัตโนมัติ** + ส่ง LINE (ลูกค้าเทสไม่มี
   LINE — การส่งจะ fail และสร้าง Todo ตามระบบ ซึ่งก็คือได้เทส flow นั้นด้วย)
- ได้เทสต่อเนื่องครบ chain: หนังสือทวง → บอกเลิก → ยึด → CN ในสัญญาเดียว
- ℹ️ งวดค้างที่ตกในเดือนที่**ปิดงวดบัญชีไปแล้ว** cron จะข้ามไม่ accrue (ปลอดภัย มี Sentry แจ้ง)
  — CN จะครอบเฉพาะงวดที่ accrue ได้ในเดือนที่ยังเปิดอยู่

### 2.5 ปิดยอดก่อนกำหนด (สัญญา #7)
- หน้าสัญญา → ปิดยอดก่อนกำหนด → เช็คส่วนลดดอกเบี้ย + ยอดปิด (กฎ: ยอดปิดยึดคืน = ยอดปิดก่อนกำหนดเสมอ)

### 2.6 POS ขายสด (เครื่องว่าง) — `/pos`
- ขาย "ทดสอบระบบ มือถือมือสอง" เงินสด → ใบเสร็จ → เช็ค stock ตัด, ยอดขายขึ้น Dashboard/commissions

### 2.7 เปิดสัญญาผ่อนใหม่ทั้ง workflow (เครื่องว่าง + ลูกค้าเปล่า)
- `/contracts/create` → เลือก "ทดสอบระบบ ลูกค้าใหม่ 1" + เครื่อง "ทดสอบระบบ มือถือใหม่"
  → credit check → อนุมัติ → เซ็น → activate
- ⚠️ activate จะ post JE เปิดสัญญาจริง (1A + SHOP) → สัญญาจะ**โผล่ในคิวจ่ายให้หน้าร้าน
  (INTER-CO)** — ห้ามเอาไปรวมรอบจ่ายจริงเด็ดขาด (ดูข้อห้าม 3.2)

### 2.8 Trade-in (ลูกค้าเปล่า) — `/trade-in`
- รับซื้อเครื่องจากลูกค้าเทส → ตีราคา → รับซื้อ
- ⚠️ **กรอก IMEI ขึ้นต้น `TEST-` เสมอ** — cleanup ใช้ IMEI นี้ตามเก็บเครื่องที่รับซื้อเข้าสต็อก

### 2.9 ค่าใช้จ่าย / เงินเดือน / รายได้อื่น
- สร้างเอกสาร DRAFT → เทส flow อนุมัติ/post ได้ตามปกติ
- ⚠️ เอกสารพวกนี้**ไม่ผูกกับสัญญาเทส** — cleanup ไม่เก็บให้ ต้อง **void/reverse ผ่านหน้าจอเอง
  ก่อนรัน cleanup**

### 2.10 รายงาน
- TB / P&L / งบทดลอง / ECL — ระหว่างเทสจะมีตัวเลขสัญญาเทสปน (รวม JE จาก cron กลางคืน:
  ดอกเบี้ยค้างรับ 2A + สำรองหนี้ ECL) — **หายหมดหลัง cleanup**
- ⚠️ อย่ายื่น ภ.พ.30 / ปิดงวดบัญชี ระหว่างที่ยังมีข้อมูลเทสค้างอยู่

## 3. ข้อห้าม (สำคัญ)

1. **ห้ามจ่ายผ่าน QR PaySolutions จริง** — เงินจริงจะวิ่งเข้าบัญชีจริง ใช้บันทึกรับชำระ
   เงินสด/โอน แทน
2. **ห้าม approve รอบจ่าย INTER-CO ที่มีสัญญาเทส** — JE รอบจ่ายไม่ได้ stamp ต่อสัญญา
   cleanup ตามลบไม่ได้ (ถ้าพลาดไปแล้ว: reverse รอบจ่ายผ่านหน้าจอก่อน แล้วค่อยรัน cleanup)
3. **ห้ามผูก/สั่ง MDM lock กับสัญญาเทส** — ไม่มีเครื่องจริง
4. **ห้ามปิดงวดบัญชี/ยื่นภาษี** ระหว่างมีข้อมูลเทสค้าง
5. trade-in ต้องกรอก IMEI ขึ้นต้น `TEST-` เสมอ

## 4. ลบข้อมูลหลังเทสเสร็จ

เช็คลิสต์ก่อนรัน:
- [ ] เอกสารบัญชีที่สร้างระหว่างเทส (ค่าใช้จ่าย/เงินเดือน/รายได้อื่น) void/reverse หมดแล้ว
- [ ] ไม่มีรอบจ่าย INTER-CO ที่มีสัญญาเทสค้าง POSTED (ถ้ามี → reverse ก่อน)

```bash
EXPECTED_DB_NAME=bestchoice npm --prefix apps/api run cleanup:test-contracts     # ดูก่อน (dry-run)
CONFIRM_CLEANUP=YES_I_AM_SURE EXPECTED_DB_NAME=bestchoice npm --prefix apps/api run cleanup:test-contracts
```

cleanup ทำอะไร: hard-delete JE ทุกใบของสัญญาเทส (คืน Trial Balance) + soft-delete สัญญา,
งวด, ตารางงวด, ใบเสร็จ, หนังสือทวง, รายการยึด, คำขอยกเลิกสัญญา, ใบขาย, ค่าคอมพนักงาน,
trade-in, เครื่องเทส, ลูกค้าเทส

⚠️ dry-run จะพิมพ์**รายชื่อทุกตัวที่จะโดนลบ** (เลขสัญญา / IMEI / ชื่อลูกค้า / เลขใบขาย) —
**อ่านก่อนยืนยันเสมอ** โดยเฉพาะบรรทัดที่ flag "เปิดผ่าน UI (เลขจริง)" ว่าเป็นสัญญาเทสจริงๆ
ไม่ใช่สัญญาลูกค้าจริงที่หลงมา (เช่น เครื่องจริงที่เคยถูกกรอก IMEI ขึ้นต้น TEST-)

สิ่งที่เหลือค้าง (ยอมรับได้): audit logs (ลบไม่ได้โดยดีไซน์), เลขรันใบเสร็จ/ใบขายกระโดดข้าม,
call log ใต้สัญญาที่ถูกลบ (มองไม่เห็นจากหน้าจอแล้ว)

หลัง cleanup แนะนำเปิด `/financial-audit` + งบทดลอง (`scope=ALL`) เช็คว่า balance ทั้งสองฝั่ง
