# จ่ายเงินผู้จัดจำหน่าย / มัดจำ / เจ้าหนี้รายผู้จัดจำหน่าย (ก้อน 2 · ตุลาคม 2569)

ที่มา: คำตัดสินเจ้าของกิจการ 2026-10-05 และคำตอบฝ่ายบัญชี 2026-09-30 ข้อ 9 · 2026-10-05 ข้อ 1 และข้อ 4
("ให้โปรแกรมสร้างเมนูจ่ายเงินผู้จัดจำหน่าย และตัดสต๊อคให้เรียบร้อยก่อนใช้งานจริง")

## กติกา

- **บัญชีที่จ่าย เลือกได้ (2026-10-13 — ตอบคำถามฝ่ายบัญชี 13/10/2569 "เงินสดย่อย/อื่น ๆ")**: ค่าเริ่มต้น = ธนาคารหน้าร้าน (จ่ายออก) `S11-1202` ·
  เลือกได้อีก `S11-1201` ธนาคารหน้าร้าน (รับเข้า) · **`S11-1106` เงินสด - เงินสดย่อย (บัญชีใหม่ — ข้อเสนอ รอฝ่ายบัญชีรับรองรหัส)** ·
  ไม่มีเช็ค · **ไม่มี** เงินสดเจ้าของ `S11-1104` / ตู้เซฟ `S11-1105` / ลิ้นชักสาขา `S11-1101`–`S11-1103` — ยอดของบัญชีเหล่านั้นเดินตามสมุดปิดยอดลิ้นชัก/
  นำฝาก (อ่าน FIFO จากตาราง ไม่ใช่สมุดบัญชี) การเครดิตจากเมนูนี้จะทำให้สองสมุดไม่ตรงกันถาวร
  — เดิมโอนธนาคารเท่านั้น (คำตัดสินเจ้าของ 2026-10-05) · รายการเก็บบัญชีที่จ่ายในคอลัมน์ `bankAccountCode` (ชื่อคอลัมน์เดิม) · ตารางรายการจ่ายในใบแสดงคอลัมน์ "จ่ายจาก"
- **สลิปบังคับเมื่อจ่ายจากบัญชีธนาคาร** · จ่ายเงินสดย่อยแนบหลักฐานได้ไม่บังคับ · วันที่จ่ายไม่เกินวันนี้ และย้อนหลังไม่เกิน 365 วัน
- **เงินสดย่อยจ่ายได้ไม่เกินยอดในบัญชี** (`S11-1106` Dr − Cr ของรายการ POSTED สมุด SHOP · ตรวจในธุรกรรมเดียวกับการบันทึก) — ไม่พอ = 400 ไม่มีแถว/รายการเกิด ·
  **ยังไม่มีเมนูเติมเงินสดย่อย**: ต้องลงรายการโอนเข้า `Dr S11-1106 / Cr S11-1202` ด้วยมือ (API `POST /journal` — หน้าสมุดรายวันบนเว็บอ่านอย่างเดียว) ก่อนใช้
  — คำถามถึงฝ่ายบัญชี: เงินสดย่อยตั้งวงเงินเท่าไร เติมจากบัญชีไหน และใครเป็นผู้ถือ (ตอบแล้วค่อยทำเมนูเติม/คืนเงินสดย่อย)
- ส่งคำขอซ้ำด้วย `requestId` เดิม: ยอดและบัญชีต้องตรงกับที่บันทึกไปแล้ว (ตอบรายการเดิม) — ต่างกัน = 409 ให้รีเฟรชแล้วตรวจก่อนบันทึกใหม่
- รับมัดจำคืน (ยกเลิก/ปิดใบ) เข้าธนาคารรับเข้า `S11-1201` เท่านั้น — มัดจำที่จ่ายจากเงินสดย่อยก็รับคืนเข้าธนาคาร (ไม่มีทางรับคืนเป็นเงินสด)
- ชนิดรายการโปรแกรมตัดสินจากฐานะในสมุดบัญชีของใบสั่งซื้อ:
  - มีเจ้าหนี้คงเหลือ (รับของแล้ว) → **ชำระค่าสินค้า** ไม่เกินเจ้าหนี้ · ส่วนที่จ่ายเกิน = มัดจำ รอหักตอนรับของที่เหลือ
  - ยังไม่มีเจ้าหนี้ → **มัดจำ** (`S11-4201`) · ถูกหักเข้าเจ้าหนี้อัตโนมัติตอนรับของ (หน่วยที่รอถ่ายรูปหักตอนผ่านเข้าคลัง)
- เพดาน: มัดจำ + ชำระ − มัดจำที่ได้คืน ≤ ยอดสุทธิของใบ · **ใบที่ "ปิดใบ รับไม่ครบ" (2026-10-11)**: ≤ มูลค่าของที่รับจริงตามบัญชี (Σ เจ้าหนี้ที่ใบรับของตั้ง) — ยอดสุทธิของใบคงเดิม
- งวดของวันโอนปิดแล้ว → ลงวันที่บันทึกแทน และสร้างงานแจ้งฝ่ายบัญชี (แท็ก `supplier-payment-period`)
- รายการที่บันทึกผิด: **เจ้าของ** ยกเลิกรายการ (ต้องมีเหตุผล) = กลับรายการเต็มจำนวนลงวันที่ที่กด · มัดจำที่ถูกหักเข้าเจ้าหนี้แล้วยกเลิกไม่ได้
- ยกเลิกใบสั่งซื้อที่มีมัดจำค้าง ต้องเลือก **ได้คืน** (เข้า `S11-1201` · ส่วนที่ได้คืนไม่ครบ → `S53-1105`) หรือ **ไม่ได้คืน** (→ `S53-1105`)
- **ปิดใบ รับไม่ครบ** (คำตัดสินเจ้าของ 2026-10-11 — ใบที่รับของบางส่วนแล้วผู้จัดจำหน่ายไม่ส่งที่เหลือ): OWNER/ผู้จัดการสาขาปิดได้เฉพาะใบ "รับบางส่วน" · ปิดแล้วแก้ไม่ได้ ของที่มาทีหลังเปิดใบใหม่ · มัดจำค้างระบุผลแบบเดียวกับยกเลิก (รายการบัญชีชุดเดียวกัน) · ต้องไม่มีเครื่องของใบค้างในคิวรอถ่ายรูป · ใบยังเป็นเจ้าหนี้จนกว่าจะจ่ายค่าของที่รับแล้วครบ
- **ตีกลับเครื่องขณะใบมีมัดจำค้าง** (กด "ไม่รับเข้าคลัง" จากคิวรอถ่ายรูป): เครื่องไม่เคยลงบัญชี ไม่มีรายการให้กลับ แต่มัดจำส่วนนั้นค้างใน `S11-4201` → ระบบสร้างงานแจ้งฝ่ายบัญชีหนึ่งใบต่อใบสั่งซื้อ (แท็ก `po-deposit-reject`) และปิดให้เองเมื่อมัดจำค้างของใบเป็นศูนย์ (ปิดใบ/ยกเลิกใบระบุผลมัดจำ) — ไม่มีรายการบัญชีอัตโนมัติ
- สร้าง/อนุมัติใบสั่งซื้อ **ไม่รับยอดจ่าย** อีก · `PATCH /purchase-orders/:id/payment` ตอบ 410
- รับเข้าตรงจ่ายทันที: โอน + สลิป แล้วลงรายการใน transaction เดียวกับรับของ (ทางนี้ยังโอนธนาคารอย่างเดียว — `S11-1202` · เงินสด/เช็ค = 400 · ยังไม่เปิดเลือกบัญชี)
- `PurchaseOrder.paidAmount` / `paymentStatus` = ผลรวมจากตาราง `purchase_order_payments` — ห้ามเขียนตรง

## Endpoint

| เส้นทาง | สิทธิ์ | หน้าที่ |
|---|---|---|
| `POST /purchase-orders/:id/payments` | OWNER, BRANCH_MANAGER | บันทึกการจ่าย `{ paidAt, amount, slipUrl, reference?, note? }` |
| `POST /purchase-orders/:id/payments/:paymentId/void` | OWNER | ยกเลิกรายการ `{ reason }` |
| `GET /purchase-orders/:id/payments` | + FINANCE_MANAGER, ACCOUNTANT | รายการจ่าย + ฐานะจากสมุดบัญชี |
| `GET /purchase-orders/payables/ledger?month=YYYY-MM` | + FINANCE_MANAGER, ACCOUNTANT | เจ้าหนี้รายผู้จัดจำหน่าย |
| `GET /purchase-orders/payables/ledger/:supplierId?month=` | + FINANCE_MANAGER, ACCOUNTANT | รายการเคลื่อนไหว |
| `POST /purchase-orders/:id/cancel` | OWNER, BRANCH_MANAGER | body `{ depositOutcome, refundedAt?, refundAmount?, slipUrl?, reason? }` เมื่อมีมัดจำค้าง |
| `POST /purchase-orders/:id/close-short` | OWNER, BRANCH_MANAGER | ปิดใบ รับไม่ครบ `{ reason, depositOutcome?, refundedAt?, refundAmount?, slipUrl?, depositReason? }` — ใบ `PARTIALLY_RECEIVED` เท่านั้น |

## ยังไม่ทำ / รอ

- รายการจ่ายเก่าที่กรอกไว้ก่อนมีเมนู (คอลัมน์ `paidAmount` เดิม) ไม่ย้อนลงบัญชี — หน้าจอแสดงป้ายเตือน
- รหัสบัญชีย่อยในผัง (ถ้าฝ่ายบัญชีต้องการจริง) — รอคำตอบเอกสาร 05/10 ข้อ 4
- ก้อน 3 ตัดสต๊อก (หาย/เสียหาย/ตัดจำหน่าย) และก้อน 5 ภาษีซื้อของเครื่องขายผ่อน
