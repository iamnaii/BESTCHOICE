# ค่าปรับของรายการแบ่งชำระ — 2026-09-08

ผู้ใช้กำหนดว่า เมื่อเก็บค่าปรับในรายการ 2/1 แล้ว รายการแบ่งชำระถัดไปของงวดเดิม (2/2) ต้องไม่มีค่าปรับใหม่ ยกเว้นพนักงานระบุเพิ่ม ขอบเขตนี้ไม่ยกเว้นค่าปรับของงวดเดือนใหม่

## พฤติกรรมที่แก้

- หยุดคำนวณค่าปรับอัตโนมัติใหม่หลังงวดนั้นมีการรับชำระแล้ว ทั้งตอนรับเงิน การแสดงยอด และ cron รวมถึงกรณีค่าปรับเริ่มต้นเป็น 0
- เก็บ `Payment.lateFee` เป็นยอดสะสม เพราะ `amountPaid` รวมค่าปรับที่รับไปแล้ว ช่องแก้ไขแสดงเฉพาะค่าปรับที่ยังต้องเก็บ โดยอ่านยอดรับแล้วจาก JE ที่ยังมีผล
- การเพิ่มค่าปรับส่งเป็น `additionalLateFee` และบันทึกใน transaction รับเงิน พร้อมข้อมูล audit รองรับการรับเงินตรง, Draft และ QR (QR เก็บคำสั่งไว้ใน metadata แล้วบันทึกเมื่อ gateway ยืนยัน)
- ใบเสร็จใหม่อ้างอิง JE ของตนเอง ประวัติและ PDF จึงไม่ย้ายค่าปรับที่เพิ่มภายหลังไปไว้ในใบแรก รายการเก่าจับคู่เฉพาะกรณีระบุได้แน่นอนจาก payment, จำนวนเงิน และวันรับเงิน
- หากประวัติผสมเก่า/ใหม่ระบุค่าปรับของใบเก่าไม่ได้ จะไม่เดายอด และระงับการพิมพ์ PDF ใบนั้นเพื่อไม่คำนวณ VAT ผิด
- QR ที่มีการอนุโลมถูกปิดพร้อมคำแนะนำให้ใช้เงินสด/โอนและระบุผู้อนุมัติ เนื่องจาก callback ยังไม่รองรับข้อมูลอนุมัติอนุโลม

## กรณีจากภาพ

ค่างวด 6,079 บาท รับแล้ว 3,179 บาท (ค่าปรับ 100 + ลูกหนี้ 3,079):

| ครั้งถัดไป | ค่าปรับครั้งนี้ | เงินรับ | 2B |
| --- | ---: | ---: | --- |
| ไม่มีการเพิ่ม | 0 | 3,000 | Dr = Cr = 3,000 |
| พนักงานเพิ่ม 50 | 50 | 3,050 | Dr = Cr = 3,050 |

ยอดลูกหนี้ตาม JE ที่เหลือ 2,999.67 บาท และกำไรปัดเศษ 0.33 บาท รวมเป็น 3,000 บาท ค่าปรับ 100 บาทในใบเสร็จแรกยังคงเดิม

## การตรวจสอบ

- PostgreSQL แยก: preview/cron 5 เคส และ real service + JE + receipt อีก 3 เคส ครอบคลุมไม่มีค่าปรับใหม่, เพิ่ม 50, และ Draft/post เพิ่ม 50; เปลี่ยน config เป็น 250 หลังรับครั้งแรกเพื่อยืนยันว่าไม่คิดเพิ่มเอง
- API unit tests ของ payment, late fee, pending summary, QR และ receipt ผ่าน; API typecheck/build ผ่าน
- Web 238 suites / 1,630 tests ผ่าน; build และ scoped lint ผ่าน
- Browser ใช้ PaymentsPage, RecordPaymentWizard และบริการ query/preview จริง ตรวจ 0 → 50 → 0, ยอด Dr/Cr และ payload direct/draft/QR พร้อมข้อจำกัด QR อนุโลม ผ่านโดยไม่มี page error
- Browser จำลอง auth/settings และดักคำขอบันทึก/ส่ง QR ไม่ให้ถึง server; การบันทึกจริงตรวจใน PostgreSQL ทดสอบ ไม่มีการส่ง QR หรือข้อความภายนอก
