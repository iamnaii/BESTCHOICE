# หน้ารายละเอียดสินค้า (สต็อก) — รีดีไซน์แนว A + เครื่องคำนวณค่างวด BESTCHOICE | GFIN

**สถานะ:** เจ้าของเคาะ mockup แล้ว 2026-09-11 (design canvas `https://claude.ai/code/artifact/26992def-767f-4509-8705-cd8c62f675e3` v5) → ลงโค้ด
**ขอบเขต:** `/products/:id` (ProductDetailPage) + เครื่องคำนวณ GFIN ทั้งระบบ (shared calc · ตั้งค่า GFIN · preview เว็บร้าน)

## 1. ปัญหาของหน้าเดิม (จากภาพจริง + โค้ด)

1. งานหลักของหน้าคือบอกราคา/ค่างวดลูกค้า แต่เครื่องคำนวณอยู่ล่างสุด ต้องเลื่อนผ่านการ์ด 4 ใบ
2. ปุ่มเขียวหลัก 2 ปุ่มแย่งกัน (คัดลอกสรุป / แก้ไขข้อมูล) + ปุ่ม "กลับ" ไป `/products` ทั้งที่ breadcrumb ไป `/stock`
3. ข้อมูลสินค้า 13 ช่อง 3 คอลัมน์ ครึ่งหนึ่งเป็น "-"
4. ทุน/กำไรเป็นการ์ดใหญ่ 2 ใบเพื่อตัวเลข 2 ตัว
5. "ราคาในระบบเดิม (0)" โผล่ทั้งที่ว่าง
6. GFIN ไม่มีข้อมูลรุ่น = การ์ดครึ่งจอว่าง
7. เครื่องที่ **ขายผ่อนไปแล้ว** ยังโชว์เครื่องคำนวณ + ปุ่ม "ใช้ราคานี้ทำสัญญา" + "คัดลอกสรุปส่งลูกค้า"
8. breadcrumb แถบบนสุด (TopBar) โชว์ UUID แทนชื่อรุ่น (`/products` ไม่อยู่ใน map ของ TopBar)

## 2. โครงหน้าใหม่ (แนว A — ใบเสนอราคา 2 คอลัมน์)

- **หัวหน้า** (PageHeader เดิม): ชื่อ `brand model` + ป้ายสถานะ + subtitle `name · หมวด · สาขา` · ปุ่ม: หลัก 1 ปุ่ม + outline + เมนู ⋯
  - พร้อมขาย/จอง/อื่น ๆ: **คัดลอกสรุปส่งลูกค้า** (primary) · คัดลอกลิงก์ (จางเมื่อยังไม่ขึ้นเว็บ) · แก้ไขข้อมูล (manager) · ⋯ = โอนสาขา (manager + สถานะโอนได้)
  - ขายผ่อนแล้ว (`SOLD_INSTALLMENT` + มีสัญญา): **เปิดสัญญา CT-…** (primary, ไป `/contracts/:id`) · แก้ไขข้อมูล · ⋯ — ไม่มีคัดลอกสรุป/ลิงก์
  - ซ่อมแล้ว (`REFURBISHED`): ปุ่ม "นำเข้าคลังพร้อมขาย" (ReturnToStockAction เดิม) ขึ้นเป็นปุ่มหลัก
  - ตัดปุ่ม "กลับ" ออก (breadcrumb ทำหน้าที่แทน)
- **แท็บเดิม**: ข้อมูลสินค้า · รูปถ่าย (มือสอง) · ขึ้นเว็บ
- **คอลัมน์ซ้าย** (`minmax(0,1fr)`): การ์ดข้อมูลเครื่อง → ผลตรวจ QC (ย่อ) → แถบทุน/กำไร → เครื่องอื่นรุ่นเดียวกัน + โปร
- **คอลัมน์ขวา** (420px, `lg:sticky`): การ์ดราคาขาย → การ์ดคำนวณค่างวด (หรือการ์ดสัญญาเมื่อขายผ่อนแล้ว)
- จอแคบกว่า `lg` ยุบเป็นคอลัมน์เดียว **คอลัมน์ขวาขึ้นก่อน**

### 2.1 การ์ดข้อมูลเครื่อง
- แถวบน: รูป (มือสอง = รูปหน้าจาก 6 มุม, อื่น ๆ = placeholder) · `brand model` · ชิป (ความจุ · สี · หมวด · เกรด · แบต% · ประกันร้าน) · IMEI/Serial mono + ปุ่มคัดลอก (`useCopyToClipboard`)
- มือสอง: แถบรูป 6 มุม (`GET /products/:id/photos`) + ลิงก์ไปแท็บรูปถ่าย
- ตาราง 4 คอลัมน์ ช่องว่างโชว์ "—" (มือสองเพิ่ม แบต/ประกันศูนย์/กล่อง/เกรด; อุปกรณ์เสริมใช้ชุดฟิลด์ของ ACCESSORY เหมือน ProductInfo เดิม)
- ป้ายในหัวการ์ด: หมวด · สาขา

### 2.2 แถบทุน/กำไร (`canSeeCost` เท่านั้น)
`ต้นทุน X · กำไร Y (Z% ของราคาผ่อน)` บรรทัดเดียว มีไอคอนกุญแจ — สูตรกำไรเดิม (ราคาผ่อนถ้ามี ไม่งั้นราคาสด − ทุน)

### 2.3 การ์ดราคาขาย
ราคาเงินสด (primary, ใหญ่) · ราคาผ่อน (ตั้งต้น) · ป้าย "เติมอัตโนมัติจากตารางราคากลาง" · ลิงก์ "แก้ราคา" (manager) · บรรทัดสถานะขึ้นเว็บ (จาก readiness: พร้อม = ✓ "ขึ้นเว็บแล้ว · ลิงก์ส่งลูกค้าใช้ได้", ไม่พร้อม = ✕ + เหตุผลแรกที่ยังไม่ผ่าน) + ลิงก์ไปแท็บขึ้นเว็บ · "ราคาในระบบเดิม (N)" เป็นลิงก์เล็กเปิด Popover **เฉพาะเมื่อ N > 0** · คำเตือน fallback เดิมคงไว้

### 2.4 การ์ดคำนวณค่างวด (การ์ดเดียว แทน BcCalculatorCard + GfinCalculatorCard)
- แสดงเฉพาะ `PHONE_NEW` / `PHONE_USED` / `TABLET` และเครื่องที่ยังไม่ขาย · ไม่มีราคาผ่อน → กล่องเตือนเดิม
- **สวิตช์ BESTCHOICE | GFIN** บนสุด (segmented) · GFIN ไม่มีข้อมูลรุ่น → ปุ่ม GFIN จาง กดไม่ได้ + label "ไม่มีข้อมูลรุ่นนี้"
- **ฝั่ง BESTCHOICE**: dropdown งวด (ตัวเลือก "N งวด · ผ่อนเดือนละ X" คิดจากดาวน์ปัจจุบัน) · เงินดาวน์ (ขั้นต่ำจาก config) · กล่องผลลัพธ์ "ค่างวด BESTCHOICE X ฿/เดือน · ดาวน์ · ยอดจัด · งวด" · รายละเอียดพับได้ (ดอกเบี้ย · คอม [ซ่อนจาก SALES] · VAT · รวม) · บรรทัดเทียบ GFIN งวดเดียวกัน (ถ้ามี) + "สลับไปดู" · ปุ่ม "ใช้ราคานี้ทำสัญญา" (role เดิม) · หมายเหตุว่าสรุปส่งลูกค้าใช้ค่าที่เลือกอยู่
- **ฝั่ง GFIN** (ชื่อช่องตามหน้าขอสินเชื่อของ GFIN): ดาวน์ (%) dropdown ขั้นละ 5% จากขั้นต่ำถึง 80% พิมพ์ทับได้ · จำนวนเงินดาวน์ (sync) · **กล่อง "ดาวน์ที่แจ้ง GFIN → ลูกค้าจ่ายดาวน์จริง"** (กติกาเจ้าของ: ส่วนต่างราคาส่งสูงสุด − ราคาผ่อนที่ต้องการ มาลดดาวน์) · % คอมมิชชั่น dropdown (ค่าตั้งต้นตามหมวด: มือถือ 15 · iPad 5; ซ่อนจาก SALES) · ผ่อนได้สูงสุด (อ่านอย่างเดียว จากตาราง) · ผ่อนชำระ dropdown "N งวด · ผ่อนเดือนละ X" · กล่องผลลัพธ์ "รวมเงินผ่อนต่องวด (ปัดขึ้นเป็นบาท)" · รายละเอียด (ราคาส่ง = ราคากลาง + OVER · ส่วนลดดาวน์ · ดาวน์ตามสูตร · ดาวน์จริง · ยอดจัดหลังหักดาวน์ · เรท · ยอดจัด×เรท · ค่าล็อกเครื่อง/งวด · รวม N งวด) · **แผงเฉพาะร้านค้า** (ซ่อนจาก SALES): ค่าคอมสุทธิ = ยอดจัด × %คอม · ค่าทำสัญญา 100 · ยอดโอนให้ร้านสุทธิ = ยอดจัด + คอม − 100 · ร้านรับรวม = ดาวน์จริง + ยอดโอน · บรรทัดเทียบ BESTCHOICE · ไม่มีปุ่มทำสัญญา
- state ของสองฝั่งจำแยกกัน สลับไปมาไม่หาย · state ยกขึ้นหน้า (index.tsx) เพื่อให้ "คัดลอกสรุปส่งลูกค้า" ใช้ค่าที่เลือกอยู่

## 3. เครื่องคำนวณ GFIN — ให้ตรงหน้าคำนวณสินเชื่อ/ขอสินเชื่อของ GFIN

อ้างอิง: โค้ดหน้า `client.gfinn.xyz/shop/calculation` (chunk `app/shop/(private)/calculation/page-*.js`) + ภาพหน้าขอสินเชื่อ + ตารางราคา GFIN ประกาศ 15 ส.ค. 2569 + คำยืนยันเจ้าของ

**สูตรของ GFIN**
- ยอดจัดหลังหักดาวน์ `F = ราคาส่ง − เงินดาวน์`
- รวมเงินผ่อนต่องวด `M = ceil(F × rate(months, commission%)) + deviceLockFee 100`
- ค่าคอมมิชชั่นสุทธิ `= F × commission%` (ยืนยันจากภาพ 16,500 × 15% = 2,475)
- ยอดโอนให้ร้านสุทธิ `= F + คอม − ค่าทำสัญญา 100` (16,500 + 2,475 − 100 = 18,875)
- เรทขึ้นกับ (จำนวนงวด, % คอมมิชชั่นที่ร้านเลือก) · ดาวน์ขั้นต่ำเป็นค่าต่อร้าน (ในภาพ 25%) สูงสุด 80% ขั้นละ 5%

**กติกาของร้าน (เจ้าของ 2026-09-11)**
- ราคาส่งสูงสุด = ราคากลางรุ่นนั้น (ราคามือ 1/มือ 2) + OVER · ส่งที่ราคาสูงสุดเสมอ
- ส่วนต่าง (ราคาส่งสูงสุด − ราคาผ่อนที่ต้องการ) เอามาลดดาวน์ให้ลูกค้า: `ดาวน์จริง = max(ดาวน์ตามสูตร − ส่วนต่าง, 0)` (= `downDiscount`/`downAmountActual` ที่ `calcGfinInstallment` ทำอยู่แล้ว)
- ราคาผ่อนที่ต้องการ > ราคาส่งสูงสุด → ไม่มีส่วนลด และร้านได้น้อยกว่าราคาผ่อน → UI เตือน (warning)
- % คอมมิชชั่นตามหมวด: มือถือ 15 · iPad 5 (ผู้จัดการแก้รายเครื่องได้)

**สิ่งที่ต้องเพิ่มในระบบ**
| เรื่อง | เดิม | ใหม่ |
|---|---|---|
| ตารางเรท | `gfin_rate_factors` unique(`months`) | + `shop_commission_pct` (Int, default 15) · unique(`months`, `shop_commission_pct`) · แถวเดิม = คอม 15 |
| ผ่อนสูงสุดต่อซีรีส์/สภาพ | ไม่มี | `gfin_overprice_rules.max_months Int?` (กฎ OVER มีอยู่แล้วต่อซีรีส์+สภาพ; `allowance` 0 ได้เพื่อใส่แค่เพดานงวด) |
| การปัด | `round2` | ค่างวด = `ceil` เป็นบาท (ตาม GFIN) — ตัวอย่างเดิมในเทส (2,923) ยังตรง |
| ดาวน์ขั้นต่ำ | ตายตัว 0.30 | SystemConfig `gfin.minDownPct` (default 25) · UI dropdown ขั้นละ 5 ถึง 80 |
| คอมตามหมวด | ไม่มี | SystemConfig `gfin.commissionPct.PHONE` (15) · `gfin.commissionPct.TABLET` (5) |
| iPad | `findGfinMapping` รับแค่ PHONE_* | รับ `TABLET` → condition `HAND_1` |
| ผลลัพธ์ฝั่งร้าน | ไม่มี | `shopCommissionAmount` · `contractFee` (100) · `netTransferToShop` · `shopTotalReceived` |
| endpoint ค่าตั้งค่า | — | `GET /gfin-config/settings` → `{ minDownPct, maxDownPct: 80, downStepPct: 5, contractFee: 100, commissionPctByCategory }` (ทุก role) · `PATCH` (OWNER) |

ผู้เรียก `calcGfinInstallment` ที่ต้องตามไปแก้: `apps/web` (การ์ดใหม่) · `apps/api/src/modules/shop-catalog/installment-preview.service.ts` (เลือกเรทด้วยคอมตามหมวด) · เทส shared/api

## 4. API: `GET /products/:id` เพิ่ม `activeContract`
```
activeContract: null | {
  id, contractNumber, status, createdAt,
  customerName,               // ชื่อลูกค้า (ไม่ส่งเบอร์/บัตร)
  salespersonName,
  sellingPrice, downPayment, totalMonths, monthlyPayment,
  paidInstallments, nextDueDate  // จาก Payment: นับ status PAID · งวดถัดไป = dueDate ต่ำสุดที่ยังไม่ PAID
}
```
- ดึงเฉพาะเมื่อ `status === SOLD_INSTALLMENT` (query แยกใน `findOne` ไม่แตะ `productInclude` ที่ list ใช้ร่วม) · สัญญาล่าสุดที่ `deletedAt null` และสถานะไม่ใช่ `DRAFT`/`CANCELED`
- ผ่าน `omitCostPrice` เหมือนเดิม (ไม่มีต้นทุนในก้อนนี้)

## 5. คัดลอกสรุปส่งลูกค้า
- ใช้ค่าที่เลือกอยู่ในเครื่องคำนวณ (งวด/ดาวน์ของ BESTCHOICE) แทน `computeDefaultBcInstallment` (ยังใช้เป็น fallback เมื่อการ์ดยังไม่โหลด)
- บรรทัดผ่อนใช้รูปแบบเดียวกับสติกเกอร์/บอท (สคริปต์ขาย: ห้ามเอ่ยชื่อไฟแนนซ์/ดอกเบี้ย/%):
  - `เรทที่ 1 ดาวน์ 2,985 บาท ผ่อนเดือนละ 1,838.26 บาท 12 งวด`
  - `เรทที่ 2 ดาวน์ 1,900 บาท ผ่อนเดือนละ 3,327 บาท 12 งวด` — แนบเมื่อ GFIN ใช้ได้กับรุ่นนี้ (คำตอบ "ok" ของเจ้าของ) โดยใช้งวด/ดาวน์ที่เลือกอยู่ฝั่ง GFIN
- **เปลี่ยนข้อความบรรทัดเดิม** ("ผ่อน 12 งวด ดาวน์ … งวดละ …") เป็นรูปแบบ "เรทที่ 1 …" — แจ้งเจ้าของใน PR ให้ veto ได้
