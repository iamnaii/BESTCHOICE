# ตรวจความแน่นของหน้าจอมือถือ

รอบต่อจากการเปลี่ยน Noto Sans Thai Looped ตาม [แผนปรับมือถือ](../../superpowers/plans/2026-10-14-mobile-density.md) ใช้ UI UX Pro Max ประกอบการเลือกขนาดพื้นที่แตะและระยะห่าง ตรวจภาพหน้าจอ 320px ของ 30 หน้าตัวแทน แล้วจำลองอาการกับโค้ดปัจจุบันก่อนแก้

## จุดที่พบและแก้

| จุด | อาการเดิม | หลังปรับ |
| --- | --- | --- |
| รายได้อื่น | ขอบหน้าซ้อนกัน ทำให้เหลือพื้นที่เนื้อหา 240px บนจอ 320px; ชื่อสถานะแตกหลายบรรทัดและเบียดไอคอน | คืนพื้นที่เป็น 288px แยกชื่อสถานะออกจากแถวจำนวน ลบชื่อสถานะอังกฤษที่ซ้ำ รองรับจำนวนยาวโดยไม่ตัดตัวเลขหรือไอคอน |
| จดหมาย | หัวข้อถูกปุ่มส่งออกบีบจนเป็นหลายบรรทัด | วางหัวข้อและปุ่มคนละแถวบนมือถือ ใช้พื้นที่ขอบเดียวกับหน้าอื่น |
| รับซื้อ / แถบเครื่องมือตารางร่วม | ปุ่มเลือกคอลัมน์บีบช่องค้นหาและตัวกรอง | ให้ส่วนค้นหาและตัวกรองเต็มแถวบนมือถือ ตัวเลือกคอลัมน์อยู่แถวถัดไป ปุ่มแบ่งกลุ่มรับซื้อสูงอย่างน้อย 44px |
| ลูกค้า | การ์ดตัวนับหกใบกินพื้นที่ก่อนถึงช่องค้นหา | ลดช่องว่างในการ์ดและระหว่างการ์ดบนมือถือ ยังคงหกตัวกรอง ชื่อ จำนวน และสถานะที่เลือก |
| ค่าใช้จ่าย | ชื่อหน้ายาว มีชื่อโมดูล/เวอร์ชันและชื่อผู้ใช้ซ้ำ; ช่องค้นหาจัดแถวไม่เหมาะกับจอเล็ก | ใช้ชื่อ “ค่าใช้จ่าย” พร้อมคำอธิบายสั้น จัดช่องค้นหาคู่ปุ่มตัวกรอง และเชื่อมปุ่มหัวหน้า “เจ้าหนี้คงค้าง” / “สรุปรายวัน” ที่เดิมไม่มีการทำงานเข้าปลายทางที่มีอยู่ |
| หน้าร้าน | ชื่อรุ่นถูกเลขเครื่องบีบ ปุ่มตัวกรองเตี้ย ปุ่มดูเครื่องไม่ตรงกัน และปุ่มแชทลอยบังราคา | แยกเลขเครื่องออกจากชื่อรุ่น จัดปุ่มท้ายการ์ดตรงกัน เพิ่มพื้นที่แตะเป็น 44px ลดขอบส่วนแนะนำบนมือถือ และซ่อนปุ่มแชทลอยเฉพาะรายการสินค้าบนมือถือ |

การติดต่อ LINE ยังอยู่ในท้ายหน้าร้านและปุ่ม “ทักแชทถามเครื่องนี้” ในหน้ารายละเอียด ปุ่มลอยบนเดสก์ท็อปและหน้าอื่นยังทำงานเดิม ไม่มีการเปลี่ยนฟอนต์เอกสาร สีแบรนด์ สูตรการเงิน สิทธิ์ หรือความหมายของตัวกรอง

## การตรวจ

- ตัวตรวจจับอาการเดิมได้ครบหกกลุ่มก่อนแก้
- หลังแก้ ตัวตรวจเฉพาะความแน่นผ่าน 50 route/width/theme states: 5 หน้าแอดมินที่ 320/375/390/430px ทั้งสองธีม และ 1440px; หน้าร้านอีกห้าขนาดจอ
- ตรวจช่องค้นหา พื้นที่ชื่อสถานะ หัวข้อ พื้นที่แตะ การเลือกตัวกรอง สลับราคาสด/ผ่อน การจัดแนวปุ่ม และไม่ล้นหน้าจอ พร้อมยอดจำนวนจำลอง 1,234,567 รายการ
- ผู้ตรวจอิสระตรวจจำนวนถึง 123,456,789 และแก้ข้อพบเรื่องไอคอนถูกตัดกับแถวเครื่องมือว่างแล้ว ไม่มีข้อค้างจาก review
- component tests ที่เกี่ยวข้องผ่าน 65 รายการ; catalog/filter/warranty browser tests เดิมผ่าน 4 รายการ
- เอกสารจริงสาม renderer × screen/print เทียบก่อน–หลังแล้วหกกรณีตรงกัน
- inventory ผ่านครบ 269 รายการหน้า × 320/390px × สองธีม รวม 538 route/width states และ 1,076 ภาพ ไม่พบรายการ REVIEW ตามเกณฑ์ฟอนต์ การโหลด และการล้นของตัวตรวจ ใช้ API จริงกับฐานข้อมูลทดสอบแยกและข้อมูลจำลอง
- `npm run local:check` รอบปิดงานผ่าน 39 ขั้นตอน รวม type check, lint, build, unit tests (แอป 3,326 / shared 149 / หน้าร้าน 46) และ flow ที่รองรับในพรีวิวบนเดสก์ท็อป/มือถือ ดู [ผลตรวจรวม](local-check.json) และ [สรุปหลักฐาน](verification.json)

ตัวตรวจเฉพาะความแน่นวัดส่วนที่เปลี่ยนของแต่ละหน้า การตรวจข้อมูลและการโหลดหน้าจดหมายเต็มหน้าใช้ inventory ที่ต่อ API และฐานข้อมูลทดสอบแยก เนื่องจาก local preview หลักรองรับเพียงบางโมดูล

รอบตรวจรวมครั้งแรกพบข้อจำกัดของตัวทดสอบคลังไฟล์: โฟลเดอร์ทดสอบที่สะสมมี 21 รายการ จึงทำให้โฟลเดอร์ใหม่อยู่หน้าสอง แต่ตัวทดสอบเดิมค้นหาเฉพาะหน้าแรก แก้ตัวทดสอบให้ใช้ปุ่มแบ่งหน้าจริง ตรวจผลตอบกลับและการโหลดก่อนเลือกชื่อที่ตรงกัน ทดสอบเฉพาะคลังไฟล์ผ่านที่ 1440/390px และผ่าน independent review แล้ว ไม่มีการเปลี่ยนโค้ดแอปหลัง inventory มือถือรอบนี้

Source fingerprint ของ inventory และรอบตรวจรวมต่างกันเฉพาะการแก้ตัวทดสอบคลังไฟล์ดังกล่าว เปรียบเทียบ hash ของไฟล์ใน `apps/` และ `packages/` แล้วตรงกันทั้งหมด พรีวิวหลักตรงกับ fingerprint ของรอบตรวจรวมที่ผ่าน

ภาพ 1,076 ภาพเป็นหลักฐานจากตัวตรวจอัตโนมัติ การประเมินความแน่นด้วยสายตาทำกับ 30 หน้าตัวแทนและจุดที่แก้เพิ่มเติม ไม่ใช่การรับรองทุกสถานะข้อมูล ทุกสิทธิ์ หรือทุกอุปกรณ์
