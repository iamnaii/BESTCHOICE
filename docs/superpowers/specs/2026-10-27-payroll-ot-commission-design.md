## 1. เจตนาและเหตุผล

ระบบลงเวลา (ก้อน 10) เก็บชั่วโมง OT ต่อคนต่อวันได้แล้ว แต่ใบเงินเดือนยังให้คนพิมพ์ยอด OT เองเป็น "รายได้พิเศษ" และค่าคอมพนักงานขายจ่ายแยกนอกใบเงินเดือนโดย**ไม่ลงบัญชีและไม่หักภาษี**เลย ก้อนนี้ต่อสองอย่างเข้าใบเงินเดือนเดิม:

- OT / ทำงานวันหยุด คิดจากระบบลงเวลาอัตโนมัติ ตามสูตรเจ้าของ `ชั่วโมง × อัตรา × (เงินเดือน ÷ 30 ÷ 8)`
- ค่าคอมที่อนุมัติแล้วเข้าใบเงินเดือนเป็นรายการ จ่ายพร้อมเงินเดือน ลงบัญชีและเข้าฐาน ภ.ง.ด.1 ตามใบเงินเดือนที่มีอยู่
- สลิปกระดาษ A4 ที่มีอยู่แล้วแต่ไม่มีทางเข้า เปิดใช้ได้จริง และแสดงที่มาของ OT/ค่าคอม

**ความสำเร็จ:** สิ้นเดือนผู้ทำเงินเดือนกด "ดึง OT และค่าคอมงวดนี้" ครั้งเดียว ได้ยอดที่ถูกต้องและตรวจสอบย้อนได้ ไม่มีค่าคอมจ่ายซ้ำ และข้อมูลลงเวลาของเดือนที่จ่ายแล้วแก้ไม่ได้

## 3. เป้าหมาย / ไม่ทำ / ห้ามเกิด

**เป้าหมาย**
1. ปุ่ม "ดึง OT และค่าคอมงวดนี้" ในฟอร์มใบเงินเดือน เติมแถวรายได้พิเศษที่ระบบสร้าง (ล็อก แก้มือไม่ได้) + รายการค่าคอม + สรุปลงเวลา + รายการที่ต้องตรวจ
2. server คิดยอดเองทุกครั้งที่บันทึก/ลงบัญชี — ไม่เชื่อตัวเลขจากหน้าเว็บ
3. ค่าคอมหนึ่งรายการอยู่ได้ในใบเงินเดือนที่ยังมีผลเพียงใบเดียว · POST = ค่าคอมเป็น PAID · VOID = กลับเป็น APPROVED
4. วันลงเวลาของ (คน, เดือน) ที่อยู่ในใบเงินเดือน POSTED แก้ไม่ได้
5. สลิป A4 พิมพ์ได้จากหน้ารายละเอียดใบเงินเดือน แสดง "ชั่วโมง × อัตรา" และรายการค่าคอม

**ไม่ทำในก้อนนี้**
- หักเงินสาย/ขาด/ลาไม่รับค่าจ้าง (D1)
- ปฏิทินวันหยุดตามประเพณี/วันหยุดนักขัตฤกษ์ (ร้านเปิดทุกวัน หยุดสัปดาห์ละ 1 วันสลับ — วันหยุดในระบบ = `dayKind DAY_OFF`)
- OT อัตโนมัติของพนักงานรายวัน/สัญญาจ้าง (D4) · ใบเงินเดือนที่ฐานเงินเดือนเป็น 0
- ตั้งค่าใช้จ่ายค่าคอมค้างจ่าย ณ วันขาย (รอฝ่ายบัญชี คำถาม A3)
- สิทธิ์ BM ทำใบเงินเดือน (เดิมเลือกพนักงานไม่ได้ — แยกเป็นงานต่างหาก)
- เปลี่ยนวิธีแนะนำ WHT (×12) และฐานประกันสังคม (คงฐานเงินเดือนอย่างเดียว) จนกว่าฝ่ายบัญชีตอบ

**ห้ามเกิด (anti-goals)**
- ค่าคอมจ่ายซ้ำ (ใบเงินเดือน + ปุ่มจ่ายเก่า + ใบจ่ายคอมรายเดือน)
- OT ของคนเดียวกันเดือนเดียวกันถูกดึงเข้าสองใบ (สองสาขา/สองฝั่ง)
- ยอด OT บนใบไม่ตรงข้อมูลลงเวลาตอนลงบัญชี โดยไม่มีใครรู้
- ส่งสลิปทาง LINE/อีเมล

## 5. การคิดเงิน (ฟังก์ชันบริสุทธิ์ตัวเดียว ใช้ทั้ง บันทึก / ส่งขออนุมัติ / อนุมัติ-ลงบัญชี)

อัตราต่อชั่วโมง `h = EmployeeProfile.baseSalary ÷ 240` (= ÷30 ÷8) **ไม่ปัด** — ใช้เงินเดือนเต็มเดือนในทะเบียน ไม่ใช่ฐานในบรรทัด (คนเข้า/ออกกลางเดือนถูกพิมพ์ฐานตามวัน ถ้าใช้ฐานในบรรทัด อัตรา OT จะต่ำกว่า ม.61) · ทะเบียนเปลี่ยนหลังดึง = ยอดคิดใหม่ไม่เท่า → 409 ตาม §8 (คำตัดสินผม §15)

| แถว (source) | ชั่วโมงมาจาก | ยอด | บัญชี (ค่าเริ่มต้น) |
|---|---|---|---|
| `ATTENDANCE_OT` OT วันทำงาน | Σ `otHours` ของแถว `dayKind = WORK` และ `LEAVE_*` ที่มีการตอก (ลาแล้วมาทำงาน = วันทำงาน) | `h × 1.5 × ชม.` | role `shop_payroll_overtime` (S52-1202) / `payroll_overtime` (53-1103) |
| `ATTENDANCE_HOLIDAY` ทำงานวันหยุด (เวลางานปกติ) | แถว `DAY_OFF` / `SHOP_CLOSED` ที่มีการตอก: นาทีที่อยู่ในช่วงเวลางาน [workStart, workEnd] − พัก 60 นาทีเมื่ออยู่ในช่วงงาน ≥ 5 ชม. → ปัดตามตาราง 15/45 → เพดาน 8 ชม. | `h × 1 × ชม.` | บัญชีเดียวกับ OT (รอฝ่ายบัญชี A5) |
| `ATTENDANCE_HOLIDAY_OT` OT วันหยุด | `otHours` ของแถว `DAY_OFF` / `SHOP_CLOSED` | `h × 3 × ชม.` | บัญชีเดียวกับ OT |
| `COMMISSION` ค่าคอม | Σ `commissionAmount` ของรายการที่ดึง (ดู §6) | ตามยอด | S51-1101 "ค่าคอมพนักงานขายสาขา" (SHOP เท่านั้น — รอฝ่ายบัญชี A3) |

- ปัดเงิน **ครั้งเดียวต่อแถวต่อคนต่อเดือน** HALF_UP 2 ตำแหน่ง (`ชม.` รวมทั้งเดือนก่อน แล้วคูณ) · ตัวอย่างเงินเดือน 15,000: `h = 62.5` · OT 1.5 ชม. = 140.63 · OT วันหยุด 2 ชม. = 375.00 · ทำงานวันหยุด 8 ชม. = 500.00
- ชั่วโมงเก็บใน `quantity` · อัตราต่อชั่วโมงหลังคูณเท่า (`h × multiplier`, ไม่ปัด) เก็บใน `rate` · สลิปพิมพ์ "2 ชม. × 93.75" (แสดงอัตราปัด 2 ตำแหน่ง ยอดใช้ค่าที่คำนวณจาก `rate` เต็ม)
- `isTaxable = true` ทุกแถวระบบ (เงินได้ ม.40(1) — รอฝ่ายบัญชี A2) · ฐานประกันสังคมคงเป็นฐานเงินเดือนอย่างเดียว (รอ A1)
- **ไม่คิดอัตโนมัติ** เมื่อ `EmployeeProfile.employmentType ≠ MONTHLY` หรือ `EmployeeProfile.baseSalary` ว่างหรือเป็น 0 (D4) → ไม่สร้างแถว แต่ส่งชั่วโมงและคำเตือน "พนักงานรายวัน/ไม่มีฐานเงินเดือนในทะเบียน — กรอก OT เอง"
- ข้อมูลลงเวลาอ่านตรงจาก `attendanceDay` **ทุกสาขา** ของ userId ในเดือน (`dbDate(bangkokMidnight(...))`) — ไม่ผ่าน controller/boundary ของลงเวลา · รวมตาม userId (ไม่ใช่ตามสาขา)
- แถวที่มีธง `MISSING_OUT` ได้ OT 0 อยู่แล้ว (กติกาลงเวลา) — เข้า "รายการที่ต้องตรวจ" ให้ผู้จัดการแก้เวลาออกก่อนดึง

## 6. ค่าคอม

- ดึงเฉพาะ `SalesCommission` ของ `salespersonId = userId` · `status = APPROVED` · `period ≤ งวดของใบ` (ค่าคอมที่อนุมัติค้างจากเดือนก่อนเข้าได้) · `deletedAt null` · ไม่ผูกกับใบเงินเดือนที่ยังมีผล
- ไม่ดึง `PENDING` (ยังไม่อนุมัติ) · `CLAWED_BACK` / `PARTIALLY_CLAWED_BACK` (รอเจ้าของตัดสินภายหลัง) · ใบเงินเดือนฝั่ง `FINANCE` ไม่ดึงค่าคอม (บล็อกพร้อมข้อความ — รอฝ่ายบัญชี A7)
- ตารางใหม่ `PayrollCommissionItem { id · payrollLineId (Cascade) · salesCommissionId · amount Decimal(12,2) · releasedAt? · createdAt }` + **partial unique** `(sales_commission_id) WHERE released_at IS NULL` (SQL ใน migration) ⇒ ค่าคอมหนึ่งรายการอยู่ได้ใบเดียว · แก้ร่าง (ลบ/สร้างบรรทัดใหม่) = cascade · VOID = ตั้ง `releasedAt`
- POST ใบเงินเดือน (ใน tx ของ post): รายการที่ผูก → `PAID` · `paidAt = documentDate` · `paidAmount = amount` · VOID: กลับเป็น `APPROVED` · ล้าง `paidAt/paidAmount` · `releasedAt = now`
- หน้า `/commissions`: ปุ่ม "อนุมัติ" ใช้ได้ (**แก้บั๊ก**: เว็บเรียก `PATCH /commissions/:id/approve` แต่ API เป็น `@Post` → 404 · `CommissionsPage.tsx:114,126`) · ถอดปุ่ม "จ่าย" รายแถว · ป้ายสถานะ "อยู่ในใบเงินเดือน PR-…" · API `POST /commissions/:id/pay`, `POST /commissions/payouts/generate`, `PATCH /commissions/payouts/:id/paid` → **410** "จ่ายค่าคอมผ่านใบเงินเดือนเท่านั้น — สร้างใบเงินเดือนที่หน้ารายจ่าย › สร้างเอกสารใหม่ › เงินเดือน (PR) ระบบดึงค่าคอมที่อนุมัติแล้วให้เอง" (ชื่อเมนูจริงต่างตาม role: "บันทึกรายจ่าย" / "ค่าใช้จ่ายดำเนินงาน" / "รายจ่าย" ⇒ ใช้คำว่า "หน้ารายจ่าย" · ปุ่มจริง "สร้างเอกสารใหม่" › "เงินเดือน (PR)") · ใบจ่ายคอมรายเดือนเดิมเหลือดูอย่างเดียว
- `markPayoutPaid` / `generatePayouts` เดิมรวมแถว PENDING/PAID และไม่อัปเดตแถวข้างใน (บรีฟ §2 ข้อ 10) — ปิดด้วย 410 ข้างบน ไม่ต้องซ่อม
- **ค่าคอมเก่าไม่มีให้จ่ายซ้ำ** (ตรวจ prod 27/10): `sales_commissions` 8 แถว + `commission_payouts` 1 ใบ (DRAFT) เป็นข้อมูลทดสอบที่ถูกลบแล้วทั้งหมด · ใบเงินเดือน 0 ใบ ⇒ ไม่ต้อง migration · กันไว้อีกชั้น: ไม่ดึงแถวที่อยู่ในใบจ่ายรายเดือนที่ไม่ใช่ร่าง (ตัวตรวจเดียวกับด่าน G4b ของยกเลิกใบขาย — ห้ามเขียนชุดที่สอง)
- ร่างที่ถูก soft delete ไม่ cascade ⇒ ต้องตั้ง `releasedAt` ของ `PayrollCommissionItem` เองใน tx เดียวกัน · VOID คืนสถานะแบบมีเงื่อนไข (`updateMany where status = PAID` — แถวที่ถูกเรียกคืนไปแล้วไม่ถูกตั้งกลับเป็น APPROVED)

## 6ข. หักคืนค่าคอมที่จ่ายแล้ว (D7)

- **ที่มาของยอดเรียกคืน** (ค่าคอมที่ `PAID` ผ่านใบเงินเดือนแล้วเท่านั้น): (ก) รอบเรียกคืนรายวันเดิม `commission-clawback.cron.ts` (ผิดนัดเร็ว — ตั้ง `clawbackAmount` / `clawbackPercent` อยู่แล้ว) (ข) ยกเลิกใบขาย `SaleVoidService` — ด่าน G4 เปลี่ยนจาก "บล็อกเมื่อค่าคอมจ่ายแล้ว" เป็น "เปลี่ยนเป็น `CLAWED_BACK` เต็มยอดที่จ่ายใน tx เดียวกับการยกเลิก" (ค) คืนเครดิตเทิร์น `credit-contract-cleanup.util.ts` — เลิก throw "ต้องเรียกคืนค่าคอมก่อน" ใช้กติกาเดียวกับ (ข) · ~~(ง) ยกเลิกสัญญา~~ **ไม่เปลี่ยน** — `contract-commission.util.ts` คงคำตัดสินเจ้าของ 20/09 (เรียกคืนเฉพาะค่าคอมที่ยังไม่จ่าย) · ทุกทางเขียน `clawbackAmount` / `clawbackAt` / `clawbackReason` ผ่าน **helper ตัวเดียว** (ห้ามเขียนชุดที่สอง) · ค่าคอมที่ยังไม่จ่าย (PENDING/APPROVED) ใช้กติกาเดิมของแต่ละทาง (ยกเลิก/ลบได้เลย)
- **ใบเงินเดือนงวดถัดไป:** ปุ่ม "ดึง OT และค่าคอมงวดนี้" เติมแถวหัก `source = COMMISSION_CLAWBACK` (ล็อกแบบแถวจากระบบ) ต่อพนักงาน = Σ ยอดเรียกคืนที่ยังไม่ถูกหัก · ผูกทีละรายการกันหักซ้ำ (partial unique แบบเดียวกับ §6 — ใช้ตารางเดียวกับ `PayrollCommissionItem` แยกด้วยชนิด PAY / CLAWBACK ได้) · POST = รายการหักถูกปิด (`deductedAt`) · VOID = ปลดกลับไปรอหัก
- **เพดาน (คำตัดสินผม — ป.คุ้มครองแรงงาน ม.76):** ค่าคอมเป็น "ค่าจ้าง" (ม.5 — เงินที่จ่ายตามผลงาน) และ ม.76 ห้ามหักค่าจ้างนอกเหตุที่กฎหมายกำหนด ⇒ **หักได้ไม่เกินค่าคอมของงวดนั้นของคนนั้น** (หักกลบค่าคอม ไม่แตะเงินเดือนฐาน/OT) · ส่วนที่เกิน **ยกไปงวดถัดไป** แสดงบนใบและสลิป "ยกไปงวดหน้า n บาท" · ลาออกแล้วยังเหลือ = ขึ้นรายการค้างให้เจ้าของตัดสินเอง (ไม่หักอัตโนมัติ) · ถามฝ่ายบัญชี/กฎหมายยืนยัน A9
- **บัญชี:** แถวหักลง Cr บัญชีค่าคอมเดียวกับตอนจ่าย (S51-1101 — ลดค่าใช้จ่าย ไม่ใช่รายได้) ผ่านรายการหักของ `PayrollTemplate` เดิม (V19 ตรวจรหัสอยู่แล้ว) · ฐาน ภ.ง.ด.1 ของงวด = รายได้ − ค่าคอมที่หักคืน (A9)
- **หน้าค่าคอม:** ป้าย "เรียกคืน — รอหักในใบเงินเดือน" → "หักคืนแล้วในใบ PR-…" · ยกเลิกใบขายได้ตามปกติ ข้อความหลังยกเลิกบอก "ค่าคอม n บาทที่จ่ายแล้วจะหักในเงินเดือนงวดถัดไป"

## 8. ลำดับการทำงานและ API

1. ผู้ทำเงินเดือนเลือกสาขา · ฝั่ง · งวด · พนักงาน (หรือคัดลอกงวดก่อน — **ข้ามแถว source ≠ MANUAL**)
2. **(แทนที่โดย §17 — ไม่มี endpoint prefill · ปุ่มคือ "บันทึกร่าง + คิดยอด" ซึ่งบันทึกร่างแล้วแสดงยอดที่ระบบคิด)** ~~กด **"ดึง OT และค่าคอมงวดนี้"**~~ → `POST /expense-documents/payroll/prefill { branchId, entityScope, payrollPeriod, userIds[] }` (roles เดียวกับสร้างใบเงินเดือน · ลง manifest) คืนต่อคน: `systemIncome[]` (source, ชื่อ, ชม., อัตรา, ยอด, บัญชี) · `commissionItems[]` (เลขสัญญา/ใบขาย, วันที่, ยอด) · `attendanceSummary` · `review[]` (วัน + ธง: MISSING_OUT, DEVICE_CONFLICT, DEVICE_UNAVAILABLE, AFTER_PIN_LOCKOUT, LOCATION_CHANGED, NETWORK_CHANGED, CORRECTED, NO_PIN) · `warnings[]` (รายวัน/ไม่มีฐาน · ดึงไปแล้วในใบอื่น · ยังไม่ถึงเวลาปิดงวด)
3. แถวระบบแสดงล็อก (ป้าย "จากระบบลงเวลา" / "ค่าคอม n รายการ") · แผง "รายการที่ต้องตรวจ" กดเปิดวันนั้นที่ เมนู ลงเวลา › วันนี้ (เลือกวันที่) ได้
4. บันทึกร่าง (create/update) → server **คิดแถวระบบใหม่เองทุกบรรทัดที่ผูกพนักงาน ทุกครั้งที่บันทึก** (รวมใบจากแม่แบบ/คัดลอกงวดก่อน — §16) — client ไม่ส่งแถวระบบเลย · แถว MANUAL คงเดิม · ผูก `PayrollCommissionItem`
5. ลงบัญชี (POST) → ตรวจ (ก) ถึงเวลาปิดงวดแล้ว (D3) ถ้ามีแถวระบบลงเวลา (ข) คิดใหม่แล้ว**ต้องเท่ากับ**ที่เก็บไว้ ไม่งั้น 409 "ข้อมูลลงเวลา/ค่าคอมเปลี่ยนหลังดึง — กด ดึง OT และค่าคอมงวดนี้ อีกครั้ง แล้วตรวจก่อนลงบัญชี" (ค) ไม่มีใบอื่นที่ยังมีผลในงวดเดียวกันที่มีแถวระบบลงเวลาของคนเดียวกัน → JE `PayrollTemplate` เดิม (Dr รายบัญชีรายได้พิเศษมีอยู่แล้ว) + ค่าคอมเป็น PAID ใน tx เดียวกัน
6. **(แทนที่บางส่วนโดย §17 — ส่งขออนุมัติได้หลังเวลาปิดงวดเท่านั้น และตอนส่งระบบคิดยอดใหม่ · ส่งกลับเป็นร่าง = กด "แก้ไข" ไม่มี route ใหม่)** **ขั้นอนุมัติ (คำตัดสินผม §15):** PAYROLL ต้องอนุมัติทุกใบ (`approval_required_doc_types` ค่าเริ่มต้น `['PAYROLL']`) และ `auto_post_on_approve = true` ⇒ ด่าน (ก)(ข)(ค) ของข้อ 5 ทำงานใน `approve()` ไม่ใช่แค่ `post()`. ส่งขออนุมัติได้ทุกเวลา · ปุ่ม "อนุมัติและลงบัญชี" ปิดจนถึงเวลาปิดงวดพร้อมบอกเวลา · อนุมัติแล้วชน 409 → **ทางใหม่ `PENDING_APPROVAL → DRAFT` "ส่งกลับเป็นร่าง"** (ผู้อนุมัติกด · AuditLog หลัง commit) แล้วผู้ทำเงินเดือนดึงใหม่และส่งอีกครั้ง · ปิดขั้นอนุมัติไว้ = ใบยังเป็นร่าง กดดึงใหม่ได้ทันที · ข้อความ 409 ต้องชี้ปุ่มตามสถานะใบ (รออนุมัติ → "ส่งกลับเป็นร่าง" · ร่าง → "ดึง OT และค่าคอมงวดนี้")
7. **ด่านเครื่องถูกใช้ซ้อน (D6):** อนุมัติ (หรือลงบัญชีเมื่อปิดขั้นอนุมัติ) ถูกปฏิเสธเมื่อมีแถว `attendanceDay` ของ (คนในใบที่มีแถวระบบลงเวลา, เดือน) ที่ยังมีธง `DEVICE_CONFLICT` → 409 "อนุมัติไม่ได้ — มีวันที่ติดธง เครื่องถูกใช้ซ้อน n วัน (ชื่อ · วันที่) ให้เจ้าของตรวจที่เมนู ลงเวลา แล้วกด ตรวจแล้ว ล้างธง" (แก้เวลาโดยผู้จัดการไม่ล้างธง — `attendance.service.ts:274`) · ส่งขออนุมัติได้ (แผง "วันที่ต้องตรวจ" แสดงธงนี้สีแดงไว้บนสุด) · ธงอื่นเตือนอย่างเดียว
8. `totalAmount` ของใบ PAYROLL = ยอดก่อนหัก (ฐาน + รายได้พิเศษ) เพื่อให้เกณฑ์อนุมัติถูก (เดิม = Σฐาน) — builder ต้อง grep ผู้อ่าน `totalAmount` ของ PAYROLL ทุกตัวก่อนแก้

## 13. จุดที่เทสต้องครอบ (review focus)

1. คนเดียวสองสาขาในเดือนเดียว: OT รวมตาม userId และดึงได้ใบเดียว
2. ลงเวลาถูกแก้หลังดึงแต่ก่อน POST → 409 · หลัง POST แก้ไม่ได้
3. ค่าคอม: ใบเงินเดือน VOID แล้วดึงเข้าใบใหม่ได้ · ใบที่สองดึงซ้ำไม่ได้ (unique) · ปุ่มจ่ายเก่า/ใบจ่ายรายเดือน = 410
3ข. หักคืน: ยกเลิกใบขายที่ค่าคอมจ่ายแล้วสำเร็จ + ค่าคอมเป็น CLAWED_BACK · งวดถัดไปหักไม่เกินค่าคอมงวดนั้น ยกส่วนเกิน · หักซ้ำสองใบไม่ได้ · VOID ใบที่หักแล้วปลดกลับไปรอหัก · ธง เครื่องถูกใช้ซ้อน ค้าง = อนุมัติ 409
4. ปัดเศษ: รวมชั่วโมงก่อนแล้วปัดครั้งเดียว (15,000 × 0.5 ชม. × 3 วัน = 140.63 ไม่ใช่ 140.64) · ไม่ปัดอัตรา (16,500 × 1.5 ชม. = 154.69)
5. POST ก่อน 18:00 วันที่ 1 เดือนถัดไปของใบที่มีแถวระบบลงเวลา → ปฏิเสธพร้อมเวลาที่ทำได้
6. วันหยุด: มา 13:00–21:00 บน DAY_OFF (เวลางาน 10–19) → ทำงานวันหยุด 5 ชม. (6 ชม. − พัก 1) · OT วันหยุด 2 ชม.

1. **วันที่ยังมีธง "เครื่องถูกใช้ซ้อน" (สงสัยตอกแทนกัน) — ห้ามอนุมัติจนกว่าเจ้าของล้างธง หรือแค่เตือน?** ธงนี้ล้างได้เฉพาะเจ้าของอยู่แล้ว แต่สเปกตอนนี้จ่าย OT ของวันนั้นแล้วล็อกทันทีหลังลงบัญชี · **ค่าที่ผมแนะนำ:** ธงเครื่องชนกัน = บล็อกปุ่มอนุมัติ (ชี้ไปหน้าลงเวลาให้เจ้าของตรวจ) · ธงอื่น (ไม่มีเวลาออก / ตอกหลังพักรหัส / ผู้จัดการแก้เวลา / ตำแหน่งเปลี่ยน) = เตือนในแผง "วันที่ต้องตรวจ" อย่างเดียว
2. **ค่าคอมที่จ่ายผ่านเงินเดือนไปแล้ว ถ้าต้องเรียกคืนภายหลัง จะหักจากเงินเดือนงวดถัดไปไหม?** หลังลงบัญชีเงินเดือนครั้งแรก ค่าคอมจะเป็น "จ่ายแล้ว" จริงเป็นครั้งแรก ⇒ (ก) ยกเลิกใบขายที่ค่าคอมจ่ายแล้วถูกบล็อกถาวร (ด่าน G4 "ยังไม่มีเมนูเรียกคืนค่าคอมที่จ่ายแล้ว") (ข) คืนเครดิตเทิร์นจะล้ม "ต้องเรียกคืนค่าคอมก่อน" (ค) รอบเรียกคืนค่าคอมรายวัน (`commission-clawback.cron.ts`) จะตั้งยอดที่พนักงานต้องคืนแต่ไม่มีทางหัก · **ค่าที่ผมแนะนำ:** เพิ่มแถวหักอัตโนมัติ "หักคืนค่าคอม" ในใบเงินเดือนงวดถัดไป (ล็อกแบบแถวจากระบบ) และให้ยกเลิกใบขาย/คืนเครดิตเทิร์นเปลี่ยนค่าคอมที่จ่ายแล้วเป็น "เรียกคืน" แทนการบล็อก — ขอบเขตเพิ่มราว 1 งาน

## 16. ปรับหลังรีวิวแผน (27/10 ดึก — รีวิวแบบหาจุดพัง 3 มุม ยืนยันแล้ว 31 ข้อ)

แผน (แยกเป็น 2 ส่วนแล้ว — §17): `docs/superpowers/plans/2026-10-27-payroll-ot-part1.md` + `docs/superpowers/plans/2026-10-27-payroll-ot-part2-commission.md` หัวข้อ "Decisions" — สรุปที่เปลี่ยนจากสเปกข้างบน (ข้อที่ §17 เปลี่ยนต่อให้ยึด §17):

## 17. ปรับหลัง /scrutinize (27/10 ดึก — เจ้าของ "ok" ทั้ง 3 ข้อ)

- **แยกเป็น 2 PR**: PR-1 = OT / ทำงานวันหยุด / ด่าน / ล็อกเดือน / สลิป / หน้าลงเวลา (แผน `docs/superpowers/plans/2026-10-27-payroll-ot-part1.md`) · PR-2 = ค่าคอมผ่านเงินเดือน / หักคืน / ภาษี / หน้าค่าคอม (แผน `...-part2-commission.md`) — ระหว่างรอ PR-2 ค่าคอมยังใช้ทางเดิม (ปุ่มอนุมัติรายแถวยังพังตามเดิมจนถึง PR-2)
- **ส่งขออนุมัติได้ตั้งแต่ 18:00 วันที่ 1 ของเดือนถัดไปเท่านั้น** (ทุกใบที่มีพนักงานผูก) และตอนส่ง ระบบคิดยอดใหม่ให้ — แทน "ส่งได้ทุกเวลา" ที่ผมตัดสินไว้ (เดิมทุกใบจะถูกตีกลับเพราะยอดขยับจนถึงวันที่ 1) · ใบที่มีแต่พนักงานรายวันก็ใช้เวลาปิดงวดเดียวกัน (ไม่งั้นลงบัญชีกลางเดือนแล้วล็อกลงเวลาที่เหลือของเดือน)
- **ปุ่ม = "บันทึกร่าง + คิดยอด"** (ไม่มี endpoint ดูตัวอย่างแยก) · รายการ "วันที่ต้องตรวจ" + คำเตือนเก็บไว้ในใบ ผู้อนุมัติเห็นในหน้ารายละเอียด
- **ส่งกลับเป็นร่าง = กด "แก้ไข"** ใบที่รออนุมัติ/อนุมัติแล้วได้เลย ใบกลับเป็นร่างเอง (ไม่มีปุ่ม/route ใหม่)
- **ยกเลิกสัญญา: ค่าคอมที่จ่ายแล้วไม่เรียกคืน** (คำตัดสิน 20/09 คงเดิม)
- ล้างธง "เครื่องถูกใช้ซ้อน" ได้เสมอ แม้เดือนนั้นจ่ายแล้ว (ธงไม่เปลี่ยนตัวเงิน) — ล็อกเฉพาะการแก้เวลา/ประเภทวัน · ข้อความชี้ให้เจ้าของ "ตรวจแล้ว ล้างธง" อย่างเดียว
- ผจก.สาขาใส่ได้เฉพาะพนักงานของสาขาตัวเอง (กันย้อนคำนวณเงินเดือนคนอื่นจากอัตราต่อชั่วโมง)
- แถว OT ที่กรอกเองบนบรรทัดที่ระบบคิดให้ = ห้าม ยกเว้นติ๊ก **"รายการปรับปรุงงวดก่อน"** (ใช้แก้ OT ที่จ่ายขาดของเดือนที่ล็อกแล้ว)
- ห้ามกู้ใบเงินเดือนจากถังขยะทุกกรณี · ข้อความ error แบบมีรายละเอียด (ตารางยอดต่าง/เวลาที่ทำได้/วันติดธง) ต้องผ่านตัวกรอง error กลางได้
- ค่าคอมที่อนุมัติ**หลังส่งใบ**ไม่ทำให้ใบถูกตีกลับ — ไปเข้าใบงวดถัดไปเอง (ตีกลับเฉพาะเมื่อรายการที่อยู่ในใบแล้วเปลี่ยนหรือจ่ายไม่ได้) · หักคืนเฉพาะค่าคอมที่จ่ายผ่านใบเงินเดือนจริง ค่าคอมที่ไม่เคยจ่ายไม่มีอะไรต้องหัก
- ปุ่ม "แก้ไข" / แก้แล้วบันทึก / คัดลอกงวดก่อน / ตอนส่ง — ระบบไม่เอาแถวที่ระบบคิด (OT, ค่าคอม, หักคืน) กลับเข้ามาเป็นแถวกรอกเอง (กันหักซ้ำ)
