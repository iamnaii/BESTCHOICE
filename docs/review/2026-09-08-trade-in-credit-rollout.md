# Trade-in rollout — 8 กันยายน 2026

งานสี่ข้อที่เจ้าของอนุมัติ: ป้องกันรับซื้อซ้ำเมื่อเครือข่ายขาด, ตรวจหลักฐานก่อนรับเครื่อง, ใช้เครดิตเทิร์นซื้อสินค้า/ทำสัญญา และแก้การตรวจ CI

## พฤติกรรม

1. Quick Buy ส่ง UUID ต่อการรับซื้อหนึ่งครั้ง บันทึกผู้ทำรายการและ hash คำขอในฐานข้อมูล ส่งซ้ำด้วยข้อมูลเดิมได้รายการเดิม ข้อมูลหรือผู้ทำรายการไม่ตรงถูกปฏิเสธ หน้าจอเก็บเฉพาะ UUID ใน sessionStorage และตรวจหารายการค้างก่อนส่งใหม่ ไม่เก็บบัตร/ลายเซ็นใน storage นี้ เลขใบสำคัญจัดสรรแบบแข่งขันกันแล้วมีผู้ชนะหนึ่งราย
2. การรับเครื่องต้องมีชื่อผู้ขาย เลขบัตรที่ผ่าน checksum โทรศัพท์ ที่อยู่ และอย่างน้อย IMEI หรือ Serial หากเครื่องไม่มีอีกหมายเลขต้องระบุเหตุผล ตรวจตัวตนกับ Contact/Customer ที่เลือก หลักฐานที่ลงนามแล้วแก้ทับไม่ได้ และการเปลี่ยนหลักฐานบนหน้าจอต้องยืนยัน/ลงนามใหม่ การบันทึกร่างประเมินยังทำได้ก่อนหลักฐานครบ
3. EXCHANGE ที่รับเครื่องแล้วออกเครดิต SHOP แยกมูลค่าเครื่อง V กับโบนัสส่วนลด B ใช้เต็มยอดครั้งเดียวกับลูกค้าและสาขาเดิม ใน POS เงินสดหรือสัญญา BESTCHOICE มีการ claim และลงบัญชีใน transaction เดียวกัน หากมีการใช้พร้อมกันสำเร็จได้เพียงหนึ่งรายการ
4. CI สร้าง shared package ก่อน Jest โดยตรง เติม company grants ของบัญชี seed และส่ง grants ทั้ง login กับ /auth/me; E2E ตรวจสิทธิ์จริงครบห้าบทบาทก่อนใช้ token ปรับการตรวจ URL ให้รองรับ ?zone=shop/fin โดยยังตรวจหน้าเป้าหมาย

## ยอดและบัญชี

ตัวอย่างราคาขาย 15,000 บาท, V 5,000, B 500: ราคาสุทธิ 14,500 บาท ถ้าขายสดเก็บเพิ่ม 9,500 บาท ถ้าผ่อนและเก็บเงินสด D 2,000 บาท ดาวน์รวม 7,000 บาท เงินต้น 7,500 บาท โบนัสนับเป็นส่วนลดเพียงครั้งเดียว ไม่ใช่เงินสดรับ ใช้ Decimal จนถึงสตางค์

รับเครื่อง: Dr S11-2002 / Cr S21-2003 ตาม V การใช้เครดิตลดหนี้สิน S21-2003; สัญญาย้าย V ไปเงินรับล่วงหน้า S21-2001 และรับเงินจริงเฉพาะ D เก็บ snapshot บน Sale/Contract เพื่อรักษายอดเดิมและผูก hash เอกสาร หน้าสรุป ประวัติขาย Excel รายละเอียดสัญญา และ PDF แยกยอดและเลขอ้างอิงเครดิต

Void ขายสดหรือยกเลิกสัญญากลับรายการใช้เครดิตแล้วคืนเครดิตเดิม เก็บประวัติ redemption ที่ถูกยกเลิกไว้ ลบร่างที่รับเงินจริงแล้วคืนเฉพาะ D ส่วนยกเลิกสัญญาที่เปิดใช้งานแล้วคง D รอคืนตามขั้นตอนเดิม ไม่สร้างการคืนเงินสดจาก V

ยกเลิกสัญญาที่ใช้เครดิตลบสถานะใช้งานของใบขาย ลูกหนี้ไฟแนนซ์ และรายการระหว่างบริษัท พร้อมเรียกคืนค่าคอมที่ยังไม่จ่ายและยกเลิกร่างรอบจ่ายที่เกี่ยวข้อง หากรับเงิน/กระทบยอดหรืออนุมัติรอบจ่ายไปแล้ว ต้องกลับรายการนั้นก่อน ระบบไม่คืนเครดิตทิ้งไว้พร้อมยอดขายเดิม

รายงานประมาณการจากธุรกรรมหัก V ออกจากเงินสดรับ รวมเครดิตที่ยังไม่ใช้เป็นหนี้สินตามประวัติวันที่ และเก็บเงินดาวน์ที่ยังถือไว้หลังยกเลิกจาก journal จริง รายงาน GL ยังคงใช้ journal เดิม การคืนดาวน์ด้วย manual JV ต้องใส่ reference CONTRACT เพื่อให้รายงานแยกสัญญาได้; manual JV ที่ไม่มีอ้างอิงไม่สามารถระบุสัญญา/สาขาจากข้อความได้อย่างถูกต้อง

## ขอบเขตและการปล่อย

- ใช้เต็มยอดครั้งเดียว ไม่มี wallet แบ่งใช้ ไม่มีถอนเครดิตเป็นเงินสดอัตโนมัติ
- ไม่รองรับ EXTERNAL_FINANCE และการเปลี่ยนเครื่องภายหลังผ่าน DefectExchange/ContractExchange สำหรับสัญญาที่ใช้เครดิต ระบบปฏิเสธชัดเจนเพื่อไม่ให้เครดิต/เงินดาวน์ถูกใช้ซ้ำ
- การยกเลิกใบที่ผูก booking/online order/ของแถมต้องจัดการรายการเกี่ยวข้องก่อน ไม่ยกเลิกอัตโนมัติ
- ไม่เปลี่ยน flow/journal/คำรับรอง/หมายเลขเครื่องของข้อมูลเก่า และไม่ออกเครดิตย้อนหลังให้อัตโนมัติ
- เพิ่ม migration SHOP `20260908140000_trade_in_purchase_request`, `20260908141000_trade_in_intake_evidence`, `20260908142000_trade_in_credit_redemption` พร้อมบัญชี S21-2003 ต้องปล่อย API/shared/web ที่สอดคล้องกันและ refresh หน้ารับซื้อเก่าก่อนใช้งาน
- การตรวจหลักฐานในระบบไม่ใช่ฐานตรวจเครื่องหาย ภาพและลายเซ็นในการทดสอบเป็นข้อมูลจำลอง

## หลักฐานการตรวจ

- API regression 622 suites: 7,536 ผ่าน / 8 skipped (ข้อยกเว้นเดิม)
- PostgreSQL แยก 5 suites: 53 ผ่าน รวม retry/concurrent purchase, เครดิตใช้พร้อมกัน, rollback เมื่อ journal ล้มเหลว, ตัวตนไม่ตรง, ยกเลิกร่างทั้ง direct/POS, activation/cancellation, payout guard และเงินสด/หนี้สินในรายงาน
- AppModule จริงบนฐาน PostgreSQL ชั่วคราว: grants login + /auth/me ครบ OWNER/BM/SALES/FINANCE_MANAGER/ACCOUNTANT; browser login 6 และ sidebar/trade-in 11 ผ่าน ใช้ COMPANY scope จริง ไม่มี auth mock
- PDF ตัวอย่างใบรับเครื่องเทิร์น A4 หนึ่งหน้า: IMEI ที่ไม่มีพร้อมเหตุผล, Serial, V/B, คำรับรองและลายเซ็นอยู่หน้าเดียวกัน สัญญาตัวอย่างแปดหน้ามีตารางเครดิตบนหน้าลายเซ็นและไม่มีข้อความล้น (template สัญญาเดิม)
- ผล local และ CI ล่าสุดบันทึกหลังตรวจชุดสุดท้ายด้านล่าง
- POS browser บน AppModule จริง: รับเครื่อง EXCHANGE ผ่าน HTTP จริงแล้วเลือกเครดิตจากหน้าจอ ขาย P15,000 รับเงินเพิ่ม9,500 และ P5,500 รับเงินเพิ่ม0; ตรวจ Sale ที่บันทึกจริงและรายละเอียดในประวัติขายผ่านทั้งสองกรณี ใช้ข้อมูลจำลองและตั้งบัญชีเงินสดสาขาทดสอบ S11-1101 ก่อนขาย
