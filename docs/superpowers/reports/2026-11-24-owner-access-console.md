# หน้าพนักงานและสิทธิ์ — 24 พฤศจิกายน 2569

## ขอบเขต

พัฒนาหน้าเจ้าของที่ `/settings/access/employee-permissions` ใน worktree `feat/owner-access-console` โดยใช้บริการสิทธิ์เดิมและเพิ่ม API อ่านสำหรับหน้าจอ ไม่เปลี่ยนบัญชีหรือข้อมูลร้านจริง และไม่ merge/push/deploy

เปิดทดลอง: http://localhost:5216/settings/access/employee-permissions?zone=settings — เซิร์ฟเวอร์ยังทำงานและตรงกับ source ที่ตรวจแล้ว (`local:status`: running/current = true)

มี 3 แท็บ:

| แท็บ | การใช้งาน |
|---|---|
| พนักงาน | ค้นหาพนักงาน ดูสิทธิ์ที่ใช้ได้จากเซิร์ฟเวอร์ เทียบกับการมอบหมายที่บันทึกไว้ และแก้ตำแหน่ง/ส่วนงาน/ขอบเขต/สาขาเป็นแต่ละรายการ |
| ตำแหน่งและสิทธิ์ | สร้าง คัดลอก แก้ เปิด–ปิดตำแหน่ง ค้นหาสิทธิ์เป็นกลุ่ม ระบุสิทธิ์สงวนและข้อมูลสำคัญ ตรวจสิทธิ์ที่เพิ่ม/ถอนและจำนวนคนที่ได้รับผลก่อนบันทึก |
| ประวัติการเปลี่ยนแปลง | แสดงผู้แก้ เวลา เป้าหมาย และข้อมูลก่อน–หลัง เฉพาะเหตุการณ์สิทธิ์ พร้อมแบ่งหน้า |

การเพิ่มแม่แบบเป็นคำสั่งที่เจ้าของต้องกดเอง ไม่เขียนทับตำแหน่งเดิม ไม่สร้างการมอบหมายโดยอัตโนมัติ บัญชีเจ้าของถูกล็อกจากการแก้การมอบหมายทั้งใน UI และ API

## ข้อควรรู้ก่อนใช้กับบัญชีจริง

- สิทธิ์ตามตำแหน่งยังไม่ได้เชื่อมครบทุกขั้นตอนของระบบเดิม หน้านี้อธิบายกติกาสิทธิ์และขอบเขตตามข้อมูลปัจจุบัน ไม่ได้ยืนยันว่าเมนูและขั้นตอนงานทั้งหมดพร้อมย้ายแล้ว
- บันทึกการมอบหมายให้บัญชีที่ใช้กติกาเดิมจะเริ่มใช้ระบบตำแหน่งทันที และนำสิทธิ์ยกเว้นรายบุคคลเดิมออก หน้าตรวจผลกระทบแสดงข้อมูลและขอการยืนยันนี้อย่างชัดเจน
- `ASSIGNED` ต้องได้รับมอบหมายรายการนั้นจริงด้วย ส่วน `BRANCHES` ต้องเลือกสาขา และ `COMPANY` ให้ขอบเขตทั้งส่วนงาน การมอบหมายหลายตำแหน่งไม่ผสมตำแหน่งกับสาขาข้ามรายการ
- หน้าตั้งค่านี้ไม่เปลี่ยนสถานะเจ้าของบัญชี ไม่กำหนดเพดานอนุมัติทางธุรกิจใหม่ และไม่ย้ายพนักงานทั้งร้าน การย้ายจริงต้องตรวจความพร้อมของแต่ละขั้นตอนตามแผนสิทธิ์ฉบับใหญ่ก่อน

## การตัดสินใจระหว่างพัฒนา

- หน้าจอใหม่ต้องส่งรุ่นตำแหน่งและข้อมูลที่ยืนยันไปตรวจใน transaction เสมอ ส่วน API เดิมยังรับคำขอที่ไม่มีค่าประกอบเพื่อความเข้ากันได้ ผลแลกเปลี่ยนคือเจ้าของอาจต้องโหลดใหม่แม้อีกคนแก้เพียงชื่อตำแหน่ง
- การย้ายบัญชีทั้งร้านและการเชื่อมสิทธิ์กับงานเดิมแยกจากการทำหน้าจอนี้ หากย้ายก่อนพร้อม บัญชีอาจถูกปฏิเสธในขั้นตอนที่ยังไม่รองรับ จึงไม่ได้ย้ายหรือ deploy ในงานนี้
- คำเตือน Prisma เดิมเก็บเป็นงานอัปเกรดเครื่องมือ ไม่มีการเปลี่ยน config เพื่อกลบคำเตือน
- ผู้ประสานงานตรวจ `local:check`, browser และสถานะ server บน source สุดท้ายแล้ว ไม่ใช้ผลจากรอบก่อนแก้แทน

## ประเด็นย่อยที่ยังไม่ได้เปลี่ยน

พารามิเตอร์แบ่งหน้าถูกแปลงเป็นตัวเลขก่อนตรวจ ทำให้ข้อความทศนิยมที่ละเอียดเกินความแม่นยำของ JavaScript อาจถูกปัดเป็นจำนวนเต็มที่ยอมรับได้ แต่ขนาดหน้าที่อ่านฐานข้อมูลยังถูกจำกัดไม่เกิน 50 รายการ มีคำเตือน Prisma เรื่องตำแหน่ง config เดิมใน package.json ซึ่งเป็นงานอัปเกรดเครื่องมือแยกจากฟีเจอร์นี้

การคัดลอกชื่อตำแหน่งที่ยาวมากอาจสร้างชื่อแนะนำเกิน 120 อักขระหนึ่งตัว ผู้ใช้ต้องย่อชื่อก่อนบันทึก และแม่แบบที่เคยถูกลบแต่ยังจองรหัสอยู่ อาจยังปรากฏในรายการที่จะเพิ่ม แม้เซิร์ฟเวอร์จะข้ามรหัสนั้นและไม่เขียนทับข้อมูลเดิม

หากข้อมูลสิทธิ์ยกเว้นเดิมเสียรูปแบบ ระบบจะปิดการยืนยันไว้อย่างถูกต้อง แต่ข้อความในหน้าจอยังบอกให้โหลดใหม่โดยไม่ระบุว่าข้อมูลตั้งค่าตัวไหนต้องแก้ การโหลดใหม่อย่างเดียวไม่ซ่อมข้อมูลนั้น

การตรวจ API รอบหนึ่งพบ HTTP 501 ใน products-route test เดิม การรันคำสั่งเดิมซ้ำโดยไม่แก้โค้ดผ่านทั้งหมด รายงานไว้เพื่อไม่ซ่อนผลรอบแรก
