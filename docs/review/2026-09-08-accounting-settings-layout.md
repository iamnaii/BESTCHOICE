# จัดหน้าตั้งค่าผังบัญชีและงวดบัญชี

ย้ายการจับคู่รหัส PEAK ออกจากหน้ารวมบัญชีและภาษี ไปอยู่ในหน้าผังบัญชี โดยมีแท็บ **รายการบัญชี** และ **จับคู่รหัส PEAK** (`/settings/accounting/chart?tab=peak`) แท็บ FINANCE / SHOP ของรายการบัญชียังกรองตามผังเดิม ส่วนการจับคู่ PEAK แสดงทั้งสองผังตามพฤติกรรมเดิมและเก็บค่าที่ยังไม่บันทึกเมื่อสลับมุมมอง

- ผู้ใช้ OWNER / ACCOUNTANT แก้ไขและนำเข้ารหัส PEAK ได้; FINANCE_MANAGER อ่าน ค้นหา และดาวน์โหลดได้ตามสิทธิ์ API เดิม
- ลิงก์เดิม `/settings#peak-mapping`, `/settings/accounting#peak-mapping` และ `/settings/accounting/peak-mapping` ไปยังแท็บใหม่ หน้า PEAK Export ใช้ลิงก์ใหม่ และการค้นหาการตั้งค่าเปิดหน้าผังบัญชีได้ตรงเส้นทาง
- หน้างวดบัญชีแสดงสองแท็บ **FINANCE (การเงิน)** / **SHOP (หน้าร้าน)** แทน dropdown บริษัท และคงตัวเลือกปีไว้ อ่านเฉพาะ CompanyInfo ของสองส่วนธุรกิจนี้
- กล่องปิด/เปิดงวดระบุบริษัทและเดือนปีที่เลือก คำสั่งและการอัปเดต cache ใช้เป้าหมายที่เก็บไว้ตอนกดรายการ จึงไม่เปลี่ยนบริษัทหรืองวดตามตัวกรองที่เปลี่ยนภายหลัง
- ไม่มีการเปลี่ยน API, schema หรือกติกาปิด/เปิดงวด

ตรวจด้วย component tests รวม 122 กรณี (20 files), Web production build และ scoped lint ไม่มี error การทดสอบหน้าจอใช้ UI และบริการจริงจาก checkout นี้บนฐานจำลอง: บันทึกรหัส PEAK ของบัญชีจำลอง ตรวจ audit/CSV/validation/สิทธิ์ และสลับบริษัทกับปีเพื่อตรวจงวด โดยไม่สั่งปิดหรือเปิดงวดจริง

หน้าทดลอง: http://localhost:5197/settings/accounting/chart?tab=peak และ http://localhost:5197/accounting/periods

หลักฐานการทดสอบอยู่ใน `.tmp/payment-preview/check-chart-periods.json` และไฟล์ภาพหน้าจอ/ข้อมูล runtime ของงานนี้ ไม่มีการ deploy หรือแก้ข้อมูล production
