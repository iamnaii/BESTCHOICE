# หน้าตั้งค่า GFIN ใหม่ — ราคาและเงื่อนไขรายรุ่นในตารางเดียว

วันที่: 2026-11-20 · สถานะ: รอเจ้าของตรวจ

ม็อกอัปที่เจ้าของอนุมัติ: https://claude.ai/artifact/WUyXgvXP7SXHsxGbUywcwD (6 หน้า)

ที่มา: หน้าตั้งค่า GFIN ตอนนี้มี 6 แท็บ (ใบราคา · ส่วนเพิ่มราคา · ตารางค่างวด · ค่าตั้งต้น · ทดสอบจับคู่ · กลุ่มไลน์)
เจ้าของต้องจำว่ารุ่นไหนอยู่ "กลุ่ม" ไหนจาก 8 กลุ่ม และดูไม่ออกว่าเครื่องหนึ่งเครื่อง GFIN ให้เท่าไร
ตัวอย่างจริง: ดาวน์ iPhone 17 Pro Max มือ 2 ออกมา 8,000 แทน 5,900 เพราะกลุ่ม "มือ2 17/Air" ตั้งดาวน์ 30% ไว้ ทั้งที่ใบเงื่อนไขยกเว้นเฉพาะมือ 1

## 1. เป้าหมาย

1. ดูแถวเดียวรู้ครบว่ารุ่นนี้ มือนี้ GFIN ให้ราคาเท่าไร (แยกความจุ) ผ่อนสูงสุดกี่งวด ดาวน์ขั้นต่ำเท่าไร
2. เงื่อนไขเก็บรายรุ่นรายมือ (1 แถวต่อรุ่นต่อมือ) แทน 8 กลุ่ม — ค่าที่คิดได้ทุกเครื่องเท่าเดิมหลังแปลง
3. เรียงค่ากลางตามเลขข้อของใบเงื่อนไข G Finn (ใบข้อ 2, 3, 4, 7) และบอกเวอร์ชัน/วันที่เริ่มใช้ของใบ
4. นำเข้าใบราคา GFIN แล้วได้ทั้งราคาและเงื่อนไข (OVER · ผ่อนสูงสุด) และปิดราคาที่ GFIN ไม่ส่งมาแล้วได้
5. ทดลองคำนวณที่บอกว่าแต่ละตัวเลขมาจากไหน และใช้สูตรเดียวกับหน้าสินค้า
6. ใช้บนมือถือได้

### ไม่อยู่ในรอบนี้

- iPad (ใบราคายังไม่มี iPad) — ช่องค่าคอม iPad ซ่อนไว้ ค่าในฐานข้อมูลไม่แตะ
- OVER ต่างกันตามความจุ (เช่น iPhone 14 Pro มือ 2 1TB ที่ใบให้ 0) — ระบบยังเก็บ 1 ค่าต่อรุ่นต่อมือ หน้าตรวจนำเข้าให้เจ้าของเลือกค่าเดียว
- เช็กวงเงิน 40,000 / เอกสารรายได้เกิน 20,000 (ระบบไม่มีเช็กนี้ ไม่แสดงในหน้า)
- เปลี่ยนแท็บ "กลุ่มไลน์ & ข้อความ" (ยกมาทั้งหมดตามเดิม)

## 3. ข้อมูล

### 3.1 ไม่เปลี่ยน schema ของตารางหลัก

- `GfinModelMapping` (ราคา): 1 แถว = รุ่น (`gfinSeries`) + ความจุ + สภาพ — ใช้เฉพาะแถว `gfinVariant IS NULL` (แถวรูปแบบเก่า 54 แถวปิดอยู่แล้ว ไม่แสดง)
- `GfinOverpriceRule` (เงื่อนไข): หลังแปลง `seriesPattern` = ชื่อรุ่นเดียว (ตรงกับ `gfinSeries`) — `findGfinOverpriceRule` รองรับอยู่แล้ว ไม่ต้องแก้

### 3.2 Migration `gfin_rules_per_model`

1. ทุกคู่ (รุ่น, สภาพ) ที่มีแถวราคา (`deleted_at IS NULL AND gfin_variant IS NULL`, เปิดหรือปิดก็ได้):
   หากติกาที่ใช้จริงด้วยกติกาเดียวกับ `findGfinOverpriceRule` — กติกาเปิดอยู่ ไม่ถูกลบ สภาพตรง มีรุ่นนี้ใน `split('|')` เลือกตัวที่มีรุ่นน้อยสุด (เท่ากันเลือก `created_at` เก่าสุด)
2. เจอ → สร้างกติกาใหม่ `label = '<รุ่น> มือ <1|2>'`, `series_pattern = '<รุ่น>'`, คัดลอก `allowance` `max_months` `min_down_pct`, `is_active = true`
3. ไม่เจอ → ไม่สร้าง (แถวนั้นจะขึ้น "ยังไม่ตั้งเงื่อนไข" — ตอนนี้มีแค่ iPhone 12 มือ 2)
4. กติกาเดิมทุกตัวที่มี `|` → `deleted_at = now()` (กู้คืนได้จากถังขยะ)
5. partial unique index `gfin_overprice_rules (series_pattern, condition) WHERE deleted_at IS NULL`

**ตรวจก่อน merge (บังคับ — CI รัน migration บน prod ทันทีที่ merge · `deploy-gcp.yml` job `migrate-db` ก่อน `deploy-api` · training deploy มือทีหลัง จึงใช้เป็นด่านไม่ได้):**

1. เทสบน DB จริง (`apps/api/src/modules/gfin-config/__tests__/gfin-rules-per-model.migration.db.spec.ts`) — fixture = snapshot ของ prod
   (กติกา 8 กลุ่ม + ราคา 109 แถวที่เปิดอยู่ ณ 20/11/2026 14:53 · ไม่มีข้อมูลลูกค้า) → คำนวณ OVER / ผ่อนสูงสุด / ดาวน์ ของทุก (รุ่น, ความจุ, สภาพ)
   ด้วย `findGfinOverpriceRule` + `resolveGfinDownPct` บนกติกาเดิม → รัน SQL ของ migration → คำนวณซ้ำ → ต้องเท่ากันทุกแถว
   ยกเว้นข้อ 3 (iPhone 12 มือ 2 — เดิมไม่มีกติกา ยังไม่มีกติกา) · เทสเพิ่ม: รันซ้ำไม่สร้างแถวซ้ำ (migration ต้อง idempotent) · คู่ที่จำนวนรุ่นเท่ากันเลือก `created_at` เก่าสุด
2. ก่อนกด merge: `gcloud sql backups create --instance=bestchoice-db --description="before gfin_rules_per_model"` (PITR ปิดอยู่)
3. หลัง deploy: SQL อ่านอย่างเดียว (แนบใน PR) — นับกติกาที่ยังไม่ลบต่อสภาพ · ไม่มีคู่ (series_pattern, condition) ซ้ำ · ไม่มีกติกาที่มี `|` เหลือ ·
   ทุกคู่ (รุ่น, สภาพ) ที่มีราคามีกติกา ยกเว้น iPhone 12 มือ 2

### 3.3 ค่าตั้งใหม่ใน `SystemConfig`

- `gfin.sheetVersion` (ข้อความ เช่น `6.5`) และ `gfin.sheetEffectiveDate` (`YYYY-MM-DD`) — แสดงบนการ์ดเวอร์ชัน แก้ได้ในกล่อง "เปลี่ยนเป็นเวอร์ชันใหม่"
- ค่าตั้งต้นว่าง → การ์ดเขียน "ยังไม่ได้ระบุเวอร์ชันใบเงื่อนไข"

## 4. สูตรคำนวณ — เปลี่ยน 1 อย่าง

ไม่มีกติกา (`findGfinOverpriceRule` คืน null) → GFIN ไม่พร้อมใช้ เหตุผลใหม่ "ยังไม่ได้ตั้งเงื่อนไข GFIN ของรุ่นนี้"

| ที่เรียก | เหตุผลเดิม | เพิ่ม |
|---|---|---|
| `packages/shared/src/model-quote.ts` `buildRate2` | `NO_PRICE_LIST` … | `NO_RULE` |
| `apps/web/src/pages/ProductDetailPage/utils/gfinQuote.ts` `buildGfinQuote` | `no_mapping` … | `no_rule` |
| `apps/api/src/modules/shop-catalog/installment-preview.service.ts` | `no_gfin_mapping` … | `no_gfin_rule` |

ผู้อ่านเหตุผลที่ต้องแก้คู่กัน:

| ผู้อ่าน | แก้ |
|---|---|
| `apps/web/src/pages/ProductDetailPage/components/InstallmentCalculatorCard.tsx` (`switch` เหตุผล — `default` คืน null = เงียบ) | เพิ่มเคส `no_rule`: "GFIN: รุ่นนี้ยังไม่ได้ตั้งเงื่อนไข — ตั้งใน ตั้งค่า → GFIN" |
| `apps/api/src/modules/sales-bot/tools/get-installment-rates.tool.ts` `rate2UnavailableText` | ไม่แก้ — `NO_RULE` ตกข้อความกลาง "ยังไม่มีราคาผ่อน GFIN สำหรับรุ่นนี้" (ไม่บอกลูกค้าเรื่องตั้งค่าภายใน) |
| `PriceCard.tsx` (หน้าเพิ่มสินค้า) / `pricing-quote.service.ts` (หน้าราคา) | ไม่แก้ — แสดง `rate2.message` ที่ตัวคำนวณให้มา |

`gfinMaxMonthsFor` / `gfinMinDownPctFor` (gfinQuote.ts) คืนค่าเดิมเมื่อไม่มีกติกา (null / ค่ากลาง) — `buildGfinQuote` คืน `no_rule` อยู่แล้วจึงไม่กระทบ
ส่วนอื่นของสูตร (ราคาส่ง = ราคา + OVER × ไทย 1 / นอก 0.5 · ดาวน์ขั้นต่ำ = กติกาก่อน ไม่มีใช้ค่ากลาง · ปัดดาวน์หลักร้อย) ไม่แตะ

## 5. API (`/gfin-config`, แก้ได้เฉพาะ OWNER ตามเดิม)

| เส้นทาง | งาน |
|---|---|
| `GET settings` / `PATCH settings` | เพิ่ม `sheetVersion`, `sheetEffectiveDate` · **เมื่อ `commissionPhone` เปลี่ยนจากค่าเดิมเท่านั้น** ต้องมีแถว `GfinRateFactor` เปิดอยู่ของ % ใหม่ ไม่งั้น 400 "ยังไม่มีตารางค่างวดของคอม N% — เพิ่มตารางค่างวดก่อน" · ส่งค่าเดิมกลับมา = ไม่ตรวจ · `commissionTablet` ไม่ตรวจ (วันนี้ไม่มีตารางค่างวดคอม 5% — ตรวจแล้วบันทึกฟอร์มไม่ได้) |
| `POST overprice-rules/bulk-upsert` **ใหม่** | `{ items: [{ series, condition }], allowance?, maxMonths?, minDownPct?: number \| null }` — ฟิลด์ไม่ส่ง = ไม่เปลี่ยน · `minDownPct: null` = ใช้ค่ากลาง · ทุก `series` ต้องมีแถวราคา (`gfinVariant IS NULL`, ไม่ถูกลบ) อย่างน้อย 1 แถว ไม่งั้น 400 "ไม่พบรุ่น X ในใบราคา" (กันพิมพ์ชื่อผิดได้กติกาที่ไม่มีวันจับคู่) · คู่ที่ยังไม่มีกติกา ต้องส่ง `allowance` และ `maxMonths` ไม่งั้น 400 · คู่ที่มีกติกาแล้ว (รวมกติกาที่ปิดใช้ — unique index ครอบ) = แก้แถวเดิม ไม่สร้างใหม่ · ทั้งชุดใน transaction เดียว · audit `GFIN_RULES_BULK_UPSERTED` ครั้งเดียวพร้อมค่าก่อน/หลังทุกแถว |
| `POST max-prices/import` | ไม่เปลี่ยน — คอลัมน์ OVER/ผ่อนสูงสุดในไฟล์ หน้าเว็บรวมเป็นรายคู่แล้วส่งผ่าน `bulk-upsert` เอง |
| `POST max-prices/close` **ใหม่** | `{ ids: string[] }` → `isActive = false` ทั้งชุด · audit `GFIN_MAX_PRICES_CLOSED` |
| `PATCH max-prices/:id`, `POST max-prices` | ใช้ตามเดิมสำหรับแก้ราคา 1 ช่อง / เปิดคืน / ใส่ราคาช่องว่าง (`modelMatchPattern = gfinSeries`) |
| `POST overprice-rules`, `PATCH overprice-rules/:id` | คงไว้ (หน้าเดิมใช้ระหว่าง PR 1 กับ PR 2) · **`seriesPattern` ที่มี `\|` (หลายรุ่น) → 400 "เงื่อนไขเก็บรายรุ่นแล้ว — แก้ทีละรุ่น"** (กติกากลุ่มใหม่ไม่มีผลเพราะกติการายรุ่นชนะเสมอ — `findGfinOverpriceRule` เลือกตัวที่มีรุ่นน้อยสุด) · ชนกับ unique index → 409 "รุ่นนี้มีเงื่อนไขอยู่แล้ว" |
| ถังขยะ (`trash-registry.ts` ประเภท `gfin_overprice_rule`) | กู้กติกาที่ `seriesPattern` มี `\|` → ปฏิเสธ "กติกากลุ่มเดิมกู้ไม่ได้ — เงื่อนไขเก็บรายรุ่นแล้ว (ดูค่าเดิมในรายการนี้ได้)" · กติการายรุ่นกู้ได้ตามเดิม (ชน unique index = 409 รุ่นนี้มีเงื่อนไขอยู่แล้ว) |

## 6. หน้าเว็บ (`apps/web/src/pages/GfinConfigPage`)

### 6.1 โครง

- แท็บผูกกับ URL `?tab=terms|calc|line` (ลิงก์ตรงได้ · กดย้อนกลับได้)
- ไม่ใช่ OWNER เห็นเฉพาะ `line` ตามเดิม · OWNER เปิดหน้าครั้งแรก = `terms`
- ลบ: `MaxPricesTab`, `OverpriceRulesTab`, `GfinSettingsPanel`, `MatchPreviewPanel` · `RateFactorsTab` ย้ายไปอยู่ในกล่อง "แก้ตารางค่างวด"

### 6.2 แท็บ "เงื่อนไข & ราคา"

1. **การ์ดเวอร์ชัน** — "ใบเงื่อนไข G Finn Version X · ใช้ตั้งแต่ วว/ดด/ปปปป" + ปุ่มแก้
2. **ค่ากลาง**
   - ดาวน์ขั้นต่ำ % (ใบข้อ 2)
   - ค่าคอม iPhone (ใบข้อ 3) เป็น select ของ % ที่มีตารางค่างวด
   - ค่าทำสัญญา
   - ชิปค่างวดของคอมที่เลือก: งวด → `ceil(10,000 × factor) + fee` (ใบข้อ 4) + ปุ่ม "แก้ตารางค่างวด"
3. **ตารางราคาและเงื่อนไขรายรุ่น**
   - ปุ่มดาวน์โหลดแบบฟอร์ม (เพิ่มคอลัมน์ OVER · ผ่อนสูงสุด) + นำเข้า Excel
   - แถบส้มเมื่อมีแถว "ยังไม่ตั้งเงื่อนไข" + ปุ่มกรอง "ดูเฉพาะแถวที่ต้องดู"
   - ค้นหารุ่น · กรองตระกูล (13, 14 … Air, 18 — สร้างจากข้อมูล) · กรองมือ
   - จัดกลุ่มตามตระกูล พับ/เปิดได้ (ค่าตั้งต้น: เปิดทุกตระกูล) · หัวตระกูลมีปุ่ม "เลือกมือ 1/มือ 2 ทั้งตระกูล"
   - คอลัมน์: เลือก · รุ่น · สภาพ · ราคาแยกความจุ (สร้างจากความจุที่มีในข้อมูล เรียง 64GB → 1TB) · OVER · ผ่อนสูงสุด · ดาวน์ · แก้
   - แถวมือ N ขึ้นเฉพาะเมื่อรุ่นนั้นมีราคาของมือ N อย่างน้อย 1 ช่อง (เปิดหรือปิดก็ได้)
   - ราคาปิด/ไม่มี = "—" · ดาวน์จากค่ากลาง = สีเทา `25%` · ตั้งเฉพาะรุ่น = ตัวหนา · ไม่มีกติกา = ช่องส้มคร่อม 3 คอลัมน์ "ยังไม่ตั้งเงื่อนไข · ยังคิดผ่อนไม่ได้" + ปุ่ม "ตั้งเงื่อนไข"
   - เลือกแถว → แถบดำ "เลือก N แถว · …" + "แก้เงื่อนไขพร้อมกัน" (เลือกปนมือได้ — กล่องแก้แสดงทุกรุ่นพร้อมป้ายมือ)
4. **กดช่องราคา** → popover: แก้ราคา · ปุ่ม "GFIN ไม่รับแล้ว (ปิด)" · บรรทัดราคาส่ง = ราคา + OVER
   กดช่อง "—" → ใส่ราคา (ถ้ามีแถวปิดอยู่ = เปิดคืนพร้อมราคาใหม่)
5. **กล่องแก้เงื่อนไข** (1 แถวหรือหลายแถว)
   - ชิปรุ่นที่เลือก (กดเอาออกได้)
   - OVER: ไม่เปลี่ยน / ตั้งเป็น __ · ผ่อนสูงสุด: ไม่เปลี่ยน / 10 / 12 / 15 · ดาวน์: ไม่เปลี่ยน / ใช้ค่ากลาง / กำหนด __%
   - แต่ละช่องบอก "ตอนนี้ …" (ค่าเดียวกันทุกแถว หรือ "ต่างกัน 2 ค่า")
   - แถวที่ยังไม่มีกติกา: OVER และผ่อนสูงสุดต้องกรอก ("ไม่เปลี่ยน" กดไม่ได้)
   - กล่องสรุป "จะเปลี่ยน: …" + ตัวอย่าง 1 เครื่อง (ราคาความจุต่ำสุดของแถวแรก, ราคาขาย = ราคาส่ง) ดาวน์และค่างวดก่อน → หลัง
   - บันทึก → `bulk-upsert`
6. **มือถือ** (< 768px) — การ์ดทีละรุ่น: ชื่อรุ่น · บล็อกมือ 1/มือ 2 (เลือก · ราคาเป็นชิปความจุ · OVER/ผ่อน/ดาวน์ · แก้) · แถบเลือกติดล่าง

### 6.3 นำเข้าใบราคา (ต่อจาก `gfinPriceListImport.ts`)

1. อ่าน Excel: รุ่น · ความจุ · มือ · ราคา · OVER (ไม่บังคับ) · ผ่อนสูงสุด (ไม่บังคับ)
2. หน้าตรวจ
   - **ราคา**: เพิ่มใหม่ · เปลี่ยน · เท่าเดิม (เหมือนเดิม) + **มีในระบบแต่ไม่มีในไฟล์** (แถวเปิดอยู่ `gfinVariant IS NULL` ที่ไม่ตรงคีย์ใดในไฟล์) แยกสองกลุ่ม
     แต่ละกลุ่มมีรายการ + ตัวเลือก ปิด / เปิดไว้ ของตัวเอง:
     - **รุ่นที่มีในไฟล์ แต่ขาดบางความจุ/มือ** — ค่าตั้งต้น **ปิด** (GFIN ส่งรุ่นนี้มาแต่ไม่มีช่องนี้แล้ว)
     - **รุ่นที่ไม่มีในไฟล์เลย** (เช่น iPhone 12) — ค่าตั้งต้น **เปิดไว้** (ไฟล์อาจไม่ครบ — นำเข้าเฉพาะรุ่นใหม่ต้องไม่ปิดทั้งใบราคา) · ติ๊กปิดเองได้
     - แถบสรุปบอกจำนวนที่จะปิดก่อนกดยืนยัน
   - **เงื่อนไข** รวมรายคู่ (รุ่น, มือ) จากแถวในไฟล์:
     - ทุกความจุเท่ากัน + ตรงกับระบบ → นับ "ตรงกับระบบ"
     - ทุกความจุเท่ากัน + ต่างจากระบบ → "จะเปลี่ยน" พร้อมค่าเดิม → ใหม่
     - ความจุต่างกัน → "ต้องเลือก" (radio: ค่าที่ใช้มากสุด (ตั้งต้น) / ค่าอื่นแต่ละค่า)
     - คู่ใหม่ที่ไม่มีกติกาและไฟล์ไม่มี OVER/ผ่อนสูงสุด → ต้องกรอกในหน้านี้ ปุ่มยืนยันกดไม่ได้จนกว่าจะครบ
     - ไฟล์ไม่มีคอลัมน์ OVER/ผ่อนสูงสุดเลย → ข้ามส่วนเงื่อนไข (ยกเว้นคู่ใหม่ที่ต้องกรอก)
   - ดาวน์ไม่อยู่ในใบราคา: คู่เดิมคงค่าเดิม · คู่ใหม่ = ค่ากลาง
3. ยืนยัน → ส่งราคาเป็นชุดละ 100 (เดิม) → `max-prices/close` → `overprice-rules/bulk-upsert`
   แถบความคืบหน้า "บันทึกแล้ว N/M ชุด" · พลาดกลางทาง = แจ้งว่าบันทึกไปแล้วกี่ชุด + "นำเข้าไฟล์เดิมซ้ำได้"

### 6.4 แท็บ "ทดลองคำนวณ"

- ช่องกรอก: รุ่น (จากรายชื่อรุ่นในใบราคา) · ความจุ (ชิปจากข้อมูล) · มือ · เครื่องไทย/นอก · ราคาขาย GFIN
- **ห้ามเรียก `buildGfinQuote` ตรง** — มันรับ `downPct`/`months` จากผู้เรียก (เรียกตรง = ดาวน์ผิด เช่น 8,000 vs 5,900 ที่เป็นต้นเรื่อง)
  หน้าสินค้าประกอบส่วน GFIN เองใน `resolveQuotes.ts` (`gfinMinDownPctFor` → `gfinMaxMonthsFor` → `buildGfinQuote` → ถอยงวดเมื่อ `no_factor`)
  ⇒ แยกส่วนนั้นเป็นฟังก์ชันเดียว `resolveGfinQuote(tables, product, salePrice, overrides)` ใน `ProductDetailPage/utils/gfinQuote.ts`
  คืน `{ months, downPct, minDownPct, commissionPct, quote }` (รูปเดียวกับ `ResolvedGfin` เดิม) · `resolveQuotes` และแท็บทดลองคำนวณเรียกตัวนี้ตัวเดียว
  (เทสเดิมของ `resolveQuotes` ต้องผ่านโดยไม่แก้ความคาดหวัง)
- product ของแท็บนี้สร้างจาก gfinSeries + ความจุ + มือ (`category` = `PHONE_NEW` สำหรับมือ 1 / `PHONE_USED` สำหรับมือ 2 · `deviceOrigin` ตามที่เลือก)
- `buildGfinQuote` คืน `mappingId` และ `ruleId` ที่ใช้เพิ่ม (ใช้ทำป้ายที่มา)
- ทุกบรรทัดบอกที่มา: ราคาในใบ (รุ่น · ความจุ · มือ) · OVER (รุ่น · มือ · ไทยเต็ม/นอกครึ่ง) · ดาวน์ (ตั้งเฉพาะรุ่น X% หรือค่ากลาง) + ลิงก์ "แก้รุ่นนี้" เปิดกล่องแก้ของแถวนั้น
- ตารางค่างวดทุกงวดที่ไม่เกินผ่อนสูงสุด เน้นงวดสูงสุด
- ไม่พร้อมใช้ → บอกเหตุผล (ไม่มีราคา / ยังไม่ตั้งเงื่อนไข / ไม่มีตารางค่างวด)
