# นับเงินปิดยอดลิ้นชักสาขา (shop cash close)

วันที่: 2026-09-20 · ต่อจาก `2026-09-20-shop-tenders-daily-cash-design.md` (รอบ "นับเงินปิดวัน" ที่เลื่อนไว้)
Mockup: artifact CnXmYLkT Version 6 กระดาน 7–9 — **เจ้าของเคาะ "ตามข้อเสนอทั้งหมด" 2026-09-20**

## เป้าหมาย

หน้าสรุปเงินรายวันบอกได้แล้วว่า "เงินสดที่ต้องมีในลิ้นชัก" เท่าไร แต่ยังไม่มีใครต้องยืนยันว่าเงินจริงตรงไหม
และเงินเดินจากลิ้นชักไปถึงมือเจ้าของครบไหม รอบนี้เพิ่มสองจุดตรวจ: **พนักงานนับ → ผู้รับยืนยัน** โดยสองคนต้องเป็นคนละคน

## คำตัดสินเจ้าของ (ปิดประเด็น)

| เรื่อง | คำตัดสิน |
|---|---|
| หน่วยนับ | หนึ่งสาขา = หนึ่งลิ้นชัก นับครั้งเดียวต่อสาขา (ยอดรายคนยังดูได้ในหน้าเดิม) |
| เงินหลังปิดยอด | ส่งทั้งหมด เหลือ **เงินทอนตั้งต้น** ยอดคงที่ต่อสาขา (`Branch.shopCashFloat` — ตั้งที่หน้าจัดการสาขา) |
| ต้องมีในลิ้นชัก | เงินทอนตั้งต้น + รับเงินสด − จ่ายเงินสดออก ตั้งแต่ปิดยอดครั้งก่อนถึงตอนนับ (อ่านจาก `shop_tenders` เฉพาะ `method = CASH`) |
| ผู้นับ | พนักงานขาย / ผจก.สาขา **ของสาขานั้น** = คนที่ล็อกอินอยู่ตอนกดบันทึก |
| ผู้ยืนยันรับเงิน | เจ้าของ / ผจก.การเงิน / ผจก.สาขา (ผจก.สาขา = สาขาตัวเอง) และ **ต้องไม่ใช่ผู้นับ** |
| เงินรับจริง | ผู้ยืนยันกรอกเอง — ไม่เท่ายอดแจ้งส่ง = "ส่วนต่างชั้นที่สอง" ต้องมีหมายเหตุ |
| ปลายทางเงิน | เจ้าของเก็บ / นำฝากธนาคาร / ตู้เซฟสาขา — เก็บเป็นข้อมูล |
| ยอดไม่ตรง | บังคับเหตุผล ทั้งขาดและเกิน |
| แก้ยอดนับ | ไม่ได้ — นับผิดให้ผู้ยืนยัน "ตีกลับให้นับใหม่" (แถวเดิมเป็นประวัติ, นับใหม่ = `attemptNo + 1`) |
| รายการหลังปิดยอด | ไม่เปลี่ยนยอดที่ปิดแล้ว ไปรวมรอบถัดไป + ป้าย "หลังปิดยอด" ในตารางรายการ |
| เตือนเจ้าของ | สาขาที่เมื่อวานมีเงินสดแต่ยังไม่ปิดยอด · ยอดรอยืนยันเกิน 1 วัน · เงินขาดสะสมรายเดือนต่อสาขา |
| ไม่ทำรอบนี้ | ลงบัญชีอัตโนมัติ (เงินขาด/เกิน + ย้ายเงินไปธนาคาร — รอผู้สอบบัญชี) · ล็อกการขายเมื่อยังไม่ปิดยอด · ตัวช่วยนับแบงก์ · หลายลิ้นชักต่อสาขา |

## แบบข้อมูล

`ShopCashClose` (`shop_cash_closes`, migration `20261005000000_shop_cash_close` — additive) — หนึ่งแถว = การนับหนึ่งครั้ง.
ตัวเลข `floatAmount / cashIn / cashOut / expectedAmount` เป็น **snapshot ณ ตอนนับ**. ไม่มี `deletedAt` โดยตั้งใจ (หลักฐานการนับเงินห้ามลบ).

- สถานะ `PENDING_CONFIRM → CONFIRMED` หรือ `PENDING_CONFIRM → SENT_BACK`
- **รอบ** = `(periodStart, countedAt]` โดย `periodStart` = `countedAt` ของการปิดยอดที่ **ยังมีผล** ครั้งก่อน
  (`PENDING_CONFIRM` + `CONFIRMED`; แถว `SENT_BACK` ไม่นับ ⇒ นับใหม่หลังตีกลับครอบทั้งรอบเดิม + รายการที่เข้ามาเพิ่ม)
- `sendAmount = max(นับได้ − เงินทอนตั้งต้น, 0)` · `varianceAmount = นับได้ − ต้องมี` · `receiveVariance = รับจริง − แจ้งส่ง`
- นับรอบใหม่ได้แม้ครั้งก่อนยังรอยืนยัน (ร้านต้องเดินต่อได้ถ้าไม่มีใครมารับเงิน) — เงินที่นับแล้วรอผู้รับถือว่าแยกซองออกจากลิ้นชักแล้ว
  จึงไม่อยู่ใน "ต้องมี" ของรอบใหม่

## กติกาที่บังคับใน `ShopCashCloseService`

- นับ/ยืนยัน/ตีกลับ ทำใต้ `pg_advisory_xact_lock('shop-cash-close:<branchId>')` ⇒ สองคนนับพร้อมกัน/กดซ้ำไม่ได้แถวซ้อน
- ไม่มีรายการเงินสดใหม่ตั้งแต่ปิดยอดครั้งก่อน → ปฏิเสธการนับซ้ำ (กันกดซ้ำโดยธรรมชาติ)
- **ตีกลับได้เฉพาะการปิดยอดครั้งล่าสุดของสาขา** — ครั้งที่มีการปิดยอดใหม่ทับแล้วเป็นขอบรอบของครั้งถัดไป ถ้าถอนออกเงินของรอบนั้น
  จะไม่ถูกนับอีกเลย ⇒ ให้ยืนยันตามเงินที่รับจริงและระบุส่วนต่างในหมายเหตุแทน
- AuditLog เขียน **หลัง commit** (`SHOP_CASH_CLOSE_COUNTED` / `_CONFIRMED` / `_SENT_BACK`, entity `shop_cash_close`) ตามกติกาใน `database.md`

## API (`/shop-tenders/cash-close`)

| Method | Path | Roles |
|---|---|---|
| GET | `/status?branchId&date` | OWNER, FM, ACC (ทุกสาขา) · BM, SALES (สาขาตัวเอง) |
| GET | `/history?branchId&month` | OWNER, FM, ACC · BM (สาขาตัวเอง) |
| POST | `/` | SALES, BM ของสาขานั้น |
| POST | `/:id/confirm` | OWNER, FM, BM (สาขาตัวเอง) — ≠ ผู้นับ |
| POST | `/:id/send-back` | เหมือน confirm |

ขอบเขตสาขาบังคับใน service (route ไม่มี BranchGuard — เหตุผลเดียวกับ `daily-summary`).

## หน้าจอ

`/shop/daily-cash` — กล่อง "ปิดยอดวันนี้" บนสุดเมื่อเลือกสาขาเดียว (3 สถานะ) + กล่องนับเงิน + กล่องยืนยันรับเงิน/ตีกลับ ·
แท็บที่สอง "ประวัติการปิดยอด" (แถบเตือน + ตาราง + รายละเอียดต่อแถว) · ตารางรายการของวันมีเส้นคั่น "— ปิดยอด HH:MM … —"
และป้าย "หลังปิดยอด นับรวมรอบถัดไป" · หน้าจัดการสาขามีช่อง "เงินทอนตั้งต้นของลิ้นชัก".
พนักงานขายเห็นกล่องปิดยอดของสาขาที่สังกัด (ต้องนับได้) แต่ตารางรายการยังเห็นเฉพาะของตัวเองตามเดิม — ไม่มีแท็บประวัติ.

## ที่รู้ตัวและยังไม่ทำ

- แถบเตือนขึ้นสองที่ตาม mockup: แท็บประวัติ (รายละเอียดครบ 3 แบบ) และกล่องเตือนของแดชบอร์ด (`GET /dashboard/alerts` —
  `cash_close_missed` / `cash_close_awaiting`, เงื่อนไขชุดเดียวกันผ่าน `findUnclosedYesterday` + `staleAwaitingConfirmWhere`) ·
  เงินขาดสะสมรายเดือนขึ้นเฉพาะแท็บประวัติ (แดชบอร์ดเป็นกล่องนับจำนวน ไม่มีที่แสดงยอดเงิน)
- ผู้นับจำกัดที่ SALES/BM ตามข้อเสนอ ⇒ ถ้าร้านมีแต่บัญชี OWNER (prod วันนี้ยังไม่มีบัญชี SALES) จะยังนับไม่ได้จนกว่าจะสร้างบัญชีพนักงาน
- `factory:reset` ล้าง `shop_cash_closes` (WIPE_TABLES) · cleanup ข้อมูลทดสอบรายเอกสารไม่แตะตารางนี้ (ไม่ผูกกับเอกสาร)
